# Ранние SSR-скрипты и порядок popstate при смене layout

Найдено в Studio при переходе CRT ↔ `/podderzhka`, 24.10.2026 (ST-032, ST-034, ST-039).

## Исполняемый script при клиентском монтаже

React 19 сообщает `Encountered a script tag while rendering React component`, если новый
клиентский компонент создаёт исполняемый inline-script. Такой script не выполняется. Смена
веток layout создаёт новые провайдеры и баннеры, даже если первоначальный SSR чист.

- Скрипт для разбора HTML документа размещать в постоянном корневом layout. В Studio так
  устроен `ERA_BOOT_SCRIPT`, скрывающий повторный загрузчик до первого кадра.
- В `CookieBanner` использовать `useIsHydrated` из `@letar/hooks/browser`: серверный снимок
  и гидратация сохраняют script, новый клиентский монтаж его не создаёт.
- `next-themes` предоставляет `scriptProps`. Сменяемые провайдеры Studio сохраняют исполняемый
  script при SSR, при CSR передают `type: 'text/plain'`; тему применяет эффект библиотеки.
  Безусловное отключение SSR-скрипта вернёт вспышку неправильной темы.

Проверять SSR, гидратацию и новый CSR-монтаж отдельно. Начальный рендер в unit-тесте не заменяет
переход в браузере с контролем `console.error`.

## popstate: важен момент установки обработчика

Обработчик современной ветки с `capture: true` проходил синтетические unit-тесты, но не
успевал при настоящем `page.goBack()`: ранее установленный обработчик Next.js синхронно
снимал ветку и её listener. Сам по себе capture не гарантировал нужный порядок на window.

`CrtHistoryReturn` находится в постоянном корневом layout. Его layout-effect устанавливает
listener до passive-effect маршрутизатора; `usePathname` обновляет предыдущий адрес при
обычных переходах. На popstate сравниваются предыдущий и новый адреса. Уход из поддержки на CRT и возврат по истории на главную любой локали
ставят краткую метку до монтажа CRT. Якоря той же страницы метку не ставят; cleanup снимает listener.

С ST-068 метки `studio.entry.return` и `studio.entry.switched` содержат `performance.timeOrigin`.
Свежая по TTL метка из прошлого документа не действует: reload всегда запускает вход заново.
При восстановлении нового документа по Back/Forward используется navigation timing `back_forward`;
bfcache сохраняет готовое React-состояние. На возврате нет повторной вспышки, POST и выбора языка.

Не заменять это флагом «уже посещал сайт»: новый прямой заход на главную сохраняет церемонию.
Проверять настоящий цикл Назад → Вперёд → Назад и reduced-motion в Chromium и WebKit.
