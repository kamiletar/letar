# tsgo (typecheck:tsgo) иногда эмитит `.d.ts`/`.d.ts.map` рядом с исходником вместо `outDir`

## Симптом

После `nx run <project>:typecheck:tsgo` (команда `tsgo --build tsconfig.lib.json
--emitDeclarationOnly`) в `src/` библиотеки/приложения появляются `*.d.ts` и `*.d.ts.map`
рядом с исходными `.ts`/`.tsx`, хотя `tsconfig.lib.json` явно задаёт `"outDir": "dist"` и
`dist/` при этом тоже корректно наполняется (файлы дублируются, не подменяются).

Найдено 2026-08-26 сразу в трёх местах: `libs/forms` (508 файлов), `apps/animatrona/renderer`
(десятки, например `animatrona-form.d.ts` рядом с `animatrona-form.tsx`), `libs/forms-react`
(52 файла при параллельном прогоне с `forms-core`+`forms`).

## Последствия

- Шум в `git status` (untracked-файлы).
- `nx lint` реально падает: `oxlint` ловит `typescript(no-useless-empty-export)` на
  сгенерированных `.d.ts`, если их не вычистить перед линтом.

## Что установлено при разборе

- **Не воспроизводится детерминированно** на полностью чистом дереве (`rm -rf dist` +
  удалить все `src/**/*.d.ts(.map)` во всех связанных библиотеках) при последовательном
  прогоне `nx run @letar/forms:typecheck:tsgo --skip-nx-cache` — три чистых прогона подряд
  дали 0 stray-файлов, `dist/` каждый раз наполнялся корректно.
- Предыдущее «воспроизведение» (52 файла в `forms-react`) оказалось артефактом того, что
  сама `forms-react` не была очищена перед прогоном — файлы были из более раннего состояния
  (метки времени на 1.5 часа раньше самого прогона), не результатом этого запуска.
- `tsconfig.lib.json` во всех проверенных проектах (`forms-core`, `forms`, `forms-react`)
  задаёт `outDir`/`rootDir` идентично и корректно — конфиг не является причиной.
- `@typescript/native-preview` (пакет `tsgo`) на момент разбора — `7.0.0-dev.20260707.2`,
  препрод-версия. Правдоподобная гипотеза (не подтверждена репро) — гонка/баг инкрементального
  `--build` в самом tsgo, проявляющийся при прерванном (Ctrl-C/таймаут агента) или
  параллельном запуске нескольких `tsgo --build` процессов на одной машине, либо при рассинхроне
  `tsconfig.lib.tsbuildinfo` с фактическим состоянием `dist/`.
- Масштаб: таргет `typecheck:tsgo` есть у 72 проектов (`grep -rl '"typecheck:tsgo"'
  libs/*/project.json apps/*/project.json`) — потенциально подвержены все.

## Что делать

**Если увидел stray-файлы у себя:**

```bash
cd libs/<lib>  # или apps/<app>
rm -rf dist
find src -name "*.d.ts" -delete
find src -name "*.d.ts.map" -delete
nx run <project>:typecheck:tsgo --skip-nx-cache
```

Проверить, что `src/` снова чист: `find src -name "*.d.ts" -o -name "*.d.ts.map" | wc -l` → `0`.

**Перед `nx lint`**, если недавно гонял `typecheck:tsgo` и не уверен, что вычистил — сначала
проверь `git status` на untracked `*.d.ts` в `src/`, иначе `oxlint` даст ложные
`no-useless-empty-export`.

**Гигиена git:** `.d.ts.map` в `src/**` исключён из индекса корневым `.gitignore` (такие файлы
никто не пишет руками — безопасно игнорировать всегда). `.d.ts` в `src/**` **намеренно не
игнорируется** — в репозитории есть легитимные рукописные `.d.ts` (`css.d.ts`,
`vite-env.d.ts`, `*.schema.d.ts` генераторов и т.п.), блокировать `git add` для них было бы
хуже шума в статусе.

## Дополнение 2026-08-26: правдоподобный кандидат на «наблюдал ложный TS2739, не смог повторить»

Сессия `aboi` в тот же день, через ~3 минуты после коммита `feat(forms): Form.Field.EditIntent`
(`61f2fd38`, 18:41:15) в `libs/forms`, при попытке добавить `<Form persistence={{...}}>` в
`gift-form.tsx` (18:44:42) получила `tsgo`-ошибку `TS2739` в чужом файле
`field-type-mapper.tsx:433,440` («missing displayValue, emptyValue» для `EditIntentFieldProps`) —
хотя `persistence` не имеет никакой связи с веткой `case 'editIntent'` этого файла ни по коду, ни
по типам (`useFormPersistence`/`FormPersistenceConfig` полностью независимы от
`field-type-mapper.tsx`, подтверждено чтением). Сессия сочла это багом библиотеки и обошла через
`useFormRef()`+`onFieldChange`, оставив комментарий-ссылку на «баг field-type-mapper.tsx».

Повторное расследование в тот же день (`forms`-сессия) не смогло воспроизвести: `nx
typecheck:tsgo forms` изолированно — чисто; `nx typecheck:tsgo aboi --skip-nx-cache` с реально
добавленным `persistence` (несколько вариантов конфига, включая `dialogTitle`) на той же
`gift-form.tsx`/схеме — тоже чисто, ни разу `TS2739` не появился. Библиотечный код ветки
`editIntent` (деструктуризация + `displayValue`/`emptyValue ?? ''` перед JSX) при ручном разборе
типов не содержит несоответствия.

Совпадение по времени с одновременным коммитом в `libs/forms` (сама фича `EditIntent` только что
дописывалась/собиралась) делает правдоподобной ту же гипотезу «гонка/рассинхрон инкрементального
`--build` под параллельными/быстро сменяющими друг друга прогонами `tsgo`», а не реальный дефект
типов — то есть ложное срабатывание того же класса, что stray-`.d.ts` выше, только манифестирующее
не лишними файлами, а фантомной ошибкой типов в несвязанном файле. Не доказано (репро не
получено ни разу), но: если увидишь `TS2739`/аналогичную ошибку в `field-type-mapper.tsx` или
другом файле `libs/forms` сразу после недавнего коммита в эту же библиотеку — сначала попробуй
`rm -rf libs/forms/dist libs/forms-react/dist libs/forms-core/dist` + `--skip-nx-cache` и
перепроверь на чистом дереве, прежде чем писать обходной путь в приложении-потребителе.
