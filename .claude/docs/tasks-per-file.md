# Задачи по файлам: одна задача — один файл

Очередь задач проекта — это каталог `tasks/`, где каждая задача лежит в своём файле со статусом в
шапке. Список задач никто не пишет руками: его собирает `bun scripts/tasks.mjs next <проект>`.
Заведено 2026-10-12, пилот — корень монорепо (проект `letar`, префикс `LT`).

## Зачем

Старт сессии стоил слишком дорого: скиллы велели читать планы целиком, а планы росли с каждой
сессией (корень: `PLAN.md` 124 КБ и `docs/plans/PLAN-INFRA-*.md` 1,8 МБ). Разрез по
[plan-decomposition-pattern](/.claude/docs/plan-decomposition-pattern.md) не удержался: точка входа
`PLAN_INDEX.md` у domwellbes выросла с 527 до 1082 строк за четыре недели. Причины одни:

1. статус записан прозой в нескольких местах, и сверить их можно только чтением;
2. каждая сессия дописывает журнал в точку входа;
3. архивация — отдельный ручной шаг, который забывают.

Здесь статус одно поле в шапке, журнал живёт в файле задачи, закрытие переносит файл само, а
рост замороженного плана не пропускает хук.

## Замер корня (2026-10-12)

Старт сессии `/repo` раньше велел читать `PLAN.md` и `docs/plans/PLAN-INFRA-1…7.md`: 1,96 МБ.
Теперь `tasks/README.md` (2,5 КБ) и вывод `tasks.mjs next letar` (1,5 КБ, 20 строк): около 4 КБ.

## Замер по проектам (2026-10-12)

`tasks.mjs next <проект>`. Размеры в байтах (кириллица занимает два байта на знак, токенов
получается примерно столько же, сколько байтов делённых на четыре-пять).

Для малых планов выигрыш невелик: у flora он в основном в том, что статус больше не надо искать

задача (общий шаблон старта).

## Раскладка

```
<проект>/tasks/
  tasks.json            {"project":"letar","prefix":"LT","frozen":["PLAN.md", …]}
  README.md             компас: до 120 строк
  LT-012-slug.md        открытые задачи
  done/2026-10/…        закрытые (done, dropped)
```

Проект — любой каталог с `tasks/tasks.json`: корень, `apps/*`, `libs/*`. `project` и `prefix`
уникальны по монорепо, префикс — 2–5 заглавных букв. Номер выдаёт только скрипт (максимум по
`tasks/` и `tasks/done/**` плюс один). `frozen` — пути от корня проекта: старые планы, которым
нельзя расти; из шаблонов поддержан только `*` (не пересекает `/`).

## Шапка и статусы

```yaml
id: LT-012
title: "Пометка «без НДС» на витрине"
status: ready        # idea | ready | doing | blocked | review | done | dropped
size: S              # S | M | L (у idea можно пусто)
area: tooling
priority: 2          # 1 срочно … 4; по умолчанию 3
blocked_by: []       # id задачи или "кто: чего ждём"
owner: ""
stage: ""            # название этапа таймера studio
source: ""           # откуда взято, например "PLAN-INFRA-7.md §157"
created: 2026-10-12
updated: 2026-10-12
closed:              # появляется при закрытии
```

Тело: разделы «Что и зачем», «Приёмка», «План», «Журнал», «Итог». H1 в файле нет, заголовок
только в `title`. Размер `L` режется на `S`/`M` до старта.

## Команды

`bun scripts/tasks.mjs <команда>`:

| Команда                                    | Что делает                                                                    |
| ------------------------------------------ | ----------------------------------------------------------------------------- |
| `projects`                                 | проекты с очередью и счётчики по статусам                                     |
| `next [проект…]`                           | в работе, можно брать (до 10), ждут, идеи, предупреждения                     |
| `list <проект> [--status s] [--area a]`    | полный список по фильтру                                                      |
| `show <ID>`                                | путь к файлу и его содержимое                                                 |
| `new <проект> "<заголовок>" [--size …]`    | создаёт файл; флаги `--status --area --priority --source --blocked-by --slug` |
| `start <ID> --owner <имя>`                 | `doing`, владелец                                                             |
| `set <ID> ключ=значение…`                  | правка полей шапки с проверкой                                                |
| `block <ID> "<кто: что>"` / `unblock <ID>` | ожидание и снятие ожидания                                                    |
| `note <ID> "<текст>"`                      | строка с датой в «Журнал»                                                     |
| `done <ID> [--summary "…"] [--dropped]`    | закрывает, пишет «Итог», переносит файл в `done/<ГГГГ-ММ>/`                   |
| `waiting [проект] [--on <кто>]`            | ждущие задачи по тем, кого ждём                                               |
| `check [--staged]`                         | проверка; код 1 при ошибках                                                   |

«Можно брать» = `ready`, и каждый `blocked_by` вида `LT-012` указывает на закрытую задачу.
Корень монорепо: `--root <dir>` или `TASKS_ROOT`, иначе superproject текущего репозитория.

## Поток сессии

1. Старт: `Read tasks/README.md`, `bun scripts/tasks.mjs next <проект>`. Больше ничего читать не нужно.
2. Берёшь задачу: `show <ID>` и `start <ID> --owner <имя>`. Вызов скилла с id (`/<app> DW-012`)
   сразу открывает `show`.
3. План работы пишется в раздел «План» файла задачи, а не в отдельный документ.
4. По ходу: `note <ID> "…"` для шага, находка вне задачи — `new`, не абзац в плане.
5. Конец: `done <ID> --summary "…"`; если у задачи заполнен `stage` — `time_stage_close`.

## Что куда пишется

| Что                          | Куда                                                          |
| ---------------------------- | ------------------------------------------------------------- |
| Передача следующей сессии    | «Журнал» и «План» файла задачи                                |
| Находка по ходу              | `tasks new … --source "<где нашли>"`                          |
| Находки со встречи           | отдельный документ, в задачах — ссылки на него через `source` |
| Вопрос владельцу или клиенту | `tasks new … --status blocked --blocked-by "kami: …"`         |
| Итог                         | «Итог» файла задачи (`done --summary`)                        |
| Задание мидлу                | сам файл задачи: раздел «План» с решениями                    |
| Этап таймера                 | поле `stage` в шапке                                          |

## Барьеры

- Хук `pre-commit-tasks-check.sh` (ставит `scripts/hooks/install.sh`) проверяет индекс, только если
  в коммите есть `tasks/**`, `PLAN*`/`ROADMAP*.md` или `docs/plans/**`. Работает и внутри submodule.
- Замороженный файл из `frozen` не может вырасти больше чем на 5 строк. Обход осознанного случая:
  `GIT_ALLOW_FROZEN_PLAN_GROWTH=1` (блокировка становится предупреждением), целиком —
  `GIT_SKIP_TASKS_CHECK=1`.
- Гейт `tasks-check` в `bun scripts/check-all.mjs` и тесты `scripts/tasks.test.mjs` в CI.
- `check` ловит: имя файла не по шаблону, `id` не совпадает с именем, дубль id, неверный статус,
  закрытую задачу вне `done/` и открытую внутри, `doing` без `owner`, `blocked` без `blocked_by`,
  закрытую без «Итога», компас длиннее 120 строк. Предупреждения: тело больше 200 строк,
  `doing` с размером `L`, `doing` без правок больше 3 дней.

- Pre-commit scope-guard не считает `tasks/**` отдельным scope: файл задачи едет в одном коммите с кодом её решения (проверено 2026-10-22: задача + `libs/a` проходит, задача + `libs/a` + `libs/b` блокируется, одна задача — `docs-root`). Задачи в `apps/<x>/tasks/` и так относятся к scope приложения.
- Корневой `.ignore` скрывает от ripgrep (инструмент Grep) архивы планов: `/PLAN.md`,
  `/docs/plans/`, `PLAN_COMPLETED*.md`, `PLAN-JOURNAL*.md`. Замер 2026-10-22 на слове «deploy»
  по `*.md`: 1801 → 1167 совпадений, вывод 327 → 215 КБ (−34%). Явно указанный файл или каталог
  (`path: docs/plans`) ищется как обычно, `--no-ignore` отключает правило. Новый замороженный
  архив — строка в `.ignore`.

⚠️ Публичный репозиторий: в `tasks/` корня задачи по приватным приложениям содержат только имя и
типовой чек-лист, без цифр, доменов и бизнес-логики
([public-repo-hygiene](/.claude/rules/public-repo-hygiene.md)).

## Как перевести проект

1. Проверить живую сессию проекта (`whois <app>-dev`), `fetch_inbox`, чужие резервации. У
   `libs/forms` и `libs/ui` есть координаторы, сначала написать им.
2. В submodule: `git checkout main && git pull`.
3. Завести `tasks/tasks.json`: имя, префикс 2–4 буквы, `frozen` — бывшие точки входа и архивы
   (`PLAN.md`, `PLAN_INDEX.md`, `PLAN_COMPLETED*.md`), не спецификации.
4. Найти живое, не читая планы целиком: `grep -n '^#\{1,3\} '` по точке входа и
   `grep -n '^\s*- \[ \]'`. Живое = открытые пункты очереди, то, что ждёт людей, открытые
   вопросы. Каждый пункт — `tasks new` с `--source "<файл> §…"`. Пункты «на будущее» по
   неначатым вехам не переносить: они режутся на задачи, когда веха стартует.
5. `tasks/README.md` — компас до 120 строк: что за проект, текущий фокус (id задач), три главных
   правила, где какая справка лежит.
6. Баннер «файл заморожен, очередь в `tasks/`» в замороженные файлы под H1.
7. Скилл проекта: старт = таймер, регистрация, `Read tasks/README.md`, `tasks next <проект>`;
   вызов с id сразу делает `tasks show`.
8. `tasks check`, коммит, запись результата в задачу перевода, `tasks done`.

## Шаблон блока старта для скилла

Скилл приложения с очередью не повторяет общие правила, а ссылается на них. Подставь `<app>`,
`<PREFIX>` и путь к проекту; остальное не менять:

```markdown
## Инициализация

1. Таймер: `time_start({ app: "<app>", description: "изучение плана и постановка задачи" })`.
2. Agent Mail: имя `<app>-dev`, шаблон вызова и обработка отказов — `.claude/rules/app-workflow.md`
   и `.claude/rules/agent-mail.md`. Токен одной строкой: `grep -m1 '^| <app> ' …/agent_fixed_names_tokens.md`.
3. Очередь: прочитай `<путь>/tasks/README.md` и выполни `bun scripts/tasks.mjs next <app>`.
   Вызов с id (`/<app> <PREFIX>-012`) — сразу `bun scripts/tasks.mjs show <PREFIX>-012`.
   `PLAN*.md` заморожены: целиком не читать, открывать раздел из поля `source` задачи.

## Действия

Из «можно брать» выбери задачу, `start <ID> --owner <app>-dev`, план запиши в раздел «План» файла
задачи. Находку вне задачи заводи через `tasks new <app> …`, не абзацем в плане.

## После завершения

`bun scripts/tasks.mjs done <ID> --summary "…"`, дальше чек-лист `.claude/rules/app-workflow.md` §3.
```

В скилле остаётся только то, что относится к приложению: особенности стека, предметные справки,
приватные ограничения.

## Антипаттерны

- Дописывать журнал сессии в `PLAN.md` или компас: он для этого заморожен.
- Хранить статус в тексте («сделано», «в процессе») вместо поля `status`.
- Задача размера `L` в работе: режь на части до `start`.
- Список задач в `README.md`: список собирает `next`, компас хранит только фокус и правила.
- Править шапку руками, меняя `id` или `status: done`: закрывает только `done`, номер выдаёт только `new`.
- Переписывать ссылки на старые планы: они остаются справкой, ссылки живы.
