# Сохранение, аудитория и медиа в авторском редакторе

Паттерн для долгоживущих авторских материалов: текстов, заметок и произведений.
Обновлено: 2026-10-20.

## Сохранение продолжает работу

После создания сервер возвращает id. Клиент заменяет адрес формы создания постоянным
адресом редактора (`router.replace`), а повторное сохранение остаётся на этом же адресе.
Возврат в список — отдельный явный переход. Успех показывается только после
`unwrapActionResult(await action(...))`, иначе возвращённый ActionFailure станет ложным успехом.

Не путать локальный черновик, несохранённые правки и сохранённую серверную версию.
Показывать состояние словами; после правки не оставлять безусловную надпись «Всё сохранено».
Локальное восстановление и `dirtyGuard` из app-specific `createForm` защищают разные ситуации.
Перед включением диалога проверить явный `type="button"` у его действий, роль, фокус и Escape:
диалог внутри формы не должен случайно отправлять её. Найденный дефект вести в очереди forms.

## Перезагрузка несохранённого текста

Использовать `persistence` существующего `createForm`, ключ разделять по пользователю и id
материала; для нового текста — по пользователю и контексту создания. В локальную копию входят
название, текст и выбранная аудитория. Восстановление не отправляет форму и не меняет доступ.
Пояснение должно различать «в этом браузере» и «сохранено в аккаунте».

Принятие восстановления не является сохранением на сервере: не удалять локальную копию
при завершении восстановления. Удалять её только после успешной отправки, явного отказа
или возврата всех значений к серверному исходнику. Отложенную запись сбрасывать при уходе
страницы; `debounceMs: 0` должен писать сразу. Успешная очистка отменяет и отложенную запись,
чтобы unmount не вернул уже отправленный черновик.

Регрессия: ввод → reload → восстановить → reload без нового ввода → восстановить → сохранить
→ reload без устаревшего диалога. Проверить и создание, и редактирование, изоляцию аккаунтов,
другой текст, явное удаление копии и отсутствие изменений на сервере до кнопки сохранения.
Это отдельная проверка от перезагрузки уже сохранённой версии (MC-106 / FM-027).

## Аудитория до первого сохранения

Давать выбор аудитории сразу, с закрытым значением по умолчанию. Объяснять, когда выбор
применится: в редакторе вместе с сохранением, в быстром меню списка сразу.
Если публичность материала зависит от публичности профиля, объяснять действующий доступ
и давать переход к настройкам. Не открывать профиль автоматически вслед за материалом.
Проверка авторства нужна в серверном действии независимо от наличия кнопки.

На публичной странице собственник получает прямой переход к редактированию. Булево
`viewerIsAuthor` вычислять на сервере из проверенной сессии и владельца; гостю и другому
пользователю не отдавать авторские действия. Не передавать внутренние поля владельца в клиент
ради одного сравнения id.

## Общая загрузка обложки и аудио

`Dropzone` из `@letar/image-upload` принимает произвольный `accept`, а не только изображения.
Для аудио задать собственный контент, `accept` и `onRejected`; переносить компонент или
строить вторую реализацию drag-and-drop не нужно. Выбор через кнопку/Enter/Space обязателен.

До загрузки: имя, размер, ограничения и отмена выбора. Во время: прогресс, пауза, блокировка
повторной отправки. После: обработка, результат или понятная ошибка с повтором.
Не показывать пользователю браузерный `Failed to fetch` или технический текст исключения.
Лимит записей не должен запрещать продолжить загрузку уже созданной записи, в том числе
после перезагрузки: окончательное решение принимает сервер по id загрузки.

Текст и вложения могут сохраняться отдельными действиями: это нужно прямо подписать.
Не вкладывать `<Form>` загрузки внутрь `<Form>` текста. Обновление данных вложения не должно
перемонтировать редактор с текущими правками. Ключ редактора по версии текста допустим,
если загрузка обложки эту версию не меняет; проверить это настоящим запросом в браузере.

## Генерируемая схема и русские ошибки

Ограничения всего текста и отдельных фрагментов должны проверяться одной предметной схемой
на клиенте и сервере. Нельзя отклонять длинную строфу только после отправки, если поле редактора
такой предел не проверяет. В Mug Cup технический предел — 100 000 символов на текст и до 1000
строф; одна строфа может занимать весь текст. Не обрезать авторский текст автоматически.

`unwrapActionResult` бросает `ActionFailureError`: декларативная форма обязана применить
`mapServerErrors`/`applyServerErrors` даже без пользовательского `middleware.onError`. При отказе
не очищать persistence и dirty-state, не вызывать afterSuccess. Программный submit сохраняет
отклонение Promise, DOM-обработчик ловит уже показанный отказ. Перед повторной отправкой
очищать прошлые серверные ошибки, не затрагивая клиентскую валидацию: иначе form-level ошибка
блокирует повтор ещё до вызова Server Action. Кастомный fieldMap не перезаписывать автомаппингом.

Русская UI-подпись не переводит ограничение, добавленное генератором Zod. При композиции
схемы редактора можно переопределить поле валидатором предметной области с русскими
сообщениями, сохранив `.meta()` исходного поля. Не редактировать сгенерированный файл.
Проверить пустую строку, пробелы, предельную длину и сообщения на клиенте и сервере.

## Браузерная приёмка

Основные сценарии: создание → продолжение правок → повторное сохранение → перезагрузка;
смена аудитории из списка; скрытый профиль; просмотр и правка своего материала;
гость и другой автор; выбор аудио с клавиатуры; обновление обложки при текущих правках.
Проверять 360–430 px, светлую/тёмную тему, отсутствие горизонтального переполнения.

В тестах Chakra Radio нажимать видимую подпись (или использовать клавиатуру), а не скрытый
input через `check()`: его закрывает декоративный control. CookieBanner закрывать обычным
пользовательским действием в изолированном тестовом контексте. Не использовать force-click
для обхода реального перекрытия.
