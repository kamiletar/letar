# dprint vs ESLint `curly` — конфликт из-за `useBraces` по умолчанию

## Симптом

`eslint --fix` чинит нарушения правила `curly: ['error', 'all']` (`eslint.config.mjs:238` —
требует `{}` у любого `if`/`for`/`while` без исключений), добавляя фигурные скобки:

```ts
if (x) { return 1 }
// eslint --fix →
if (x) { return 1 }
```

Если после этого прогнать `dprint fmt` по тем же файлам — правило `curly` **снова падает**.
dprint убирает только что добавленные скобки обратно:

```ts
if (x) { return 1 }
// dprint fmt →
if (x) { return 1 }
```

Два инструмента взаимно откатывают правку друг друга. При чередовании `eslint --fix` →
`dprint fmt` → `eslint --fix` результат не сходится к стабильному состоянию — каждый следующий
прогон видит нарушение, оставленное предыдущим.

## Причина

Плагин `dprint-plugin-typescript` конфигурируется ключом `typescript.useBraces`, дефолт —
`"whenNotSingleLine"`: скобки убираются, если заголовок и тело влезают в одну строку. Ни в
корневом `dprint.json`, ни в per-submodule копиях этот ключ раньше не был выставлен явно —
дефолт молча конфликтовал с `curly: 'all'` из `eslint.config.mjs`, который требует скобки
всегда, независимо от длины строки.

## Фикс

`typescript.useBraces: "always"` в `dprint.json` — «Forces the use of braces. Will add them if
they aren't used.» Однострочная форма `if (x) { return 1 }` (скобки есть, но всё на одной
строке) устойчива к обоим инструментам: dprint её не трогает, `curly` доволен присутствием
скобок независимо от количества строк. Применено в корневом `dprint.json` 2026-08-09.

```json
"typescript": {
  ...,
  "useBraces": "always"
}
```

⚠️ **Каждый submodule ведёт свой независимый `dprint.json`** (см.
[git.md § Работа с приватными submodule](/.claude/rules/git.md)) — фикс в
корневом конфиге не действует на код внутри submodule. При следующей работе с curly-долгом в
приватном приложении добавить туда ту же строку, если `eslint.config.mjs` этого приложения тоже
требует `curly: 'all'`.

## Если нужно почистить уже нарушенные файлы вручную

Когда `eslint --fix` уже расставил однострочные `{return x}`, а следующий `dprint fmt`
предполагается запускать (или уже был запущен и часть скобок пропала) — до применения фикса
выше два обходных пути:

1. Обновить `dprint.json` (см. выше) и просто перезапустить `eslint . --fix` — теперь
   результат стабилен под последующими `dprint fmt`.
2. Без правки конфига — вручную/скриптом развернуть однострочные `{stmt}` в многострочный блок
   (`{\n  stmt\n}`); dprint не сворачивает уже многострочные блоки обратно ни при каком значении
   `useBraces`. Черновой regex-проход для этого — в истории коммита
   `style(forms): исправить curly ESLint-правило по всей библиотеке`.

Часть нарушений `eslint --fix` не чинит автоматически вовсе (trailing-комментарий на той же
строке после statement, или тело содержит собственные `{}`, например
`body.from_bound = { value: x }`) — такие случаи eslint пропускает как небезопасные для
автофикса, чинить руками.
