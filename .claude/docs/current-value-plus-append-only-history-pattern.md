# Текущее значение + append-only журнал: пишем историю только при изменении

## Когда применим

- У сущности есть **одно актуальное значение** на быстрый путь чтения (текущая цена, текущий
  статус, текущий курс) и одновременно нужна **история изменений** для доказательной базы или
  аналитики — кто, когда и с каким значением это менял.
- Источников записи **несколько** (ручной ввод, импорт прайса, ответ на заявку), и все обязаны
  писать в оба места одинаково — иначе значение обновится, а история нет, либо наоборот.
- Повторная запись **того же** значения (переимпорт того же прайса, повторный webhook) не должна
  раздувать журнал строками-дублями.

Не путать с [zenstack-append-only-terminal-event-pattern](/.claude/docs/zenstack-append-only-terminal-event-pattern.md):
там лога **без** отдельного текущего значения — терминальность гарантирует unique-constraint на
`idempotencyKey`. Здесь два отдельных места хранения, и синхронизацию между ними при отсутствии
события-изменения обеспечивать некому, кроме кода.

## Приём

Один общий хелпер на обе модели, единственная точка записи для всех источников:

```typescript
export async function recordCurrentAndHistory(db: Writer, input: RecordInput): Promise<void> {
  const existing = await db.current.findUnique({ where })
  const changed = !existing || /* сравнение полей, которые считаются «изменением» */

  await db.current.upsert({ where, create: {...}, update: {...} })

  if (changed) {
    await db.history.create({ data: {...} })
  }
}
```

- **Сравнение — по значимым полям**, не по факту вызова: пришли те же цифры — журнал не растёт.
- **Одна транзакция с вызывающим.** Хелпер принимает клиент (`db`), а не создаёт свой — если
  вызывающий код оборачивает несколько записей в `$transaction`, обе операции хелпера попадают в
  ту же транзакцию. Разрыв на два отдельных вызова без общей транзакции — путь к рассинхрону при
  падении между ними.
- **`undefined` ≠ явное значение** для полей, которые не всегда известны источнику (например срок
  поставки в прайсе без сроков): `undefined` — «не трогать», `null`/значение — явное обновление,
  включая обнуление. Не смешивать с обычным паттерном required-полей формы.
- **Опциональный сброс сопутствующего поля** (например «срок действия» при получении новой цены
  по прямому запросу) — отдельным флагом входа (`resetValidUntil`), а не отдельной функцией:
  вызывающий код явно решает, годится ли новое значение «навсегда» или наследует старый срок.

## Пример

`recordSupplierPrice` (`apps/domwellbes/src/lib/procurement/supplier-price-history.ts`) — текущая
цена поставщика (`SupplierPrice`) + append-only `SupplierPriceHistory`. Источники — ручной ввод,
построчный импорт прайса, разбор очереди сопоставления и ответ на заявку (RFQ) — все идут через
эту функцию. `changed` сравнивает цену, ставку НДС и срок поставки; идентичный переимпорт не пишет
строку истории. Спека — `supplier-price-history.spec.ts`.
