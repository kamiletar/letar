# Chakra v3 `Heading` рендерит `<h2>` по умолчанию — без единого визуального симптома

⚠️ Страница может не иметь ни одного настоящего `<h1>` месяцами, и ни `nx lint`, ни `typecheck`,
ни глаз на скриншоте этого не покажут.

## Симптом

Верхний заголовок страницы написан очевидным образом:

```tsx
<Heading size="2xl">{t('title')}</Heading>
```

Выглядит и ведёт себя как главный заголовок: крупнее всего на странице, стоит первым. На глаз —
всё верно. Ни `nx lint`, ни `nx typecheck:tsgo` не жалуются — это валидный TSX, и Chakra `Heading`
компилируется в обычный HTML-элемент без ошибок.

## Причина

`Heading` — это `withContext("h2")` (`node_modules/@chakra-ui/react/dist/esm/components/heading/index.js`):
компонент жёстко привязан к тегу `<h2>` независимо от `size`. Прямого способа задать тег через
проп нет: `as=` в этом монорепо запрещён правилами (`.claude/rules/components.md`), а без него
`Heading` навсегда остаётся `<h2>`, даже если это единственный заголовок на странице.

Итог: если ни один `Heading` на странице не обёрнут явно в `<h1>`, у страницы нет `<h1>` вообще —
ни семантически, ни в DOM. Найдено на всех шести публичных страницах `studio` разом (главная,
`/services`, `/about`, `/work`, `/contact`, `/privacy`) при работе над SVG-фильтром пикселизации
заголовков, который целился именно в `<h1>` — фильтр просто не находил цель
(`document.querySelector('h1')` возвращал `null`), и это вскрыло пробел, который иначе прошёл бы
незамеченным (2026-08-19, `apps/studio/CHANGELOG.md` 0.47.0).

## Как проверить

```js
document.querySelectorAll('h1').length // должно быть 1 на странице, не 0 и не больше
```

Визуальная проверка (скриншот, глаз) ничего не покажет — `<h2>` того же `size` выглядит идентично
`<h1>`. Нужна именно проверка тега в DOM.

## Как правильно

`asChild` + нативный `<h1>` — тот же паттерн, что и для любого другого элемента при запрете `as=`:

```tsx
<Heading asChild size="4xl" color="brand.solid">
  <h1>{title}</h1>
</Heading>
```

На странице должен быть ровно один такой `Heading` — обычно это главный заголовок хиро-секции или
заголовок страницы. Остальные `Heading` на странице (подзаголовки разделов) корректно остаются
`<h2>`/`<h3>` по умолчанию — им переопределение не нужно.

Для регулярно повторяющегося главного заголовка (несколько страниц с одинаковой ролью «заголовок
страницы») стоит завести один компонент-обёртку рядом с остальными app-specific компонентами
(`_components/`), а не дублировать `asChild`+`<h1>` в каждом файле — так сделано в `studio`
(`(public)/_components/phosphor-h1.tsx`, там же логика включения SVG-фильтра завязана на ту же
обёртку).
