# Лишний JS в публичном root: barrel, Chakra и prefetch

## Симптом и проверка

В Studio `/podderzhka` (24.10.2026, ST-057) холодный mobile Lighthouse показал передачу
3,5 МБ, LCP 10,3 с и Performance 57. В source maps / unused-javascript оказались формы,
lightbox и Ark/Zag-компоненты, которых на странице нет, а в network — CRT-ветка сайта.

Проверять нужно фактические network-запросы и исходники чанков: именованный импорт из
workspace-barrel сам по себе не гарантирует, что webpack уберёт все побочные зависимости.

## Исправления

- Утилиты согласия в root-клиенте импортировать из `@letar/ui/consent-types`, а не `@letar/ui`.
  Для браузерных hooks использовать `@letar/hooks/browser`. Сначала проверять существующие
  публичные подпути пакета; не обходить exports относительными импортами в чужую библиотеку.
- Для Chakra включить `experimental.optimizePackageImports: ['@chakra-ui/react']`.
  [Официальная рекомендация](https://chakra-ui.com/docs/get-started/frameworks/next-app).
- Для тяжёлой соседней ветки оценить prefetch. В Studio ссылка возврата на CRT использует
  `prefetch={false}`: загрузка ветки начинается по действию посетителя. Это осознанный
  компромисс между холодной загрузкой текущей страницы и скоростью последующего перехода;
  тестировать нужно оба направления, включая history и reduced-motion.

После этих правок передача уменьшилась до 1,2 МБ, CLI Performance вырос до 66, LCP до 7,8 с.
Это первый шаг, а не достижение целевых 90 / 2,5 с. Повторный вход с кэшем и sessionStorage
дал 99 / 1,0 с. Точные условия и оставшиеся причины записаны в задачах Studio ST-057/ST-058.

## Условия измерения

Сравнивать production-сборки, без параллельных build/test. Холодный и повторный вход
отличаются и кэшем, и sessionStorage: для отделения заставки нужен третий сценарий — холодный
кэш с признаком seen до первого body. Не удалять анимацию только из-за высокой оценки LCP.

Сохранять полный Lighthouse JSON и трассу; различать simulated и observed метрики.
Обычный ранний останов Lighthouse может не захватить весь интерактивный загрузчик:
дополнительный прогон с `pauseAfterLoadMs: 5000` дал более консервативные результаты.
Не выбирать только лучший прогон, для дальнейшего сравнения использовать медиану ≥3 запусков.

В Studio `compress: false` защищает SSE от буферизации. Прямой localhost без reverse proxy
передаёт несжатый JS; отдельный локальный gzip-стенд уменьшил передачу до 392 КБ и дал
Performance 79–88 / LCP 3,3–3,7 с. Это диагностический стенд, не проверка production.
Не включать глобальное сжатие ради Lighthouse: отдельно проверять реальные Content-Encoding
и Cache-Control у reverse proxy при авторизованной работе с production.
