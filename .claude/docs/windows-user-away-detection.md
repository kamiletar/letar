# Windows: «пользователь отошёл» для фоновой тяжёлой работы

**Коротко:** «нет ввода N минут» не значит «человек ушёл» — он может смотреть видео или сидеть
на созвоне. Второй сигнал — флаг «экран нужен», который программы ставят, пока показывают
что-то человеку. Флаг читается **без прав администратора** через
`CallNtPowerInformation(SystemExecutionState)`. Проверено 2026-09-16 на Windows 11.

## Сигналы

| Условие               | API                                                                                          | Оговорка                                                                  |
| --------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| нет ввода N минут     | `GetLastInputInfo`                                                                           | ⚠️ только в сессии пользователя: служба в session 0 его не видит           |
| программе нужен экран | `CallNtPowerInformation(16 /* SystemExecutionState */, NULL, 0, &ulong, 4)`, бит `0x2`       | общий флаг без имени программы                                            |
| полный экран / игра   | `SHQueryUserNotificationState`: 2 `BUSY`, 3 `RUNNING_D3D_FULL_SCREEN`, 4 `PRESENTATION_MODE` | ⚠️ видео в обычном окне браузера здесь не видно — отдаёт 5 (обычный режим) |
| на зарядке            | `GetSystemPowerStatus` + `RegisterPowerSettingNotification(GUID_ACDC_POWER_SOURCE)`          | событие приходит на окно сообщений                                        |

Отсюда агент — обычный процесс в сессии пользователя (автозапуск `HKCU\...\Run`), а не служба.
Условие «при простое» планировщика задач не годится: проверяет редко и не останавливает сразу.

## Замер флага экрана

| Что происходит                                                                    | `SystemExecutionState` |
| --------------------------------------------------------------------------------- | ---------------------- |
| ничего                                                                            | `0x0`                  |
| `SetThreadExecutionState(ES_CONTINUOUS \| ES_DISPLAY_REQUIRED)` в другом процессе | `0x2`                  |
| `PowerCreateRequest` + `PowerSetRequest(PowerRequestDisplayRequired)`             | `0x2`                  |
| видео (даже без звука) играет в браузере на Chromium                              | `0x2`                  |
| видео на паузе, через 3 с / держатель закрыт                                      | `0x0`                  |

Оба API — старый и новый — попадают в общий флаг. Список держателей по именам
(`powercfg /requests`) требует **терминала администратора** — агенту он недоступен.

## Ловушки

- ⛔ **Не держать экран самому.** На время работы агент ставит только
  `ES_CONTINUOUS | ES_SYSTEM_REQUIRED` (чтобы машина не уснула). С `ES_DISPLAY_REQUIRED` он
  увидит свой же флаг и остановится.
- ⚠️ **Вечный держатель.** Утилита «не гасить экран» или зависший созвон держат флаг
  постоянно — работа не начнётся никогда, и снаружи это похоже на «агент сломался». Писать
  причину ожидания в трей и лог, дать переключатель «не учитывать флаг экрана» и подсказку
  про `powercfg /requests`.
- ⚠️ **PowerShell и шестнадцатеричные литералы.** `0x80000002` в PowerShell — отрицательный
  `Int32`; передача в параметр `uint` падает ошибкой, которая по умолчанию **не прерывает
  скрипт**. Тест «держу экран» молча ничего не держит и показывает `0x0` — ложный вывод «старый
  API не виден». Передавать `[uint32]2147483650` и ставить `$ErrorActionPreference = 'Stop'`.
- ⚠️ **Тест с задержкой.** `Add-Type` в новом процессе `pwsh` компилирует C# несколько секунд.
  Проверять флаг после метки готовности от держателя, а не через фиксированную паузу.
- Условие старта держать чистой функцией от прочитанных значений, WinAPI — тонкой обёрткой:
  тогда таблица выше становится юнит-тестом.
