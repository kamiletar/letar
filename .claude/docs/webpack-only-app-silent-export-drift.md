# ⚠️ auth-hub собирается webpack'ом, а не Turbopack — расхождения тихие, видны только в логе

**Кратко:** `auth-hub` — единственное приложение монорепо с `next build --webpack`
(`apps/auth-hub/project.json` переопределяет команду). Всё остальное собирается Turbopack.
Из-за этого код, безупречный во всех остальных приложениях, может вести себя иначе в Ключнице —
и не падением сборки, а предупреждением в логе плюс `undefined` в рантайме.

## Подтверждённый случай (2026-08-28)

`libs/forms/src/lib/context.tsx` экспортировал четыре значения одной деструктуризацией:

```ts
export const { fieldContext, formContext, useFieldContext, useFormContext } = createFormHookContexts()
```

Сборка auth-hub давала четыре предупреждения:

```
export 'fieldContext' (reexported as 'fieldContext') was not found in './lib/context'
(possible exports: useTypedFormContext, useTypedFormSubscribe)
```

То есть webpack считал, что модуль экспортирует только два function-объявления, а четыре
`const` — нет. Под webpack эти значения в рантайме приезжали бы `undefined`.

**Сборка при этом проходит.** `exit=0`, все 29 маршрутов собираются. Дефект существует только
в тексте лога — ни typecheck, ни lint, ни статус выхода его не показывают.

Фикс — разложить на отдельные экспорты через промежуточную константу. Проверено в обе стороны:
деструктуризация — 4 предупреждения, отдельные экспорты — ноль.

## ⚠️ Чего НЕ надо делать с этой находкой

Не переписывать все деструктурирующие экспорты в репозитории. Обобщение «webpack не разбирает
деструктуризацию» **неверно** — тот же паттерн в `libs/forms/src/lib/form-hook.ts`
(`export const { useAppForm, withForm } = createFormHook(...)`) и в
`libs/forms/src/lib/declarative/form-fields/base/primitives.ts` реэкспортируется из `index.ts`
точно так же и предупреждений не даёт.

### Механизм найден (2026-08-28): не расширение `.tsx`, а импорт `react/jsx-runtime`

Проверено экспериментально на самом auth-hub (5 временных файлов в `libs/forms/src/lib/`,
реэкспортированных из `index.ts`, сборка после каждого варианта, файлы удалены после
эксперимента — воспроизведение ниже):

1. `.ts`-файл с деструктурирующим экспортом, без единого импорта — 0 предупреждений.
2. `.tsx`-файл с тем же паттерном плюс отдельная функция, реально возвращающая JSX
   (`return <div>...</div>`) — 2 предупреждения, ровно на деструктурированные имена;
   обычный `export function` рядом распознаётся нормально.
3. Тот же `.ts`-файл из пункта 1, но с обычным value-импортом сверху
   (`import { useMemo } from 'react'`, без JSX) — 0 предупреждений. Значит дело не в
   «любом импорте перед деструктуризацией».
4. `.ts`-файл (не `.tsx`, JSX в файле нет вообще) с ручным
   `import { jsx as _jsx } from 'react/jsx-runtime'` — 2 предупреждения, идентичные пункту 2.
   Значит расширение `.tsx` ни при чём — играет роль только этот конкретный импорт.
5. Тот же импорт, но написанный **после** деструктурирующего экспорта в тексте файла —
   предупреждения всё равно есть. Значит порядок операторов в файле не важен.

Сравнение вывода SWC (`@swc/core`, `jsc.transform.react.runtime: 'automatic'`) объясняет, откуда
берётся этот импорт в реальном `context.tsx`: файл содержит JSX (компонент
`TypedFormSubscribe`), поэтому SWC сам вставляет
`import { jsx as _jsx } from "react/jsx-runtime"` в начало модуля при автоматическом
JSX-рантайме — это стандартное поведение SWC/Babel, не специфика webpack. `form-hook.ts` и
`primitives.ts` не содержат JSX, поэтому этот импорт у них не появляется, и деструктурирующий
экспорт остаётся видимым.

**Правило:** webpack (через RSC/flight-плагин Next.js, который сканирует модуль на предмет
`react/jsx-runtime`, отмечая его как клиентский JSX-компонент) теряет деструктурирующий
`export const { ... } = fn()`, если модуль содержит `import ... from 'react/jsx-runtime'` — то
есть если в файле есть хоть один настоящий JSX-элемент, скомпилированный через automatic-рантайм.
Причина не в расширении файла, а в содержимом: `.tsx`-файл без единого JSX-выражения в
конечном коде (только типы/интерфейсы) этому импорту не подвергнется и деструктуризацию не
потеряет; `.ts`-файл, в который кто-то вставит JSX-подобный код (не должен, но гипотетически)
пострадал бы точно так же.

**Практическое следствие:** в файле, где `'use client'` и **одновременно** есть JSX-выражение
где-либо в модуле (даже в отдельной функции, не связанной с деструктурированным значением),
избегай `export const { a, b } = factory()` для значений, которые будут реэкспортированы
дальше — раскладывай на отдельные `export const a = ...`. Файлы без JSX (чистая логика,
хуки без JSX-возврата) деструктуризацию переносят нормально.

**Аудит монорепо (2026-08-28):** `grep -rn "^export const {" libs/ --include=*.ts --include=*.tsx`
даёт 4 совпадения (`libs/forms/src/lib/form-hook.ts`,
`libs/forms/src/lib/declarative/form-fields/base/primitives.ts`,
`libs/forms-shadcn/src/lib/uikit/primitives.ts`, `libs/forms-vue-shadcn/src/lib/uikit/primitives.ts`)
— все в `.ts`-файлах, где JSX-синтаксис невозможен по определению TypeScript (это ошибка
компиляции, не только стиль). Ни один не рискует получить импорт `react/jsx-runtime`. На
момент аудита живых экземпляров этого класса бага в репозитории, кроме уже исправленного
`context.tsx`, нет.

## Второй класс ошибки: этот лог дважды прочитали неверно

Предупреждения `was not found` дважды принимали за причину падения сборки auth-hub
(отчёт от 2026-08-25). Сборка не падала. Проверять надо статус выхода, а не наличие
`not found` в выводе:

```bash
cd apps/auth-hub
AUTH_ENCRYPTION_KEY=$(openssl rand -hex 32) ../../node_modules/.bin/next build --webpack
echo "exit=$?"
```

Временный `AUTH_ENCRYPTION_KEY` нужен потому, что `/api/auth/dev-session` бросает на этапе
сборки без него — это тоже легко принять за поломку кода, хотя это отсутствующая переменная
окружения локальной машины.

## Что делать при работе с libs/, которые использует auth-hub

Правя общую библиотеку (`@letar/forms`, `@letar/ui`, `@letar/auth`), помни, что typecheck и
сборка остальных приложений на Turbopack ничего не скажут про webpack-путь. Если правка
касается формы экспортов, реэкспортов или границ клиент/сервер — прогони сборку auth-hub
и **прочитай лог**, а не только код возврата.
