# React 19: `<title>` (в том числе внутри `<svg>`) не принимает массив детей — тихий разрыв гидратации

**Симптом:** клик по вкладке `UrlTabs` (`apps/domwellbes/src/app/(admin)/_components/url-tabs.tsx`)
не переключает видимую панель и не обновляет `?tab=` в URL — ни через клик, ни через прямую
навигацию на готовый `?tab=...`. На вид похоже на баг самого компонента вкладок или на артефакт
браузерной сессии (так и было изначально записано в `apps/domwellbes/PLAN.md`, раздел D3.4).

## Настоящая причина

Компонент `FootprintPreview` (`apps/domwellbes/src/app/(admin)/admin/houses/_components/
footprint-preview.tsx`) рисует подпись SVG-иконки текстом, разбитым JSX на несколько узлов:

```tsx
<title id={titleId}>
  Пятно застройки {lengthM} × {widthM} м
</title>
```

Такой JSX компилируется в **массив из пяти детей** (текст, выражение, текст, выражение, текст).
React (актуально минимум с 19.x, `react-dom` в этом монорепо) применяет к **любому** `<title>` —
не только HTML `<title>` в `<head>`, но и SVG `<title>` внутри произвольного места дерева —
специальную обработку как singleton-ресурса и требует, чтобы `children` был одной строкой/числом,
а не массивом. В dev-режиме это печатает предупреждение в лог сервера:

```
React expects the `children` prop of <title> tags to be a string, number, bigint, or object with
a novel `toString` method but found an Array with length 5 instead. ...
While not immediately apparent, `children` in this case is an Array with length 2. If your
`children` prop is using this form try rewriting it using a template string:
<title>{`hello ${nameOfUser}`}</title>.
```

На практике сервер рендерит в HTML только **первый** элемент массива (голый текст
`"Пятно застройки "`), обрезая остальное. Клиент при гидратации ожидает полный текст —
получается несовпадение `server rendered HTML didn't match the client`, `Recoverable Error`,
`<title>` в diff-панели Next.js dev overlay.

## Почему ломается именно переключение вкладок, а не просто «страшная надпись в консоли»

`FootprintPreview` рендерится внутри `DomWellbesForm.Subscribe` → `DimensionsFields` →
внутренних под-вкладок `HouseForm` (добавлены коммитом `23f31533`, «Основное» разбито на
подвкладки) → внутри `Tabs.Content value="form"` внешнего `UrlTabs` на странице
`admin/houses/[id]/page.tsx`. Chakra `Tabs.Content` по умолчанию держит **все** панели
смонтированными в DOM одновременно (скрывает CSS, не размонтирует) — то есть `FootprintPreview`
рендерится и хайдрируется всегда, даже когда активна совсем другая внешняя вкладка (`drawings`,
`import` и т.п.).

Ошибка гидратации в этом поддереве помечена React как «Recoverable» — но recoverable означает
только «не крашит всё приложение», а не «не имеет последствий». React выбрасывает и заново
строит весь client-side поддерево вокруг места несовпадения. Дерево вкладок Zag.js (`Tabs.Root`
из `@chakra-ui/react`), которое управляет активной панелью через собственную машину состояний
и подписку на DOM-события, теряет согласованность между новым перестроенным поддеревом и своим
внутренним состоянием — клики по триггерам вкладок перестают доходить до
`onValueChange`/`router.push`, хотя визуально всё выглядит как обычная страница без единой
видимой ошибки.

Сопутствующий, более редкий симптом того же самого сбоя — соседняя (скрытая) вкладка «Основное»
short-lived показывала **чужие** данные (имя другого дома из более раннего запроса в той же
браузерной сессии) — тоже следствие того, что React перестраивает поддерево вместо аккуратного
обновления, а не отдельный баг кеширования.

## Диагностика

1. Открыть Next.js dev overlay (кружок с «N» внизу слева) → «Issues» → смотреть diff у
   `Recoverable Error: Hydration failed...`. Diff показывает ровно тот `<title>`/элемент, где
   несовпадение, и путь `at <Компонент> (файл:строка)` в самом низу.
2. Тот же текст — в логе `nx dev <app>` (stdout), даже если браузерный dev overlay уже закрыт
   или не пойман скриншотом/console tool: `React expects the children prop of <title> tags...`
   печатается туда безусловно на каждый рендер с этим паттерном.
3. `read_console_messages` браузерного инструмента усечёт длинный объект ошибки до `{stack: ...,
   message: ...}` — для полного текста и стектрейса компонента читать именно серверный лог
   (`preview_logs`), не консоль браузера.

## Фикс

Единственный правильный child — одна строка (шаблонная строка, не JSX-текст вперемешку с
выражениями на нескольких строках):

```tsx
// ❌ Массив детей — ломает гидратацию
<title id={titleId}>
  Пятно застройки {lengthM} × {widthM} м
</title>

// ✅ Один строковый child
<title id={titleId}>{`Пятно застройки ${lengthM} × ${widthM} м`}</title>
```

В этом же приложении `plot-fit-diagram.tsx` и `plot-fit-side-view.tsx` уже используют
правильный паттерн (`<title id={titleId}>{summaryTitle}</title>`, готовая строка одним
выражением) — это единственный безопасный вид `<title>` в JSX, HTML или SVG, вне зависимости
от того, простая строка нужна или собранная из нескольких значений.

## Как искать по всему монорепо

```bash
grep -rn "<title" apps/*/src libs/*/src --include="*.tsx" -A2 | grep -B2 "{.*}.*{.*}"
```

Ищет `<title>` с двумя и более JSX-выражениями в детях — кандидат на тот же баг. На момент
находки (2026-09-16, `apps/domwellbes`) это был единственный такой случай в приложении.
