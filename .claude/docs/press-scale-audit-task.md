# Задача: аудит глубины нажатия (`_active` transform) на `pressScale`

Общая формулировка задачи для приложений, у которых тема ещё не сверялась с общей шкалой
`pressScale` (`@letar/ui`, [press-scale.ts](/libs/ui/src/lib/press-scale.ts)). Заведена один раз
здесь и подключается из `PLAN.md` приложения ссылкой — не копируй текст задачи в само приложение,
только строку со ссылкой на этот файл.

## Почему это отдельный файл, а не текст в каждом PLAN.md

Аудит независимо проводился в domwellbes, driving-school и aprel8008 — каждое приложение своими
словами описало один и тот же вывод («мелкой поверхности общая шкала даёт слишком мелкую
просадку») в комментарии рядом с recipe. Тот же вывод параллельно, но ещё раз своими словами,
формулировался в grandslamcup. DRY здесь — не стилистика, а защита от того, что раскрытие правила
«когда не применять шкалу» будет расползаться по приложениям вместо одного места.

## Что сделать

1. Найти в теме приложения все `_active: { transform: 'scale(...)' }` (обычно
   `src/theme/recipes/*.ts`, `src/theme/index.ts`, `src/theme/slotRecipes/*.ts`) —
   `grep -rn "_active.*scale(" apps/<app>/src/theme`.
2. Для каждого найденного места — два варианта:
   - **Поверхность обычного размера** (кнопка, карточка, крупный интерактивный блок) → заменить
     raw-значение на подходящий шаг `pressScale` (импорт из `@letar/ui`), выбирая шаг по
     относительному размеру поверхности — крупнее поверхность, мельче шаг (см. JSDoc
     `pressScale` про логику шагов).
   - **Поверхность подпадает под одно из двух исключений**, задокументированных в JSDoc
     [`pressScale`](/libs/ui/src/lib/press-scale.ts) («Когда НЕ использовать эту шкалу») — оставить
     raw-значение как есть, но добавить короткий комментарий над recipe с причиной (образец —
     `iconButtonRecipe` в `apps/driving-school/src/theme/recipes/slotRecipes.ts` или
     `apps/grandslamcup/src/theme/recipes/slotRecipes.ts`).
3. Не переводить механически всё подряд — если значение уже осмысленно подобрано под конкретную
   поверхность и не совпадает ни с одним шагом шкалы, сначала понять, exception это или просто
   недосведённый hardcode.

## Что НЕ делать

- Не выдумывать новый третий тип исключения без явной причины — если нашёлся новый паттерн,
  который не описывается двумя существующими пунктами JSDoc, сначала обсудить с пользователем,
  дополнять ли сам `press-scale.ts`, а не документировать его только локально в приложении.
- Не трогать `pressableConfig.globalCss` (`_active: scale(0.93)` у `[data-pressable]`) — это
  отдельный механизм, сознательно не сведённый с этой шкалой (см. JSDoc, раздел «Почему шкала
  общая, а глубина нажатия в `pressableConfig` — своя»).

## Образцы готового аудита

- `apps/driving-school/src/theme/recipes/slotRecipes.ts` — `iconButtonRecipe`, `checkboxRecipe`,
  `radioRecipe`, `tagRecipe.closeTrigger` (мелкие поверхности), `sliderRecipe.thumb`
  (рост, не проседание).
- `apps/domwellbes/src/theme/index.ts`, `apps/domwellbes/src/theme/recipes/*.ts`.
- `apps/grandslamcup/src/theme/recipes/*.ts`.
