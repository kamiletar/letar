# `import 'server-only'` бросает исключение под vitest — мокать глобально в setup

Тест `apps/aboi/src/lib/checkout.test.ts` мокал `./payments/tinkoff`, но не мокал
`./payments/router.ts` — а `router.ts` сам начинается с `import 'server-only'`. Тест падал не на
логике чекаута, а на самом импорте модуля, транзитивно затянутого в граф.

**Причина:** пакет `server-only` — однострочный модуль, который при импорте вне серверного
рантайма Next.js бросает исключение (это и есть весь его смысл: не дать серверному коду попасть
в клиентский бандл). Vitest/jsdom — не серверный рантайм Next.js, поэтому `import 'server-only'`
падает **всегда**, независимо от того, трогает ли тестируемый код что-то специфичное для сервера.
Мокать нужно не тот модуль, который тест импортирует напрямую, а любой модуль в графе импортов,
у которого `server-only` — первая строка.

**Фикс:** глобальный мок в `apps/aboi/vitest.setup.tsx`:

```ts
vi.mock('server-only', () => ({}))
```

**Почему глобально, а не точечно в одном тесте:** ловушка не привязана к конкретному тестируемому
модулю — она срабатывает у **любого** теста, который транзитивно (через любую глубину импортов)
доходит до файла с `import 'server-only'` наверху. Мок в одном `*.test.ts` чинит только этот файл
и оставляет грабли для следующего теста, зацепившего другой server-only-модуль. До этого фикса
(коммит `ee24274` в submodule `aboi`, 2026-09-17) ни в одном `vitest.config.*`/`vitest.setup.*`
монорепо не было ни одного мока `server-only` — проверено грепом по всем `apps/*`.

**Когда актуально:** любой vitest-тест в приложении, где `import 'server-only'` используется хотя
бы в одном модуле (обычно — файлы с прямым доступом к БД/секретам), особенно если тест мокает
что-то _рядом_ с server-only-модулем, а не сам этот модуль.
