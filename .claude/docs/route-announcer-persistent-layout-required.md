# `RouteAnnouncer` (`@letar/ui`) — молча не работает, если не в persistent `layout.tsx`

`RouteAnnouncer` (`libs/ui/src/lib/route-announcer.tsx`) объявляет screen reader'у смену
маршрута при client-side навигации Next.js App Router. Его собственный JSDoc с самого начала
говорит: «Разместить один раз в корневом layout/shell приложения — не на каждой странице». Это
не стилистическая рекомендация, а обязательное условие работы компонента.

## Почему это ломается тихо

Компонент сравнивает текущий `usePathname()` с предыдущим значением, чтобы отличить «реальную
навигацию» от «просто ре-рендер» (изначально — через булев `isFirstRender`, затем — через
`ref`, хранящий предыдущий путь; оба варианта одинаково подвержены проблеме ниже).

Next.js App Router держит `layout.tsx` смонтированным между навигациями внутри него, но
**полностью размонтирует и монтирует заново** любой компонент, который вместо этого
импортируется отдельно в каждый `page.tsx` (например общий shell без обёртки `layout.tsx`).
Если `<RouteAnnouncer />` стоит внутри такого per-page-компонента — при каждой навигации он
получает свежий mount, и у него никогда нет «предыдущего» рендера для сравнения `pathname`.
Симптом: компонент не объявляет **вообще ни одной** навигации, кроме, может быть, случайных
совпадений на гонках между рендерами.

## Как это выглядит внешне

- `nx typecheck`/`nx lint`/юнит-тесты — зелёные, компонент синтаксически корректен.
- Playwright-тест, кликающий один раз со свежей загрузки страницы, может случайно пройти или
  упасть в зависимости от точной гонки рендеров — выглядит как флак тестового окружения
  (например Strict Mode double-invoke на dev-сервере), а не как стабильный баг.
- Обнаруживается надёжно только живой проверкой в реальном браузере: несколько последовательных
  client-side переходов подряд, с чтением `[role="status"][aria-live="polite"]` после каждого.

## Прецедент

`domwellbes` (2026-08-25, MU1 §12.31, `apps/domwellbes/PLAN_PUBLIC_MOBILE.md`) — `RouteAnnouncer`
был подключён внутри `PublicShell`, который импортируется в каждый `page.tsx` (нет общего
`layout.tsx`-обёртки для публичного шелла). Фикс — перенос `<RouteAnnouncer />` в
`app/layout.tsx` (единственный persistent родитель, покрывающий все маршруты).

## Чек-лист при подключении в новом приложении

Перед тем как считать интеграцию готовой:

1. Убедиться, что `<RouteAnnouncer />` рендерится из файла `layout.tsx` (корневого или сегмента,
   который реально остаётся смонтированным на всех маршрутах, где нужно объявление), а не из
   компонента, импортируемого в каждый `page.tsx` по отдельности.
2. Проверить вручную (не только Playwright): выполнить 2+ последовательных client-side перехода
   и убедиться, что `aria-live`-статус меняется после каждого, а не только после первого.
