# Next.js: синглтон в переменной модуля расщепляется между `instrumentation.ts` и server actions

⚠️ **Симптом:** всё, что регистрируется при старте процесса (обработчики событий, планировщик задач,
реестры провайдеров), «есть» в `instrumentation.ts` и «нет» в server action или route handler.
Код работает, ничего не падает, интеграционные тесты зелёные — а сквозной сценарий молча не
срабатывает: оплата не переводит заказ в «Оплачен», письма не уходят.

## Механизм

Next собирает `instrumentation.ts`, server actions и route handlers **отдельными графами модулей**.
Переменная уровня модуля (`const registry = createRegistry()`) в каждом графе своя, поэтому
`register()` заполняет один экземпляр, а `dispatch()` в действии читает другой — пустой.
Флаг `let registered = false` рядом с ней расщепляется так же.

Интеграционные тесты этого не ловят: тест создаёт реестр сам (или импортирует модуль один раз в
одном графе), так что оба конца видят один экземпляр.

## Вдвойне опасно, если пустой проход «успешен»

Диспетчер outbox, у которого нет подписчиков на событие, считает его обработанным и закрывает.
Первый же вызов с пустым реестром **навсегда теряет** события, которые потом уже никто не доставит.

## Как чинить

1. Общий реестр — на `globalThis`, а не в переменной модуля:
   ```ts
   const g = globalThis as typeof globalThis & { __appRegistry?: Registry }
   export const registry = (g.__appRegistry ??= createRegistry())
   ```
2. Регистрацию защищай ключом на `globalThis` (`registerOnce('orders', …)`), а не флагом модуля:
   HMR и второй граф иначе зарегистрируют дважды (`уже зарегистрирован`) или ни разу.
3. Диспетчер отказывается работать с **пустым общим** реестром (лог + возврат без изменений), а не
   закрывает события.
4. Обработчики порождают новые события (оплата → `OrderPaid` → письма): вызывай проходы до простоя
   (`dispatchUntilIdle`), один проход оставит хвост до минутного таймера.

⚠️ После правки формы реестра (новый метод) **перезапусти `next dev`**: `globalThis` переживает HMR,
и старый объект без нового метода вернёт `x is not a function`.

## Как проверить

Только живым сквозным прогоном в `next dev`/`next start` (оплата → статус → письмо), не unit-тестом.
Найдено 2026-09-27 живым прогоном; тот же паттерн — в любом приложении, которое регистрирует что-то
в `instrumentation.ts` и читает это из действий.
