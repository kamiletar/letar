# VK Audio Downloader

Когда нужен: скачивание прямых MP3-ссылок из библиотек одного или нескольких профилей VK.

Самостоятельный Python 3.10+ CLI: `scripts/vk-audio/downloader.py`.
Установка, токен, команды и точное поведение — [README](/scripts/vk-audio/README.md).
Этот инструмент не является Nx-приложением; проверки выполняются через Python `unittest`.

## Доступ к API

`scope=audio` недостаточно для `audio.get`: приложению нужен доступ к закрытому аудио API.
Открытый профиль не снимает это ограничение. Обычный новый Standalone-клиент не гарантирует
возможность чтения аудио. Проверять реальный доступ нужно режимом `--check` с локальным токеном.
Источник: [VkUserPermissions.AUDIO](https://vk-api.readthedocs.io/en/latest/enums.html).

Первая страница запрашивается с `count=2000` без offset. Полнота сверяется с `count` ответа;
при необходимости запрашиваются следующие страницы. Пустая/повторяющаяся страница до получения
полного списка считается ошибкой, чтобы не сообщать об успешном скачивании части библиотеки.

## Сохранение и повторный запуск

Файлы пишутся в `.mp3.part`, затем переименовываются в `.mp3`. Прерванная загрузка не становится
готовым MP3; при повторном запуске незавершённый файл скачивается целиком. Существующий ненулевой
MP3 считается готовым. Коллизии названий внутри списка разрешаются суффиксом из хеша audio ID.
Несколько профилей используют отдельные подпапки; для докачки сохраняйте прежнюю команду/папку.

Ответы HTML, HLS/m3u8 и другие данные без признаков MP3 не сохраняются под расширением MP3.
Таймауты, обрывы, 429/5xx повторяются максимум трижды. Число потоков 1–8, по умолчанию 6.

Секреты, URL аудио, MP3 и логи не нужны в публичном Git. `.env` и результаты игнорируются,
а текст исключений requests/VK с потенциальными параметрами запроса не печатается.
