# ZenStack 3.10.3: обход post-update при смене nullable роли

## Наблюдение 2026-11-21

Общий test-прогон при обновлении зависимостей выявил падение Flora
`src/platform/db/policies.int.spec.ts`: пользователь смог назначить себе OPERATOR.
Схема разрешает обновлять собственный User, но запрещает смену роли:

```zmodel
platformRole PlatformRole?
@@allow('read,update', auth() != null && auth().id == this.id)
@@deny('post-update', (auth() == null || !auth().isOperator) && before().platformRole != platformRole)
```

Проверка на одной локальной БД и одной сгенерированной схеме с двумя установленными
версиями ORM/PolicyPlugin, отдельным пользователем на каждый запрос:

| Версия | Запрос `null → OPERATOR` | Роль после запроса |
| ------ | ------------------------ | ------------------ |
| 3.9.8  | отклонён                 | null               |
| 3.10.3 | выполнен                 | OPERATOR           |

Auth содержит `isOperator: false`. Временные записи удалены в `finally`.
Причина на уровне реализации SQL/интерпретатора не установлена: nullable-сравнение —
условие воспроизведения, а не доказательство конкретной внутренней ошибки.

## Защита обновлений

Семейство `@zenstackhq/*` закреплено на 3.9.8 в корневых dependencies/devDependencies,
overrides и resolutions. Одного точного корневого пина недостаточно: workspace-потребители
с caret-диапазоном могут получить отдельную новую копию.
Причины и условие снятия каждого пина зарегистрированы в `scripts/intentional-pins.json`.

Отслеживание исправления — LT-087. Перед снятием пинов проверить отказ смены роли,
неизменность строки после отказа и успешное разрешённое обновление пользователя.
Снимать все пины и overrides семейства одновременно. До этого обычный deps-update
не должен возвращать 3.10.3 автоматически.

Локальные материалы: `.claude/artifacts/deps-nov21-flora-policy-compare.ts` и логи LT-086.
Исходный тест и схема остаются в приватном submodule Flora; его исходники в рамках
обновления зависимостей не изменялись.
