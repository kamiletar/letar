# Миграция `next/font/google` → `next/font/local` — воркфлоу и инструменты

`next/font/google` скачивает шрифты при **каждой** сборке. Загрузчик хрупок не только к сетевой
недоступности: на domwellbes 2026-09-22 сборка падала внутри самого загрузчика
(`TypeError: Cannot read properties of null (reading '1')` в
`next/dist/compiled/@next/font/dist/google/loader.js:122`) при полностью доступном Google Fonts —
то есть хрупкость самого парсера ответа, не сети. Разбор конкретного инцидента —
`apps/domwellbes/src/app/fonts/README.md`. Все приложения монорепо переведены на
`next/font/local` 2026-09-22 (кроме тех, что уже не используют Google-шрифты).

## Инструменты

- **`scripts/fonts/subset-google-font.py`** — скачивает variable TTF (или статический — флаг
  `--static-file`, для семейств без variable-файла, например Fira Sans Condensed/IBM Plex Mono)
  и `OFL.txt` с зеркала `github.com/google/fonts`, вырезает unicode-подмножество, ограничивает
  ось `wght` реально используемым диапазоном (`fontTools.varLib.instancer` — БЕЗ сплющивания в
  статику; другие оси, если есть, остаются вариативными), сохраняет `.woff2`. Требует
  `pip install fonttools brotli`.
- **`scripts/fonts/scan-extra-glyphs.py <src-dir>`** — сканирует исходники приложения и печатает
  все символы вне latin+cyrillic с частотой и примером файла. Отправная точка для решения «что
  добавить сверх стандартных Google-диапазонов», не финальный список — каждый найденный символ
  нужно проверить руками (см. ниже).

## Порядок действий на приложение

1. Прочитать текущий вызов `Font_Name({ subsets, weight })` — это спецификация, которую надо
   воспроизвести 1:1 (не сузить и не расширить без явной причины).
2. `scan-extra-glyphs.py` по `src/` — получить список кандидатов на добавление.
3. **Каждый кандидат проверить по контексту** (`Grep -C 2`), не бланкетно копировать список:
   - JSDoc-комментарии, `@example`-блоки генерируемых файлов — не рендерятся, исключить.
   - `*.test.ts`/`*.spec.ts` — тестовые данные, не UI, исключить.
   - Email/Excel/Telegram-шаблоны — свой шрифтовый стек вне сайта, исключить (паттерн повторён в
     `driving-school`, `dsperevod`, `time`).
   - Emoji — рендерятся через системный emoji-шрифт по fallback независимо от основного шрифта
     (браузер подставляет emoji-фонт для символов, которых нет ни в одном шрифте CSS-стека), в
     субсет не включать.
   - Canvas/`ctx.font` с generic CSS-keyword (`monospace`, `sans-serif`) — не использует
     переменную шрифта приложения, исключить (прецедент — `matrix-rain.tsx` в `kami`).
   - Остальное — реально рендерящийся текст (цены, стрелки-ссылки, чекбоксы, рейтинги) — добавить
     отдельной unicode-range группой поверх стандартных latin/cyrillic диапазонов.
4. Собрать `.woff2` через `subset-google-font.py`. **Subset ДО instancer** — обратный порядок
   роняет часть шрифтов `KeyError` на глифах, которые инстансинг уже вычистил из `gvar`
   (проверено на живых сборках, не гипотеза).
5. **Верифицировать покрытие разбором `cmap`**
   ([font-cmap-coverage-verification](/.claude/docs/font-cmap-coverage-verification.md)), не
   доверять факту «символ был передан в `--unicodes`» — субсеттер тихо пропускает кодпоинты,
   которых нет в исходном шрифте. Если кандидат не покрылся — скачать **полный невырезанный**
   файл и проверить `cmap` на нём тоже: если глифа нет и там, это не регрессия перехода, это
   свойство самой гарнитуры (уже было так под `next/font/google`), задокументировать этот факт в
   README, а не пытаться «починить» несуществующим кодом.
6. Файлы шрифта класть **рядом с файлом, где вызывается `localFont()`**, не обязательно в
   `app/fonts/` — если шрифт подключается из `theme/fonts.ts`, каталог `theme/fonts/`, и `src:
   './fonts/...'` резолвится относительно этого файла. Несовпадение — `Font file not found` на
   `next build` (Turbopack не резолвит по алиасам, только относительно исходника).
7. Для семейств без variable-файла в google/fonts (проверяется по `find_variable_ttf` — скрипт
   сам подскажет список статических файлов, если variable не нашёлся) — несколько статических
   начертаний через массив `src: [{path, weight, style}, ...]` вместо одного файла с диапазоном
   оси.
8. Написать `README.md` рядом с файлами шрифта — что внутри, зачем каждая extra-группа символов,
   что сознательно не покрыто и почему (см. `apps/aboi/src/theme/fonts/README.md` и
   `apps/time/src/app/fonts/README.md` — последний разбирает 40-локальное приложение, где шрифт
   физически не может покрыть часть скриптов, и это не регрессия).
9. Полный гейт: `nx run-many -t format --projects=<app>` → `nx lint <app>` →
   `nx typecheck:tsgo <app>` → `nx build <app>` (обязателен — единственный способ поймать
   опечатку в относительном пути) → живая проверка в браузере
   (`getComputedStyle(el).fontFamily`), что нужный элемент реально резолвит нужный шрифт, а не
   откатился на `ui-sans-serif`/`system-ui` из-за
   [chakra-font-token-var-declaration-scope](/.claude/docs/chakra-font-token-var-declaration-scope.md).

## Многоскриптовые/мультиязычные приложения — отдельный случай

Приложение на десятки локалей (пример — `time`, 40 локалей) обычно использует один
латинско-кириллический шрифт для UI, но показывает нативные названия языков (переключатель
локали) в скриптах, которых у этого шрифта физически нет — Google Fonts не предлагает
CJK/арабский/иврит/армянский/грузинский/деванагари/тайский/тамильский-телугу subset для типичных
моноширинных/текстовых гарнитур. Для таких локалей браузер и раньше, под `next/font/google`,
рисовал текст через системный fallback — переход на `next/font/local` здесь **не регрессия**, а
неизменное поведение; задача — не «почему-то не работает», а задокументировать какие локали
покрыты нативно, а какие — фолбэком, и почему (см. `apps/time/src/app/fonts/README.md`).

Отдельно попадаются буквы того же алфавита, но вне базового Google-диапазона (например казахские
Қ/қ или таджикские ҷ/ӣ — вне блока Cyrillic 0400–045F, в Cyrillic Extended-B, который Google для
многих шрифтов не предлагает вовсе). Если этих букв не было в прежнем `subsets` — это тоже
известный, не новый пробел, а не то, что нужно закрывать расширением скоупа этой миграции.

## Дедупликация лицензий

Несколько статических начертаний одного семейства (см. п. 7) получают из скрипта отдельный
`OFL-<Family>-Regular.txt`/`OFL-<Family>-Medium.txt` — текст лицензии идентичен, `diff` и оставить
один файл `OFL-<Family>.txt` без суффикса начертания.
