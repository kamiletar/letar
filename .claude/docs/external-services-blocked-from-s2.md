# IP датацентра s2 блокируется внешними сервисами по-разному

## Суть проблемы

Сервис, который отлично работает из локальной dev-среды, может быть недоступен с прод-сервера s2 —
и не всегда одинаковым образом. На сегодня в монорепо найдено два независимых механизма блокировки:

| Сервис             | Кто блокирует        | Симптом                           | Найдено                |
| ------------------ | -------------------- | --------------------------------- | ---------------------- |
| `api.telegram.org` | Провайдер датацентра | Таймаут соединения (сеть режется) | ранее                  |
| `picsum.photos`    | Cloudflare (геоблок) | `403 Geoblocked` (не таймаут)     | domwellbes, 2026-07-30 |

Разница симптомов важна для диагностики: таймаут выглядит как временная сетевая проблема и
провоцирует ретраи, а `403` — явный отказ, который ретраями не лечится.

## Что делать при выборе внешнего сервиса

При добавлении **любой** новой внешней зависимости (демо-контент, сторонний API, шрифты,
изображения-плейсхолдеры и т.п.) в новое или существующее приложение — сначала проверить
доступность **прямым запросом с самого сервера** (`curl` по SSH), а не полагаться на то, что
сервис доступен, раз он работает локально. Локальная dev-среда и прод-сервер s2 — разные сетевые
условия, и это не гипотетический риск: оба найденных случая обнаружились только на проде.

## Два варианта решения

### 1. Проксирование — для одного фиксированного эндпоинта

Годится, когда внешняя зависимость — один известный API с ограниченным числом эндпоинтов
(`api.telegram.org`). Решение — `tg-proxy.letar.best`, отдельный прокси-сервис, через который
приложения ходят к Telegram API вместо прямого обращения. См. `TELEGRAM_API_ROOT` в кодовой базе
(`apps/*/src/lib/telegram/*`) — приложения, использующие Telegram Bot API, конфигурируют базовый
URL через эту переменную вместо хардкода `https://api.telegram.org`.

### 2. Полный отказ от внешней зависимости — для произвольных/множественных эндпоинтов

Годится, когда сервис отдаёт контент по множеству непредсказуемых URL (`picsum.photos/seed/<any>`)
— проксировать нечего, эндпоинтов бесконечно много. Решение — сгенерировать или самостоятельно
захостить контент вместо похода вовне.

Пример — `domwellbes`, `prisma/seed/db.ts` → `demoImage()`: вместо запроса к `picsum.photos`
функция генерирует SVG→PNG плейсхолдер локально (через `sharp`) и кладёт в `uploads/<category>/`
на диске при первом запуске сида, идемпотентно. Отдельный роут
`src/app/api/files/[...path]/route.ts` сервит `uploads/` (паттерн уже использовался в `aboi`).

## Известные случаи в монорепо

- **Telegram Bot API** — `api.telegram.org` заблокирован провайдером датацентра на s1/s2.
  Обходится через `tg-proxy.letar.best`.
- **picsum.photos** (`domwellbes`) — геоблок Cloudflare для IP s2, `403 Geoblocked`. Обходится
  полным отказом от сервиса — локальная генерация плейсхолдеров.
