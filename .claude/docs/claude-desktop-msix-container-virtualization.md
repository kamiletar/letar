# Шелл агента в Claude Desktop работает внутри MSIX-контейнера

⚠️ **Ловушка, которая выглядит как баг проверяемого приложения.** Claude Desktop на Windows
установлен MSIX-пакетом (`C:\Program Files\WindowsApps\Claude_*`). Процессы, которые агент
запускает через Bash/PowerShell, наследуют контейнер пакета, хотя собственной package identity
у них нет (`GetCurrentPackageFullName` → `15700 APPMODEL_ERROR_NO_PACKAGE`). Поэтому часть их
записей перенаправляется в виртуальное хранилище пакета, а не в настоящий профиль:

- **Реестр HKCU** — запись видна только процессам внутри контейнера; остальные читают прежнее
  значение. Виртуальный куст: `%LOCALAPPDATA%\Packages\Claude_<publisher>\SystemAppData\Helium\User.dat`.
- **Новые каталоги в `%LOCALAPPDATA%`** — создаются в
  `%LOCALAPPDATA%\Packages\Claude_<publisher>\LocalCache\Local\` (там уже лежат `vitest`,
  `ms-playwright-mcp`). Запись в существующие каталоги (например в
  `%LOCALAPPDATA%\Programs\<App>`) идёт в настоящее место.

## Как проявилось (kami-key-the, 2026-09-16…17)

- Тихий NSIS-инсталлятор, запущенный из шелла агента, обновил файлы, но в своём представлении
  реестра агент видел устаревший `DisplayVersion`. В настоящем реестре стояла новая версия.
- Экземпляр приложения, запущенный из шелла агента, при автообновлении запускал инсталлятор
  в том же контейнере. Установка не состоялась, перезапустилась старая версия. Тот же цикл от
  экземпляра, запущенного планировщиком, прошёл успешно.
- Метки, записанные агентом в HKCU, задача планировщика не видела. Запись, сделанная задачей
  (`reg add`), агенту видна — чтение из контейнера проходит сквозь виртуальный слой к настоящему
  реестру.

## Как проверять

Всё, чей результат должен оказаться в настоящем профиле (установщики, само приложение для живых
тестов, правки реестра), запускай **вне контейнера** — через планировщик задач:

```powershell
schtasks /create /tn Probe /tr "cmd.exe /d /c `"C:\path\to\script.bat`"" /sc once /st 23:59 /f
schtasks /run /tn Probe
schtasks /delete /tn Probe /f
```

Задача работает от того же пользователя (`LogonType=InteractiveToken`), но вне дерева процессов
Claude. Читать настоящее состояние тоже надо из такой задачи (`reg query ... >> log`), а не
из шелла агента.

Проверка «я в контейнере?»: сравни значение, записанное из шелла агента, с тем, что прочитает
задача планировщика. Флаги job здесь ничего не говорят: в job состоит даже `explorer.exe`, а у
job шелла агента нет `KILL_ON_JOB_CLOSE`.

## Что НЕ является причиной

- Уничтожение потомков при завершении фоновой задачи агента: проверено, detached-потомок
  переживает её конец.
- Job Object шелла: `BREAKAWAY_OK`, без `KILL_ON_JOB_CLOSE`.
