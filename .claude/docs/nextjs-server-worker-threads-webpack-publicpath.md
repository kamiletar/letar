# `worker_threads` в серверной сборке Next.js (webpack): три ловушки

Найдено при выносе рендера PDF в пул воркеров (`apps/domwellbes/src/lib/pdf/`, 2026-09-27).
Проверено прод-сборкой (`next build --webpack`) + `next start`; `next dev` (Turbopack) файл воркера не собирает.

## 1. Путь, который webpack подставляет в `new Worker(new URL(...))`, на сервере неверен

Путь строится от `publicPath` (`/_next/`) и превращается в `C:\_next\<id>.js`. Использовать сам
литерал нельзя. Литерал нужен только сборке: он заставляет webpack собрать воркер отдельным
самодостаточным чанком `<distDir>/server/chunks/<имя>.js`. Имя задаёт комментарий
`/* webpackChunkName: "..." */` (опция `name` конструктора `Worker` — игнорируется). Реальный
путь считается вручную от `process.cwd()` и `NEXT_DIST_DIR ?? '.next'`. Литерал держат в
никогда не вызываемой функции.

Standalone-трассировка копирует весь `server/chunks/*`, отдельный `outputFileTracingIncludes` не нужен.

## 2. Воркер собирается дважды — по слою на каждого импортёра

Файл-импортёр воркера попадает в несколько слоёв (`rsc` для route handlers, другой — для
server actions), и webpack кладёт в один чанк **две копии** воркера. Обе исполняются в одном
потоке. В слое `rsc` JSX-рантайм пустой: `<div />` компилируется в `(void 0)(...)`, а экспорты
чужих модулей, которые дёргает воркер, выкидываются как неиспользуемые. Симптом:
`TypeError: (void 0) is not a function` в ответе воркера при исправном коде.

Что не помогло: `import * as ns`, отдельный `.ts`-файл ядра. Что работает:
переключатель шаблонов лежит прямо в файле воркера, а копия сначала проверяет `<div />` в
`try/catch` и регистрирует обработчик `message`, только если JSX работает и глобальный флаг ещё
не занят. Неработающая копия молчит.

## 3. Проверка

- В собранном чанке нет `(void 0)(` рядом с `renderToBuffer`;
- `next start` (Windows; standalone на Windows не запускается) с тем же `NEXT_DIST_DIR`;
- в логе `[pdf] рендер в пуле воркеров: 1` и нет `[pdf] воркер не справился`.
  Ошибка рендера в воркере (`PdfRenderFailedError`) наружу отдаётся без запасного пути — поэтому
  битая копия видна как 500, а не как тихий откат в основной поток.
