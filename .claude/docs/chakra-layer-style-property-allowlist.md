# Layer style в Chakra v3 принимает закрытый список свойств

⚠️ Лишнее свойство внутри `defineLayerStyles` не даёт ошибку на своей строке. Оно роняет **весь**
объект `value` во вторую ветку объединения и выдаёт `TS2322` на каждом свойстве блока — включая
те, к которым никто не прикасался. Ошибка указывает не туда, где причина.

## Что происходит

`LayerStyles` объявлен как `Recursive<Token<LayerStyle>>` — либо один layer style, либо вложенный
реестр других layer style. `LayerStyle` — это `CompositionStyleObject<LayerStyleProperty>`, где
`LayerStyleProperty` (`@chakra-ui/react/dist/types/styled-system/composition.d.ts`) — **закрытое
объединение строк**, а не все CSS-свойства.

Как только у объекта появляется свойство вне списка, он перестаёт совпадать с `LayerStyle`,
и TypeScript пробует вторую ветку — «это реестр вложенных токенов». Там каждый лист обязан быть
`Token<...>`, то есть объектом с полем `value`. Поэтому жалоба приходит на каждую строку:

```
error TS2322: Type 'string' is not assignable to type 'Recursive<Token<LayerStyle>> | Token<LayerStyle>'.
```

и указывает даже на безобидное `transform: 'none'`.

## Что в список НЕ входит

Список — про внешний вид поверхности. Снаружи остались, в частности:

- **поведенческие свойства**: `touchAction`, `userSelect`, `scrollBehavior`;
- **longhand-свойства перехода**: `transitionDuration`, `transitionTimingFunction`,
  `transitionProperty`, `transitionDelay` — из перехода разрешён только шорткат `transition`;
- **анимация целиком**: `animationName` и соседи — для них есть отдельный `animationStyles`
  со своим (тоже закрытым) списком `AnimationStyleProperty`.

Внутри `defineRecipe`/`defineSlotRecipe` и в пропсах компонента ограничения нет: там полноценный
`SystemStyleObject`. То есть одно и то же свойство законно в рецепте и незаконно в layer style.

## Как чинить

1. Найти в блоке свойство вне списка — по номерам строк это не видно, смотреть глазами весь
   `value`. Быстрый способ: удалять свойства по одному и считать ошибки; счётчик падает до нуля
   ровно на виновнике, а не уменьшается на единицу.
2. Перенести его туда, где оно легально:
   - поведенческое — в рецепт (`variants.<...>.root`) и в прямых потребителей layer style
     отдельным пропом;
   - longhand-переход — свернуть в шорткат `transition` с тем же набором свойств.

## Как это выглядит вживую

Диагностика ломается дважды. Во-первых, счётчик ошибок остаётся почти неизменным при удалении
невиновных свойств (28 → 27), поэтому обычная бисекция «убрал строку — стало лучше» не помогает.
Во-вторых, после переноса виновника TS начинает наконец сообщать настоящую вторую ошибку
(`TS2353`, «`transitionDuration` does not exist in type `Nested<FilterStyleObject<...>>`») — она
была всё это время, но её маскировал развалившийся вывод типов.

⚠️ Рантайм при этом **исправен**: Chakra отдаёт CSS с этими свойствами, стиль в браузере работает.
Поэтому ошибка легко переживает сессию, где её проверяли глазами в браузере, а не `typecheck`.
