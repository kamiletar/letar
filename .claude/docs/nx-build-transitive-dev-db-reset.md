# Транзитивный build-target может сбросить локальную dev-БД

При обновлении зависимостей 2026-10-24 общий `nx run-many -t build --exclude=animatrona`
всё равно включил `animatrona:db:template` через зависимости других build-targets.
Исключение проекта из списка корневых задач не исключает транзитивно востребованные шаги.

`apps/animatrona/scripts/db-template-safe.ts` перед созданием шаблона удаляет
`prisma/data/app.db` и журнал, затем выполняет `prisma db push` и копирует результат
в `resources/template.db`. Если db push падает, исходная локальная dev-БД уже может быть удалена.
Название `safe` и переменная `PRISMA_USER_CONSENT_FOR_DANGEROUS_AI_ACTION` не подтверждают
сохранность данных и не заменяют разрешение владельца на их сброс.

Перед широким build-прогоном проверяй команды транзитивных задач, особенно `db:*`,
генераторы шаблонов и подготовку Electron-ресурсов. Пользователь может хранить данные
и в игнорируемой git локальной БД.

Безопасный вариант генерации шаблона:

1. Создать отдельный временный каталог и пустую БД в нём.
2. Передать генератору URL именно этой временной БД.
3. Заполнить только необходимые шаблонные данные.
4. Копировать готовый шаблон в ресурсы после успешного завершения всех шагов.
5. Удалить только собственный временный каталог, проверив абсолютную границу пути.

Изменение самого генератора ведётся отдельно в LT-079. До этого его нельзя повторять
в общем checkout без проверки данных и изоляции. При уже случившемся сбое сначала
сохрани доступные DB/WAL/SHM/backup-файлы; не подменяй неизвестную прежнюю БД шаблоном
без проверки, что именно нужно восстановить.

Не скрывай неисполненный prerequisite из отчёта о сборке: записывай упавший шаг
и заблокированные им build-targets отдельно.
