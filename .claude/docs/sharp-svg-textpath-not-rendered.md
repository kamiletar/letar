# sharp/librsvg: `<textPath>` не рендерится вовсе

⚠️ Применимо к любому SVG, рендерящемуся через `sharp` (librsvg под капотом) — не специфично
для одного приложения. Найдено 2026-09-03 в `poster-microtext-desktop` при реализации
изогнутого текста (PLAN.md, «Вариативность нанесения», пункт 5 «Дуга»).

## Симптом

`sharp(Buffer.from(svg)).raw().toBuffer()` над SVG с `<textPath>` даёт буфер из одних нулей —
**без единой ошибки**. Обычный `<text>` в том же документе рендерится штатно. Выглядит как
опечатка в разметке или проблема с `escXml`, хотя причина — в самом рендерере.

## Проверено эмпирически, не по документации librsvg

На версии `rsvg: 2.62.91` (сборка sharp `0.35.4`) не сработал ни один из вариантов:

- `<textPath href="#id">` — 0 закрашенных пикселей;
- `<textPath xlink:href="#id">` (с объявленным `xmlns:xlink`) — 0;
- путь в `<defs>` вместо голого `<path>` в теле SVG — 0;
- прямая линия вместо дуги (упрощение до предела) — тоже 0, то есть дело не в форме пути.

При этом `<text x="..." y="...">обычный текст</text>` в том же вызове `sharp()` рендерится
нормально — рендерер в целом работает, не рендерится именно связка `<path>`+`<textPath>`.

## Рабочая замена — посимвольные списки `x`/`y`/`rotate`

SVG 1.1 позволяет задавать позицию и поворот **каждого символа** прямо на `<text>`, без
`<textPath>`:

```xml
<text x="10,15,21,28" y="30,29,28,28" rotate="-10,0,10,20" font-family="Arial" font-size="16">
  ABCD
</text>
```

Это рендерится тем же `sharp`/librsvg корректно (проверено тем же способом — подсчётом
ненулевых байт растрового буфера). Цена: ширина каждого символа для расчёта позиций нужно
знать заранее — либо реальным замером (дорого при большом числе символов/надписей), либо
приближением (равномерное деление общей ширины строки на число символов — годится, когда
контекст и так не требует типографской точности, как в `poster-microtext-desktop`, где
раскладка уже опирается на измерение реальным рендером только для габаритов слова целиком).

Реализация приближения — `arcTextPositions` в
`apps/poster-microtext-desktop/main/services/microtext/geometry.ts` (приватный submodule).

## Как проверять эту грабля быстро, без сборки приложения

```bash
node -e "
const sharp = require('sharp');
(async () => {
  const svg = '<svg xmlns=\"http://www.w3.org/2000/svg\" width=\"200\" height=\"100\">' +
    '<path id=\"c\" d=\"M 10 50 L 190 50\"/>' +
    '<text font-family=\"Arial\" font-size=\"20\" fill=\"#fff\"><textPath href=\"#c\">TEST</textPath></text>' +
    '</svg>';
  const { data } = await sharp(Buffer.from(svg)).greyscale().raw().toBuffer({resolveWithObject:true});
  console.log('nonzero:', data.filter(b => b > 10).length);
})();
"
```

`nonzero: 0` — грабля воспроизвелась на текущей версии sharp/librsvg; ненулевое число —
`<textPath>` в этой сборке уже работает, замена не нужна.
