# `toPass(click)` зависает на кнопке, которая гаснет на время server action

> Найдено 2026-09-23 в `domwellbes-e2e` («В корзину», «Оплатить»).

## Симптом

Тест с ретраем гидратации падает по таймауту **теста**, а не ассерта:

```ts
await expect(async () => {
  await button.click()
  await expect(result).toBeVisible({ timeout: 2000 })
}).toPass({ timeout: 20000 })
```

Первый клик дошёл, server action идёт дольше 2 с (под нагрузкой на staging), внутренний ассерт
падает — `toPass` повторяет колбэк. Кнопка в этот момент `disabled` (`loading`), и второй
`click()` ждёт её активности **без таймаута** (`actionTimeout` по умолчанию 0). Потом экшен
завершается, кнопка исчезает из DOM (компонент рисует «Добавлено»), клик ждёт уже появления
элемента — до конца теста. Результат на экране есть, тест красный.

Второй риск того же паттерна — повторный клик по неидемпотентному действию, если первый просто
медленный (двойное добавление в корзину, дубль заявки).

## Правило

Повторять клик **только по активной кнопке**: принятый клик гасит её на время экшена, значит
активная кнопка после паузы = клик потерялся до гидратации.

```ts
await button.click()
await expect(async () => {
  if (await result.isVisible()) { return }
  if ((await button.count()) > 0 && (await button.isEnabled())) {
    await button.click()
  }
  await expect(result).toBeVisible({ timeout: 3000 })
}).toPass({ timeout: 25000 })
```

Ошибку экшена, которую компонент рисует рядом с кнопкой, стоит проверять внутри колбэка и
бросать её текстом — иначе настоящий отказ сервера неотличим от таймаута. Готовый хелпер —
`apps/domwellbes-e2e/src/helpers/add-to-cart.ts`.

Для навигационных ссылок (`<a>`) ловушки нет — они не гаснут; там достаточно проверки URL
перед повторным кликом (`if (!pattern.test(page.url())) await link.click()`).
