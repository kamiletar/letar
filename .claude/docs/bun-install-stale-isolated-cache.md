# `bun install` не прунит устаревшие isolated-копии в `node_modules/.bun`

**Короткий вывод:** несколько версий одного пакета в `node_modules/.bun` после снятия локального
пина — не признак того, что резолюция зависимостей не схлопнулась. `bun.lock` может резолвить уже
одну версию; обычный `bun install` физические копии старых версий по себе не удаляет. Проверять
факт резолюции — по `bun.lock`, а не по `node_modules/.bun`; чинить лишние копии — `bun install --force`.

## Симптом

Убрали локальный пин версии пакета из `package.json` конкретного приложения (например
`"react": "19.2.3"` в `apps/animatrona-mobile/package.json` и `apps/animatrona-tv/package.json`),
чтобы версия бралась только из корневого `package.json` (`"react": "^19.2.8"`). После обычного
`bun install` в `node_modules/.bun` всё ещё физически лежат несколько версий пакета (в конкретном
случае — 19.2.3/19.2.6/19.2.7/19.2.8 одновременно). Выглядит так, будто снятие пина не подействовало
и резолюция зависимостей всё ещё не сошлась к одной версии.

## Причина

Bun ставит зависимости в изолированном режиме (isolated installs) — `node_modules/.bun` хранит
физически раздельные копии пакета для разных peer-контекстов workspace-члена, а не единую
плоскую версию на всё дерево, как npm/yarn classic. Это устройство хранилища, а не признак
незавершённого резолва.

`bun.lock` при этом может уже резолвить единственную версию пакета — снятие пина сработало
корректно. Но обычный `bun install` (запуск без изменений, влияющих на сам резолв) не гарантирует
прунинг физических копий, ставших неиспользуемыми в `node_modules/.bun`: устаревшие каталоги могут
остаться на диске, даже когда ни один package.json в дереве больше на них не ссылается.

## Диагностика

Не полагаться на `ls node_modules/.bun` как на источник истины о резолюции. Сверять реальный
резолв через `bun.lock`:

```bash
grep -n '"react@' bun.lock
```

Если в выводе одна запись версии пакета (например только `"react@19.2.8"`) — резолюция уже верна,
несмотря на то что `node_modules/.bun` показывает несколько версий на диске.

## Фикс

```bash
bun install --force
```

Принудительно пересобирает `node_modules` с нуля и оставляет на диске только те копии пакета,
которые реально нужны по текущему `bun.lock`.
