# Индекс документации

Полный индекс `.claude/docs/` — ссылка, условие «когда нужен» и развёрнутая аннотация с
механизмом ловушки. Короткая карта (строка на док) — в разделе «Документация» корневого
[CLAUDE.md](/CLAUDE.md); сюда приходят за подробностями, прежде чем открывать сам док.

⭐ — читать до начала работы в теме, ⚠️ — ловушка, которая выглядит как успех.

## Как вести этот файл

Новый док в `.claude/docs/` → **две** записи: развёрнутая здесь, в нужном тематическом разделе, и
короткая (ссылка + 5–10 слов) в CLAUDE.md. Аннотация здесь может быть любой длины — это не
контекст каждой сессии. В CLAUDE.md — строго одна строка.

- [zenstack-int4-overflow-money-fields](/.claude/docs/zenstack-int4-overflow-money-fields.md) ⚠️ денежное поле, исторически объявленное `Int` (не `Decimal` — та конвенция для физических величин) и хранящее сумму в копейках, падает на Postgres `value "3000000000" is out of range for type integer` — `Int`/INT4 у Prisma/ZenStack максимум `2 147 483 647`, это ≈21,47 млн ₽ в копейках, любая сумма дороже квартиры в среднем городе уже превышает лимит; баг проявляется только на конкретных больших значениях, а не на каждой записи, поэтому живёт до первого реалистичного прогона (домен — `FinancingProgram.minAmountKopecks`/`maxAmountKopecks` в `apps/domwellbes`, дефолт формы 30 000 000 ₽). Фикс — `BigInt` (INT8), не `Decimal`: сумма в копейках всегда целая, `BigInt` не тянет раундинг `decimal.js`; прямой `number → bigint` каст Prisma/ZenStack input не принимает вовсе, нужен явный `BigInt(...)`. Дальше три места, где рантайм `bigint` конфликтует с остальным кодом на `number`: RSC-граница не сериализует `bigint` в Client Component без явной ошибки в консоли браузера (только в серверном логе) — конвертировать `Number(...)` сразу при чтении; `JSON.stringify` бросает `TypeError` на объекте с `bigint`-полем — типичное место, snapshot-паттерн `JSON.parse(JSON.stringify({...}))` в server actions; Zod-схема формы и бизнес-логика (`decimal.js`, `formatKopecks`) остаются на `z.number()`, конвертация только в двух точках записи (`create`/`update`) и во всех точках чтения. Ловушка на частичном `update`: `{ ...data, minAmountKopecks: BigInt(data.minAmountKopecks) }` сводит tsgo-тип поля к `number | bigint` (Prisma input не принимает union) — вместо спреда нужно вынести поле деструктуризацией и добавить его условно, только если пришло в патче

- [redis-pubsub-cross-replica-registry-pattern](/.claude/docs/redis-pubsub-cross-replica-registry-pattern.md) кросс-реплика реестр (открытые сессии + ожидающие запросы), протестированный без реального Redis (прецедент — `apps/domwellbes/src/lib/assist/registry.ts`). Задача: модуль держал состояние в `globalThis.<key>` — стандартный приём против дублирования модуля в dev-режиме Turbopack, но работает только в одном процессе; на проде с несколькими репликами за балансировщиком без sticky-сессий два запроса одного логического потока (долгоживущий SSE-коннект и короткий HTTP-запрос команды к нему) могут попасть на разные реплики — `globalThis` одной реплики не виден другой. Решение — три приёма вместе: (1) факторизация модульного синглтона в фабрику `createRegistry(deps)` — дефолтный экспорт по-прежнему один вызов на `globalThis` (дедуп Turbopack сохраняется), а фабрика даёт создать несколько независимых инстансов в одном процессе теста, это и симулирует «две реплики» с общим хранилищем без поднятия настоящего Redis; (2) узкие структурные интерфейсы вместо `import type` клиента (`ioredis` не прямая зависимость приложений под bun isolated linker) — свой интерфейс с ровно нужными методами (`get/set/expire/keys/mget/publish`, `subscribe/on('message')`), реальный клиент удовлетворяет ему структурно без каста, эти интерфейсы и есть точка инъекции fake; (3) fake-брокер — минимальный `Map`-based объект с теми же методами вместо `ioredis-mock`/настоящего Redis (ни CI, ни локальная машина к нему доступа не имеют), два вызова фабрики с одним и тем же брокером = «две реплики с общим Redis». Асимметрия датаплейнов: команды («что-то произошло прямо сейчас») — чистый pub/sub без хранения после доставки; метаданные сессии (какие вкладки открыты, читаются синхронно, `listSessions()` не `async`) — KV с TTL плюс фоновый poll, потому что подписка на канал не даёт снимок «что есть сейчас», только будущие события. Когда браться за этот паттерн, а не за sticky-сессии на прокси — когда решение принимает не тот, кто настраивает прокси, и нужна устойчивость к рестарту/скейлингу реплики
