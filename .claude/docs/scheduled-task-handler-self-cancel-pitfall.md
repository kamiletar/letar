# `ScheduledTask`: обработчик не должен снимать (`cancelTask`) собственную задачу

⚠️ Паттерн общий для любого приложения с отложенными задачами по образцу `platform/events/tasks.ts`
(`scheduleTask`/`cancelTask`/`runDueTasks`), не только для Flora.

## Механизм

`runDueTasks` берёт задачу условным `updateMany` (растёт `attempts`), исполняет обработчик, затем
помечает её выполненной: `db.scheduledTask.update({ where: { id: task.id }, data: { doneAt: now } })`.

`cancelTask(tx, key)` — это `deleteMany({ where: { key, doneAt: null } })`: физическое удаление
строки, не пометка. Если обработчик внутри своего же выполнения вызовет `cancelTask` на **свой**
ключ, строка исчезает раньше, чем планировщик успеет проставить `doneAt` — второй `update` бьёт в
несуществующую запись (`Record to update not found`), и задача уходит в ветку `failed` с ложной
ошибкой вместо тихого успеха.

## Правило

Обработчик задачи снимает **чужие** таймеры (например, авто-отмена по неоплаченному заказу может
снять таймер оплаты другого заказа), но никогда не удаляет запись, которую планировщик прямо сейчас
исполняет. Если условие «задача больше не нужна» относится к ней самой — просто ничего не делай и
дай обработчику завершиться штатно (планировщик сам поставит `doneAt`); в Flora это выражено
комментарием в обработчике (`src/modules/orders/server/handlers.ts`,
`createAcceptTimeoutTask`): «NOT_ALLOWED — магазин уже решил, NOT_DUE — срок сдвинут: в обоих
случаях задача выполнена» — обработчик просто возвращается, не трогая свою же строку.
