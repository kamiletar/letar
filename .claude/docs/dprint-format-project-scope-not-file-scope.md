# `--projects` ограничивает какие проекты форматируются, а не какие файлы внутри проекта

Связано с [dprint-worktree-submodule-scope](dprint-worktree-submodule-scope.md), но другой
механизм: там `excludes` не срабатывают из-за `cwd`; здесь `excludes`/`--projects` работают
штатно, но сам таргет `format` внутри выбранного проекта форматирует **весь проект целиком**, а
не только файлы, изменённые в текущей сессии.

## Симптом

Команда выполнена ровно так, как требует `CLAUDE.md` — с явным `--projects`:

```bash
nx run-many -t format --projects=domwellbes,@letar/admin-ui
```

Тем не менее внутри submodule `apps/domwellbes` переформатировано 274 файла, из которых
подавляющее большинство сессия не трогала. Diff выглядит как масштабный рефакторинг (кавычки,
точки с запятой), хотя по сути ничего не изменилось.

## Причина

Таргет `format` каждого проекта (`apps/domwellbes/project.json`) объявлен так:

```json
{
  "command": "bunx dprint fmt \"**/*.{ts,tsx,js,jsx,json,md}\"",
  "cwd": "apps/domwellbes"
}
```

Glob `**/*.{ts,tsx,js,jsx,json,md}` жёстко зашит в команду и не принимает список файлов
снаружи — `nx run <project>:format -- file1 file2` просто добавит `file1 file2` как
дополнительные аргументы `dprint fmt`, не заменив glob (проверено по `project.json`: у таргета
нет входного параметра под список файлов). `--projects` в `nx run-many` решает только «какие
проекты запускать», а не «какие файлы внутри проекта форматировать» — у таргета `format` **нет
файловой гранулярности**.

## Два независимых следствия одной причины

### 1. Первый прогон вскрывает исторический дрейф стиля

Если `apps/domwellbes/dprint.json` требует `quoteStyle: "preferSingle"` +
`semiColons: "asi"` (как у всего монорепо), а часть кода приложения исторически писалась в
double-quote/semicolon стиле (до появления `dprint.json` у приложения, либо кодогенератором с
другими настройками) — единичный `nx format --projects=domwellbes` даёт сотни правок разом.
Это не баг конкретного прогона, а первое применение форматтера к файлам, которые никогда через
него не проходили.

**Как отличить от реальной проблемы:** посмотреть на характер диффа — только кавычки/`;`/отступы
без изменения логики означает первый прогон, а не чужой рефакторинг.

### 2. Коллизия с параллельным агентом внутри того же submodule

`file_reservation_paths` в Agent Mail не блокирует запись физически (см.
[agent-mail.md § Работа внутри submodule](/.claude/rules/agent-mail.md)) — она только
уведомляет. Если в момент прогона `format` другой агент правит файлы в том же submodule
(например `src/theme/*`, `PLAN.md`, `docs/ARCHITECTURE.md` — незакоммиченный рефакторинг
дизайн-системы), `dprint fmt` переформатирует и их тоже. Контент чужих правок не портится (dprint
меняет только стиль), но их diff временно несёт стилевую примесь поверх настоящих изменений —
риск случайно закоммитить чужой незакоммиченный код вместе со своим при
`git add apps/domwellbes/`.

## Восстановление после инцидента

1. Получить полный список задетых файлов: `git status --porcelain -- apps/domwellbes`.
2. Разделить на «чужие уже грязные до прогона» (принадлежат другому агенту — их **нельзя**
   слепо `git checkout`, это уничтожит незакоммиченную работу) и «переформатированные этим
   прогоном». Разделение — по `git diff` построчно: чисто стилевые правки без изменения логики
   на файлах, которые сессия не трогала намеренно, откатываются; остальное — нет.
3. Точечный откат оставшихся файлов **по одному**, не каталогом (иначе заденет чужие):

   ```bash
   while IFS= read -r f; do git checkout -- "$f"; done < files_to_revert.txt
   ```

   ⚠️ `xargs -d '\n' git checkout --` в этой Windows/git-bash-среде ведёт себя ненадёжно —
   не гарантирует полную обработку списка. `while read` через `< file.txt` — рабочий вариант,
   проверенный на 265+ файлах.

## Как не нарваться

- **Перед коммитом форматировать точечно, не таргетом проекта целиком.** У таргета `format`
  сейчас нет флага ограничения по файлам — обходить нужно, вызывая `dprint fmt` напрямую с
  явным списком изменённых путей, из каталога проекта (чтобы подхватился его собственный
  `dprint.json`):

  ```bash
  cd apps/domwellbes && bunx dprint fmt src/theme/colorMode.ts src/components/Foo.tsx
  ```

  Список изменённых файлов — `git status --porcelain -- apps/domwellbes | awk '{print $2}'`
  (или эквивалент без `awk`, если недоступен в среде).

- **`nx run-many -t format --projects=<app>` оставлять для случаев, когда весь проект
  действительно нужно переформатировать целиком** (первый прогон после появления
  `dprint.json`, разовая чистка исторического дрейфа) — и делать это отдельным коммитом
  `style: dprint fmt <app>`, не смешанным с содержательными изменениями (см. общее правило в
  [dprint-worktree-submodule-scope § Как не нарваться](dprint-worktree-submodule-scope.md#как-не-нарваться)).
- **В submodule, где может параллельно работать другой агент** — перед широким `format`
  свериться с `fetch_inbox`/резервациями на `apps/<submodule>/**`
  ([agent-mail.md](/.claude/rules/agent-mail.md)), а лучше не запускать широкий `format` вовсе,
  ограничившись точечным вызовом из пункта выше.

## Известные случаи

- **2026-08-13** (сессия работы над `apps/domwellbes`) — `nx run-many -t format
  --projects=domwellbes,@letar/admin-ui` (с корректным `--projects`, как требует `CLAUDE.md`)
  переформатировал 274 файла внутри submodule, никогда ранее не прогонявшегося через dprint
  целиком. Параллельно в том же submodule шёл незакоммиченный рефакторинг дизайн-системы другим
  агентом (`src/theme/*`, `PLAN.md`, `docs/ARCHITECTURE.md`) — контент не пострадал, diff нёс
  стилевую примесь. Восстановлено точечным `git checkout -- <file>` по 265+ файлам через
  `while IFS= read -r f; do ...; done`, `xargs -d '\n'` не сработал.
