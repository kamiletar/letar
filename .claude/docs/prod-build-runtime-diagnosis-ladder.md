# Лестница диагностики: dev → `next start` → standalone в контейнере

Когда код работает локально и падает на сервере, «локально» и «на сервере» — это не две точки, а
четыре, и различаются они сразу по нескольким осям. Прогнать промежуточные ступени дешевле, чем
гадать: каждая отсекает часть гипотез.

| Ступень                              | Что добавляется к предыдущей                                                              |
| ------------------------------------ | ----------------------------------------------------------------------------------------- |
| `next dev`                           | —                                                                                         |
| `next build` + `next start` локально | минификация, prod-бандл, `serverExternalPackages`, заинлайненный `import.meta.url`        |
| `node .next/standalone/…/server.js`  | только трассированные файлы, `process.chdir()`, симлинки `.bun`, свой резолв из чанков    |
| контейнер на сервере                 | linux вместо Windows, другая версия Node, тома с чужим uid, отсутствие `src/`, переменные |

Падение «работает локально — падает в контейнере» приписывают образу целиком; на деле
ответственная ступень обычно одна, и её видно за несколько минут.

## Чем это лучше чтения логов

Логов может не быть вовсе. Фоновая задача, которая ловит ошибку и пишет её в колонку БД, не
печатает ничего в stdout; прод-бандл минифицирован, поэтому в колонке оказывается что-нибудь вроде
`d is not a function` — без стека, без имени модуля, без файла. Ступень, на которой это
воспроизводится, говорит больше, чем сама строка.

⚠️ **`next start` запускает те же минифицированные чанки, что и прод.** Если на нём цепочка
проходит, минификация и prod-бандл ни при чём — остаются standalone-трассировка и окружение
контейнера. Но «ни при чём» тут — гипотеза, а не вывод: в разборе `d is not a function`
(2026-09-22) дефект сидел **именно в форме бандла** (webpack строил ES-namespace `node:module`
без `createRequire`,
[разбор](/.claude/docs/webpack-createrequire-resolve-nullified.md)), и всё же локальный
`next start` ту же модель собирал успешно. Причину расхождения найти не удалось. Поэтому ступень
отсекает гипотезы только вместе со стендом, а зелёная — ничего не доказывает. Предупреждение «`next start` does not work with `output: standalone`» на это не
влияет: сервер поднимается и обслуживает запросы, просто не из каталога `standalone/`.

⛔ **Standalone локально под Windows не поднять** — `server.js` спотыкается о junction-симлинки
`.bun` с `EPERM: operation not permitted, stat ...node_modules/react`. `--preserve-symlinks` не
обходит проблему, а подменяет её другой (`Cannot find module 'debug'` из
`require-in-the-middle`): флаг меняет резолв для всего процесса, включая сам Next. Эта ступень
доступна только на linux — на сервере или в контейнере.

## Оси, которые различаются между локальной машиной и контейнером

Проверять их по одной, не «в целом»:

- **версия Node.** Локально может быть новее образа (`node -v` в контейнере против своей). Вызов
  API, появившегося в свежей версии, даёт в минифицированном коде ровно «X is not a function»;
- **платформа.** Windows против linux — разные пути, разные нативные бинарники
  ([sharp/libvips](/.claude/docs/nextjs-standalone-tracing.md)), разное поведение `path.join` в
  glob-сравнениях ([разбор](/.claude/docs/nextjs-tracing-excludes-windows-backslash.md));
- **состав `node_modules`.** В образе только то, что натрассировал `@vercel/nft`: `ls
  /app/node_modules/.bun | grep <пакет>` отвечает на это за секунду;
- **тома и права.** Свежесозданный bind-mount принадлежит `root:root`, контейнер ходит под
  непривилегированным uid ([разбор](/.claude/docs/docker-bind-mount-uid-gid-mismatch.md));
- **переменные окружения.** Особенно те, чьё отсутствие включает fail-closed ветку, а не ошибку
  ([пример](/.claude/docs/file-scanner-unconfigured-rejects-all-uploads.md)).

## ⚠️ Проверка резолва не проверяет цепочку

Скрипт, который строит свой `createRequire` от каталога серверных чанков и резолвит оттуда
критичные специфайры, отвечает на вопрос «файл доехал и достижим». Он **не** отвечает на вопрос
«его найдёт код приложения»: у собранного чанка свой резолвер, свой заинлайненный при сборке
`import.meta.url` и свои минифицированные имена. Обе проверки нужны, но подменять вторую первой
нельзя — зелёный резолв соседствует с падающей цепочкой.
