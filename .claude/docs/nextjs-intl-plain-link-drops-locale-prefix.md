# `next/link` вместо `Link` из `next-intl` тихо теряет префикс локали

## Симптом

Ссылка, собранная сервером как обычная строка (`href={`/shops/${slug}`}`) и отрендеренная через
`next/link`, на локали по умолчанию (`ru`, без префикса при `localePrefix: 'as-needed'`) ведёт
куда надо. На любой другой локали (`/en/...`) она уводит пользователя на `/shops/{slug}` — то
есть обратно на `ru`-версию сайта, минуя `/en`. Ни ошибки, ни предупреждения: страница открывается,
просто язык интерфейса неожиданно переключается на дефолтный.

## Причина

`next/link` ничего не знает про роутинг `next-intl` и подставляет href буквально. Локаль-зависимые
ссылки обязаны идти через `Link` из обёртки `createNavigation(routing)` (обычно
`src/i18n/navigation.ts`) — она сама добавляет текущий префикс локали к относительному пути.
Компоненты, которые строят ссылку из пропа-строки (карточка товара, хлебные крошки, футер), обычно
уже используют такую обёртку — но новый код на соседней странице, добавляющий ещё одну ссылку на
тот же ресурс (например «продавец» → страница магазина), легко подключает `next/link` по
привычке, если автор ориентируется на импорт в верху файла, а не на назначение конкретной ссылки.

## Как проверить

Открыть страницу с проблемной ссылкой на не-дефолтной локали (`/en/...`) и посмотреть `href` в
аккуратном дереве (`read_page` инструмента браузера) или просто кликнуть и свериться с адресной
строкой — обычный просмотр верстки на дефолтной локали ловушку не покажет.

## Фикс

```diff
-import Link from 'next/link'
+import { Link } from '@/i18n/navigation'
```

Дальше `<Link href="/shops/slug">` работает как обычный `next/link`, но подставляет локаль. Правило
общее для любого приложения на `next-intl` с `createNavigation`, а не специфика одного проекта.
