# ⚠️ Страница без своей `metadata` наследует canonical и заголовок корневого layout

Next.js App Router сливает `metadata` от корня к листу. Поле, которого страница не задала,
приезжает от ближайшего предка, который его задал. Для `title`/`description` это ожидаемо и
обычно безобидно. Для `alternates.canonical` — нет.

Корневой layout приложения почти всегда объявляет canonical главной:

```ts
// app/[locale]/layout.tsx
alternates: {
  canonical: locale === routing.defaultLocale ? '/' : `/${locale}/`,
  languages: { ru: '/', 'x-default': '/' },
}
```

Любая страница ниже, у которой нет своего `alternates`, **объявляет своим каноническим адресом
главную страницу сайта**. Ни typecheck, ни lint, ни визуальный осмотр этого не показывают —
страница выглядит и работает нормально, разница только в `<link rel="canonical">`.

## Худший случай: `canonical` на главную + `noindex`

Страница с `robots: { index: false }`, но без своего `alternates`, отдаёт одновременно:

```html
<link rel="canonical" href="https://example.com/" />
<meta name="robots" content="noindex, nofollow" />
```

Это не «избыточно, но безвредно». Первый тег сообщает поисковику, что каноническая версия этого
URL — главная страница, второй — что индексировать не нужно. Директива с canonical-цели может
быть перенесена на саму цель, то есть на главную. Ставя `noindex` служебной странице, всегда
снимай и унаследованный canonical.

## Как снять наследование

Только явным `null`. `undefined` означает «поле не задано» — наследование останется:

```ts
export const PRIVATE_PAGE_METADATA = {
  alternates: { canonical: null },
  robots: { index: false, follow: false },
} as const satisfies Pick<Metadata, 'alternates' | 'robots'>
```

`languages: null` **не компилируется** — тип поля `Languages<...> | undefined`, `null`
допустим только у отдельных языков внутри объекта, не у всего поля.

## `alternates` заменяется целиком, а не по полям

Проверено живым прогоном (aboi, 2026-09-02): страница, задавшая только `alternates.canonical`,
теряет унаследованный `hreflang` — `link[rel=alternate]` в разметке не остаётся вовсе.

Для одноязычного сайта это безразлично. Но при включении второй локали `languages` придётся
проставлять на **каждой** странице со своим canonical — из корневого layout он туда молча не
приедет, и обнаружится это только внешним аудитом.

## Где искать у себя

Три типовые группы страниц без собственной `metadata`, потому что их «никто не видит»:

- формы авторизации (`sign-in`, `sign-up`, `sign-out`, `forgot-password`, `verify-email`);
- админка;
- личный кабинет.

В aboi таких оказалось 24 из ~50 маршрутов. `Disallow` в `robots.txt` от этого не спасает: он
запрещает **обход**, а не индексацию — страница попадает в индекс по внешней ссылке даже без
единого визита робота, и тогда её унаследованный canonical начинает работать.

Лечится одним `metadata` на группу — в `layout.tsx` роут-группы, а не правкой каждой страницы:

```ts
// app/[locale]/admin/layout.tsx
export const metadata: Metadata = {
  title: { default: 'Админка', template: '%s | Админка' },
  ...PRIVATE_PAGE_METADATA,
}
```

## Ловушка рядом: `'use client'`-страница не может экспортировать `metadata` вовсе

Страницы авторизации обычно целиком клиентские — и тогда `export const metadata` на том же файле
невозможен в принципе, а не просто забыт. Штатное лечение — серверная обёртка `page.tsx` +
`page.client.tsx`
([nextjs-client-page-metadata-wrapper](/.claude/docs/nextjs-client-page-metadata-wrapper.md)).

⚠️ После разнесения клиентский компонент, читающий `useSearchParams()`, требует `<Suspense>` в
серверной обёртке — пока страница была клиентской целиком, этого требования не возникало, и
сборка падает уже после рефакторинга, а не до него.

## Как проверить

Только живым прогоном: собрать список маршрутов и снять `<link rel="canonical">`,
`link[rel=alternate]`, `meta[name=robots]` и `document.title` с каждого. Греп по исходникам даёт
ложноотрицательный результат по построению — проблема именно в **отсутствии** кода.
