# Better Auth `emailOTP.sendVerificationOTP`: сбой отправки не пробрасывается наружу

⚠️ Плагин `emailOTP` не даёт вызывающему коду узнать
об ошибке канала — `auth.api.sendVerificationOTP(...)` отвечает `{ success: true }` даже если сама
функция отправки письма бросила исключение или просто не смогла достучаться до SMTP/провайдера.

Сверка установленного кода 2026-10-12: `runInBackgroundOrAwait` в
`better-auth/dist/context/create-context.mjs` по умолчанию **ждёт** callback, но перехватывает и
логирует исключение. При настроенном `advanced.backgroundTasks.handler` отправка идёт в фоне.
Причина ложного успеха — перехват ошибки, а не обязательно отсутствие ожидания.

## Симптом

Покупатель/пользователь запросил код входа, API вернул успех, страница показывает «письмо
отправлено» — а письмо никогда не приходит, потому что канал отправки был недоступен в момент
вызова. Без собственного логирования это невозможно отличить от «письмо ушло, но не дошло до
ящика».

## Что делать

Логировать (в лог приложения и/или GlitchTip) сам факт сбоя **внутри** реализации
`sendVerificationEmail`/`sendVerificationOTP`, которую передаёт приложение при создании плагина —
не полагаться на то, что ошибка всплывёт наверх сама. Пример места: `sendLoginCode` в приложении,
собирающем письмо кода — оборачивать реальную отправку в `try/catch` и логировать `catch`, прежде
чем возвращать управление в `emailOTP`.

Для пользовательской формы одного логирования недостаточно. В Flora (FL-012) callback отправки
записывает подтверждение успеха в `AsyncLocalStorage`, а серверный сценарий проверяет его после
вызова `sendVerificationOTP`. Контекст изолирован по запросу и хранит также язык письма;
параллельные запросы не смешивают результаты. Код генерирует и проверяет штатный emailOTP,
он не возвращается в браузер. При отсутствии подтверждения форма получает `EMAIL_UNAVAILABLE`.

Этот подход требует ожидания callback: не подключать фоновые задачи к такой форме без замены
подтверждения на отдельный статус доставки. Проверки должны включать настоящий отказ канала,
параллельные отправки с разными локалями и отсутствие ложного сообщения об успехе в UI.

Найдено при работе над Flora, T1.09 (2026-09-27); актуально для любого приложения на
`@letar/auth` (Better Auth), использующего плагин `emailOTP`.
