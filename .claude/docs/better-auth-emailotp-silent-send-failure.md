# Better Auth `emailOTP.sendVerificationOTP`: сбой отправки не пробрасывается наружу

⚠️ Плагин `emailOTP` не ждёт результата `sendVerificationOTP` и не даёт вызывающему коду узнать
об ошибке канала — `auth.api.sendVerificationOTP(...)` отвечает `{ success: true }` даже если сама
функция отправки письма бросила исключение или просто не смогла достучаться до SMTP/провайдера.

## Симптом

Покупатель/пользователь запросил код входа, API вернул успех, страница показывает «письмо
отправлено» — а письмо никогда не приходит, потому что канал отправки был недоступен в момент
вызова. Без собственного логирования это невозможно отличить от «письмо ушло, но не дошло до
ящика».

## Что делать

Логировать (в лог приложения и/или GlitchTip) сам факт сбоя **внутри** реализации
`sendVerificationEmail`/`sendVerificationOTP`, которую передаёт приложение при создании плагина —
не полагаться на то, что ошибка всплывёт наверх сама. Пример места: `sendLoginCode` в приложении,
собирающем письмо кода — оборачивать реальную отправку в `try/catch` и логировать `catch`, прежде
чем возвращать управление в `emailOTP`.

Найдено при работе над Flora, T1.09 (2026-09-27); актуально для любого приложения на
`@letar/auth` (Better Auth), использующего плагин `emailOTP`.
