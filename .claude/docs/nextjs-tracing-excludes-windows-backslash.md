# `outputFileTracingExcludes` молча не работает при сборке под Windows

Исключения из файлового трейсинга (`outputFileTracingExcludes`) не действуют, если `next build`
запущен на Windows. Ошибки нет, предупреждения нет — просто `.next/standalone` получается
на сотни мегабайт (а то и гигабайты) больше, чем на том же коде под linux.

## Механизм

`next/dist/build/collect-build-traces.js` приводит каждый паттерн исключения к абсолютному пути
и матчит его через `picomatch`:

```js
const resolvedGlobs = [...combinedExcludes].map((exclude) => path.join(dir, exclude))
const isMatch = picomatch(resolvedGlobs, { dot: true, contains: true })
combined.forEach((file) => {
  if (isMatch(path.join(pageDir, file))) { combined.delete(file) }
})
```

На Windows `path.join` отдаёт путь с обратными слешами
(`C:\web\letar\apps\domwellbes\private-uploads\**`), а для `picomatch` обратный слеш — **символ
экранирования**, а не разделитель. Паттерн превращается в бессмысленную строку и не совпадает ни
с чем. На linux обе стороны сравнения — обычные posix-пути, и то же исключение работает.

Проверяется за секунды, без пересборки:

```js
// linux → true, windows → false
picomatch(path.join(appDir, './private-uploads/**'), { dot: true, contains: true })(
  path.join(pageDir, relativeFileFromNftJson),
)
```

## Почему это важно знать, а не чинить

Прод-сборка идёт на сервере (linux) — там исключения работают, в образ ничего лишнего не
попадает. **Чинить конфиг не нужно**, и попытка «починить» его переписыванием паттернов вслепую
сделает хуже: на linux сейчас всё совпадает.

Ловушка в другом — в диагностике. Агент, собравший приложение локально под Windows, видит
`.next/standalone` с реальными загрузками клиентов внутри (в `domwellbes` это 16 000 файлов
`private-uploads/`, ~950 МБ) и делает верный по форме, но неверный по сути вывод: «персональные
данные утекают в Docker-образ». На проде этого не происходит.

Обратная ошибка так же вероятна: увидев чистый локальный standalone под linux, решить, что
исключения проверены для всех окружений.

## Как отличить одно от другого

Признак Windows-артефакта — исключаемый каталог попал в standalone **целиком**, вместе со всеми
файлами, при том что в конфиге исключение прописано. Признак настоящего дефекта — каталог попал
при сборке **на linux**, либо попал каталог, которого в `outputFileTracingExcludes` нет вовсе
(тогда причина другая — см.
[nextjs-dynamic-fs-path-tracing](/.claude/docs/nextjs-dynamic-fs-path-tracing.md): динамический
путь в `fs`-вызове трассирует проект целиком).

`apps/domwellbes/scripts/check-standalone-runtime-files.mjs` различает эти два случая по составу
`standalone/node_modules/.bun` (есть ли там `*-linux-*` пакеты): на linux-сборке попадание тома
роняет проверку, на Windows — печатает предупреждение.

## Побочный эффект, с которым придётся жить

Локальная прод-сборка под Windows у приложения с большим `uploads/` будет дольше и тяжелее ровно
на вес этих каталогов. Если мешает — собирать с пустыми/перемещёнными каталогами загрузок, а не
править конфиг.
