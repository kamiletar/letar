# Чтение большого постраничного веб-источника (без SSR)

Задача: прочитать целиком внешний источник на десятки страниц (форумный тред, архив
переписки, каталог) и выдать по нему связный результат. Два ограничения бьют одновременно:

1. **Нет SSR** — контент рисует JS, поэтому `WebFetch`/`fetch_and_index` получают пустой
   каркас. Нужен реальный браузер.
2. **Объём не влезает в контекст** — если тащить сырой текст всех страниц в диалог, середина
   уедет в компакт, и выводы будут делаться по обрывкам того, что уцелело.

Прецедент: 46 страниц phpBB, ~1130 сообщений, 2026-07-30. Схема ниже отработана на нём.

## Конвейер: страница → конспект на диск → следующая

На каждой странице ровно три шага, после которых сырой текст в контексте больше не нужен:

1. `mcp__Claude_Browser__navigate` на URL страницы
2. `mcp__Claude_Browser__get_page_text` — именно текст, **не** `read_page`:
   accessibility-дерево дороже в разы, а для чтения не даёт ничего сверх текста
3. Записать конспект страницы в **отдельный файл** `page-NN.txt` — факты, даты, цитаты,
   а не сырой дамп

В конце синтез собирается **из файлов**, а не из воспоминаний о прочитанном.

### Почему отдельные файлы, а не один растущий

Один накопительный файл пришлось бы дописывать через `Edit` (требует предварительного
`Read` всего файла) или переписывать `Write`-ом целиком — стоимость растёт квадратично к
числу страниц. Отдельные файлы пишутся за один вызов и **переживают компакт**: после
сжатия контекста нужный кусок читается с диска, а не восстанавливается по памяти.

### Пагинация — считать, а не кликать

Определить схему адресов и общее число страниц один раз, дальше идти по формуле. У phpBB
это `viewtopic.php?f=<F>&t=<T>&start=<N>`, где `N` кратно 25 (0, 25, 50, …). Общее число
берётся из «Страница 1 из N» или из счётчика сообщений. Клики по «вперёд» тратят вызов на
страницу и ломаются при потере состояния.

## Где хранить результат

⚠️ **Скратчпад сессии умирает вместе с сессией.** Если результат нужен следующей сессии —
переложить в `.claude/artifacts/<тема>/` (папка в `.gitignore`, между сессиями живёт).
На прецеденте материалы едва не потерялись именно на этом шаге.

Что попадает в git — решать отдельно: конспекты внешних источников часто содержат чужие
персональные данные, и тогда им место только в `.claude/artifacts/`. Приложение может
прямо запрещать хранение таких данных у себя (см. `CLAUDE.md` конкретного приложения).

## Синтез: два документа, а не один

Один документ не обслуживает две разные нужды. Разделять:

- **справка** — таймлайн, факты, цифры, риски, ссылки на источники для перепроверки;
- **пересказ** — связное чтение для человека, который хочет понять историю, а не свериться.

Оба ссылаются на постраничные файлы, чтобы любой факт можно было поднять до первоисточника.

## Грабли

- **Скриншот падает, если панель браузера скрыта у пользователя**: `Screenshot timed out
  after 5s: the Browser pane is not displayed`. Текстовые инструменты при этом работают
  штатно. Своими вызовами это не чинится — попросить показать панель либо обойтись текстом.
- **«Фото прилагается» в тексте ничего не доказывает.** Вложение могло не загрузиться.
  Проверять DOM конкретного элемента через `javascript_tool`, а не глазами по скриншоту:
  ```js
  document.getElementById('pXXXXXXX')?.closest('.post')?.querySelectorAll('img').length
  ```
- **Пропущенную страницу легко не заметить.** В конце пересчитать файлы:
  ```bash
  for i in $(seq -w 1 46); do [ -f "page-$i.txt" ] || echo "ОТСУТСТВУЕТ: page-$i.txt"; done
  ```
  На прецеденте одна страница из 46 всё-таки потерялась и нашлась только этой проверкой.
- **Объём стоит проговорить заранее.** Десятки страниц — это десятки итераций и заметная
  часть сессии. Спросить, нужна ли полнота или хватит выборки, до начала, а не на середине.

## Когда так не надо

Источник в несколько страниц — просто прочитать. Есть API или SSR — брать оттуда:
`mcp__context-mode__fetch_and_index` + `search` дешевле браузера, но на клиентском рендере
бесполезен (см. ограничение №1 выше).
