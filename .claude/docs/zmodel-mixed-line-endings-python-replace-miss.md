# `.zmodel` со смешанными окончаниями строк: замена многострочной подстроки Python-ом промахивается

## Симптом

Скрипт на Python (`s.replace(old, new)`) с многострочным `old`, скопированным из `Read`-вывода
файла `.zmodel`, не находит совпадение — `assert n != s` падает или замена молча не применяется,
хотя в файле визуально та же строка.

## Причина

Файл сохранён со смешанными окончаниями строк: основная часть — CRLF (Windows), но часть строк —
LF (правки другого редактора/агента поверх, `git` не нормализовал при отсутствии `.gitattributes`
для `*.zmodel`). Многострочный литерал `old` в Python-скрипте несёт один вид переноса (обычно LF,
если писался как обычная тройная кавычка) — побайтовое сравнение с CRLF-частью файла не совпадает
даже при визуально идентичном тексте.

Найдено на `schema/finance-money.zmodel` (2026-09-27): при попытке добавить `@meta` в блок модели
Python-замена не находила блок, хотя `grep`/`Read` показывали ожидаемый текст.

## Проверка

```bash
file schema/<файл>.zmodel        # "with very long lines" не говорит про CRLF/LF напрямую
grep -c $'\r' schema/<файл>.zmodel   # >0 и меньше числа строк — смесь
```

## Обход

- Для точечной правки одной-двух строк — **Edit-инструмент**, а не Python-скрипт: он матчит
  ровно тот текст, что вернул `Read`, независимо от переносов строк внутри файла.
- Для программной правки блока — заменять через **регулярку с `?` на перенос строки**
  (`re.sub(r'...\r?\n...', ..., s)`), а не литеральную многострочную подстроку.
- Не нормализовать файл целиком (`\r\n` → `\n` или наоборот) попутно с содержательной правкой —
  это раздувает diff репозитория, не относящийся к задаче; нормализация окончаний строк, если
  нужна, — отдельный коммит.
