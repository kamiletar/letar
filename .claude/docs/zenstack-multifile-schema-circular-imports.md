# ZenStack multi-file schema.zmodel — циклические импорты работают

Проверено 2026-08-24 на реальной схеме `apps/grandslamcup/schema.zmodel` (59
моделей/enum'ов), разбитой на 8 доменных файлов с плотным графом взаимных
импортов (`users.zmodel` ↔ `matches.zmodel` ↔ `teams.zmodel` ↔ `geo.zmodel` и
т.д. — каждый файл импортирует 4-7 остальных). `zenstack generate` (v3.9.2)
отработал без ошибок, число сгенерированных enum/моделей и содержимое
`schema.prisma`/`form-schemas/` совпали с оригиналом (различался только
порядок объявлений — следствие порядка merge файлов, не баг).

Ранее был известный баг [zenstackhq/zenstack#1257](https://github.com/zenstackhq/zenstack/issues/1257)
— `auth()` не резолвился при взаимном импорте `user.zmodel` ↔ `image.zmodel`.
Закрыт в milestone v2.0.0. Наш пин — 3.5, тест гонялся на 3.9.2 — оба выше
фикса, баг не воспроизводится.

Повторно подтверждено 2026-08-24/25 на `apps/animatrona-tracker/schema.zmodel`
(29 моделей/enum'ов, 7 доменных файлов: `enums`/`auth`/`content`/`anime`/
`distribution`/`pinning`/`library`) — тот же результат: генерация идентична
оригиналу, `prisma db push` после разбиения нашёл базу уже в синхроне (drift
отсутствует).

## Ловушки

⚠️ `import` в корневом `schema.zmodel` должен идти **до** блоков
`datasource`/`generator`/`plugin`. Если после — парсер падает с
`Expecting token of type 'EOF' but found 'import'`. Это не про циклы, а про
порядок объявлений в файле — вероятная причина прошлой (незафиксированной)
находки «циклические зависимости не работают».

⚠️ **Импорты не транзитивны.** Файл, использующий голое имя значения enum
(например `MODERATOR`/`ADMIN` в `@@allow(..., auth().role == ADMIN)`), обязан
импортировать файл с этим enum **напрямую** — даже если он уже импортирует
другой файл, который сам импортирует нужный enum. На animatrona-tracker три
domain-файла (`distribution`/`pinning`/`library`) импортировали только
`./auth`/`./anime`, но не `./enums`, хотя ссылались на значения `UserRole`
через `auth().role` — генерация падала с «Could not resolve reference to
ReferenceTarget named 'MODERATOR'», пока в каждый такой файл не добавили
прямой `import "./enums"`. Правило: каждый файл импортирует все файлы, чьи
**объявления** (модели или enum-значения) он упоминает по имени в своём теле
— не полагаться на транзитивность через промежуточный импорт.

Третье независимое подтверждение той же ловушки — `apps/animatrona/schema.zmodel` (56
деклараций, 9 доменных файлов, 2026-08-25): импорт каждого домена только в корневом
`schema.zmodel` дал те же `Could not resolve reference to TypeDeclaration` на кросс-доменных
ссылках (`Anime` ← `File`, `AudioTrack`/`Settings` ← `Episode` и т.д.). Фикс по тому же правилу
выше — каждый доменный файл импортирует все остальные 8, раз граф ссылок плотный и не сводится к
одному-двум enum'ам. После фикса `zenstack generate` (17 enum/39 моделей) и `prisma db push` —
идентичны оригиналу.

## Как тестировали

Изолированный `git worktree` рядом с основным чекаутом (см.
[git.md § Работа рядом с другими агентами](/.claude/rules/git.md) — техника
для тестирования без риска для общего чекаута). Подводный камень: `nx` в
worktree ломается на project-graph (несвязанная проблема с `@letar/forms-core`
в `vitest.config.ts` шести библиотек) — обходится прямым вызовом бинарника
`node_modules/.bin/zenstack generate` из `cwd` приложения, минуя Nx. Второй
подводный камень: `libs/zenstack-form-plugin/dist/` — build output, не
коммитится, в свежем worktree отсутствует и даёт непонятную Windows ESM
ошибку («Received protocol 'c:'») при попытке загрузить плагин по
относительному пути — фикс: скопировать уже собранный `dist/` из живого
чекаута (read-only переиспользование артефакта).
