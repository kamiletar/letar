# Next.js 16 — авто-генерируемый `AGENTS.md`

## Что это

Начиная с Next.js 16, `next dev` при запуске сам создаёт в корне приложения `AGENTS.md` (и
однострочный `CLAUDE.md` с импортом `@AGENTS.md`, если реального `CLAUDE.md` там ещё нет). Логика
— `node_modules/next/dist/server/lib/generate-agent-files.js`. Файл адресован ИИ-агентам:
предупреждает, что конвенции Next.js в этой версии могут расходиться с обучающими данными модели,
и отсылает к докам внутри `node_modules/next/dist/docs/`.

`AGENTS.md` **пересоздаётся при каждом запуске `next dev`** — если удалить его из диффа, он
появится заново как untracked при следующем `nx dev`.

## Решение: `AGENTS.md` — не коммитить, `CLAUDE.md` — коммитить как обычно

Только `apps/*/AGENTS.md` добавлен в корневой `.gitignore`. Причины:

- Содержимое одинаковое/шаблонное для каждого приложения — раздувает репо без пользы.
- Пересоздаётся каждый dev-запуск — постоянный шум в `git status`, если коммитить.
- Это не проектная документация, а инструкция для агента от самого Next.js.

`CLAUDE.md` в `.gitignore` **не добавляем** — в репо уже есть конвенция `apps/<app>/CLAUDE.md` для
**реальной** ручной документации приложения (см. `animatrona`, `animatrona-mobile`, `aprel8008`),
и она не должна прятаться от git. Если `next dev` создал в приложении только стаб `@AGENTS.md` —
это обычный untracked-файл: коммитить его как есть (импорт останется рабочим, `AGENTS.md`
пересоздастся при следующем `next dev`) или сразу заменить настоящим содержанием — оба варианта
штатно проходят через git, `.gitignore` тут ни при чём.

Первое приложение, где паттерн замечен, — `mandala` (2026-08-04, первый `next dev` после
обновления до Next.js 16).
