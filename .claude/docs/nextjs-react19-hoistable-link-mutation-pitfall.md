# Next.js 16/React 19: прямая мутация React-управляемого `<link>`/`<meta>` нестабильна

⚠️ Класс ловушки — не «баг конкретной фичи», а общее свойство React 19 в Next.js App Router.

## Симптом

Код держит ссылку на DOM-узел `<link>` (или `<meta>`), отрендеренный Next.js через
`generateMetadata`/файловую конвенцию (`icon.tsx`, `manifest.ts` и т.п.), и напрямую мутирует его
атрибут (`link.href = ...`) или удаляет узел (`link.remove()`) — например, чтобы реализовать
«живую» иконку вкладки (индикатор непрочитанных сообщений, статус таймера) или подменить
`og:image` без полного ре-рендера страницы.

На вид работает. Но на **любом следующем ре-рендере где-либо в дереве приложения** (необязательно
в том же компоненте — это может быть `setState` в совсем другом клиентском компоненте того же
layout, сработавший асинхронный эффект, роутер-переход) React заново сверяет свой внутренний
реестр «hoistable»-ресурсов (Next float API — механизм, которым React 19 хостит `<link>`/`<meta>`/
`<script>` в `<head>` независимо от места объявления в JSX-дереве) с реальным DOM. Не найдя
ожидаемое состояние (изменённый `href` или пропавший узел), React **молча вставляет новую копию**
поверх — не убирая старую и не восстанавливая мутацию. Итог — дублирующиеся узлы в `<head>`,
накапливающиеся при каждом таком «чужом» ре-рендере.

## Как воспроизводится и как проверять

Не воспроизводится рассуждением по dev-серверу — эффект наблюдался именно на прод-сборке
(`next build` + `next start`), в dev картина смазывается Fast Refresh/Strict Mode. Проверять
живым `document.querySelectorAll('link[rel~="icon"]').length` до и после мутации + один
дополнительный ре-рендер (например клик по любому интерактивному элементу того же layout).

## Обход

Не трогать React-управляемые узлы вообще. Завести **свой собственный** узел (`createElement` +
`appendChild`), не связанный с React-деревом, и работать только с ним — добавлять последним в
`<head>`, браузер использует его поверх более ранних `<link rel="icon">` при прочих равных. Тот же
приём используют сторонние библиотеки favicon-бейджей (favico.js и подобные) — они никогда не
переиспользуют существующий `<link>`, только добавляют свой.

На unmount/уходе со страницы — просто убрать свой узел (`remove()`), не пытаться восстановить
исходные атрибуты чужих: раз их никто не трогал, они и так остались как были.

## Где ещё может встретиться

Любая динамическая метадата, для которой соблазнительно переиспользовать существующий тег вместо
добавления нового: счётчики непрочитанных в заголовке вкладки, живой `theme-color` по времени
суток, подмена OG-превью на клиенте без полной перезагрузки. Если реализуешь что-то из этого —
сразу заводи свой узел, не мутируй чужой.
