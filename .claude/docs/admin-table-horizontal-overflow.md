# ⚠️ Таблица админки без `Table.ScrollArea` тянет горизонтальный скролл всей страницы

**Класс бага:** `<Table.Root>` в Chakra v3 сам по себе **не** прокручивается. Таблица шире
экрана раздвигает документ, и горизонтально ездит вся страница — вместе с шапкой, заголовком и
кнопками. На телефоне это выглядит как «вёрстка поехала», а не как «таблица не влезла».

**Почему не ловится обычными проверками:**

- `nx lint`, `nx typecheck:tsgo`, `nx test` — зелёные, разметка формально корректна;
- на десктопе (и в любом скриншоте шире таблицы) проблемы не видно вообще;
- ширина зависит **от данных**, а не только от числа колонок: таблица с пятью колонками может
  быть в порядке на пустой базе и разъезжаться на реальной. Поэтому «проверил на dev — нормально»
  ничего не доказывает.

## Лечение

Обернуть **каждую** таблицу списка, а не только ту, что сегодня разъехалась:

```tsx
<Table.ScrollArea>
  <Table.Root size="sm" variant="outline">
    …
  </Table.Root>
</Table.ScrollArea>
```

`Table.ScrollArea` (экспортируется как `TableScrollArea`) даёт контейнеру `overflow-x: auto` —
прокручивается сама таблица, страница остаётся на месте. Это соответствует общему правилу
монорепо: широкий контент (таблицы, диаграммы, блоки кода) скроллится внутри своего контейнера,
`body` не скроллится горизонтально никогда.

## Рецепт аудита

Прогнать все страницы раздела на ширине 375px и сравнить `document.documentElement.scrollWidth`
с шириной вьюпорта; для не совпавших — перебрать элементы, чей `getBoundingClientRect().right`
вылезает за `clientWidth`. Готовый скрипт — `.claude/artifacts/studio-overflow.mjs`
(Playwright + dev-session, принимает список путей аргументами).

⚠️ **Запускать через PowerShell, не через Bash-тул** — Git Bash на Windows превращает
аргумент `/owner/clients` в `C:/Program Files/Git/owner/clients` (POSIX path conversion), и
скрипт падает на «invalid URL», а не на отсутствии страницы.

## Замер (studio, 2026-09-03)

Из двенадцати страниц владельца разъезжались четыре, и ни одна — незначительно:

| Страница          | `scrollWidth` при экране 375px | Причина                          |
| ----------------- | ------------------------------ | -------------------------------- |
| `/owner/jobs`     | 777px                          | `JobsTable` из `@letar/admin-ui` |
| `/owner/leads`    | 757px                          | колонка «Действия» 249px         |
| `/owner/projects` | 631px                          | восемь колонок                   |
| `/owner/clients`  | 557px                          | семь колонок                     |

Обёрнуты все четырнадцать таблиц приложения плюс `JobsTable` в `@letar/admin-ui` — последняя
чинит тот же баг сразу во всех приложениях, где есть страница задач.

## Соседний симптом, который ищется тем же скриптом

Не всякий горизонтальный скролл — таблица. На `/owner/time` вылезало всего 4px: два кнопки
(«Импорт из Toggl» + «Запись вручную») в `HStack` без `flexWrap`. Лечение другое —
`flexWrap="wrap"` на строке заголовка. Тот же класс ловушки, что у шапки карточки агента,
разобранной в [react-duplicate-responsive-dom](/.claude/docs/react-duplicate-responsive-dom.md)
по соседству: `HStack` не переносит содержимое по умолчанию, и на узком экране его дети просто
выходят за край.
