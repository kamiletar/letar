# Отклик на нажатие у интерактивных поверхностей

⚠️ `_active` с сжатием на 1% — это состояние, которого глазу нет. Формально оно есть, в CSS
видно, в код-ревью проходит; пользователь нажатия не видит.

## Правило

**Интерактивная поверхность отвечает на нажатие той же глубиной, что кнопка сопоставимого
размера в теме этого приложения.**

Кнопка — единственный элемент, у которого отклик на нажатие обычно продуман и уже описан
токенами. Всё остальное, что нажимается (карточка-ссылка, плитка, строка списка, тайл выбора),
должно отвечать так же — иначе интерфейс говорит разными голосами: кнопка проваливается под
пальцем, а карточка рядом молчит.

Практически: открой `recipes/button.ts` своего приложения, посмотри шкалу `_active` по размерам
и возьми значение для размера, ближайшего к твоей поверхности. Карточка — крупная, значит
нижняя часть шкалы (`lg`/`xl`), не базовое значение для `md`.

Число не берётся «на глаз» и не копируется из другого приложения: у приложений разные шкалы
кнопок, и связь «карточка = кнопка того же масштаба» должна пережить будущую правку кнопок.

## Что должно быть в `_active`, кроме масштаба

Одного `transform` мало. Полный набор:

```ts
{
  cursor: 'pointer',
  // Снимает 300ms задержку тапа на мобильных — без неё нажатие «залипает»
  touchAction: 'manipulation',

  // Перечисляем свойства явно: `all` анимирует и то, что меняться не должно
  // (цвет текста, отступы) — смена контента даёт лишнее движение
  transitionProperty: 'border-color, box-shadow, transform',
  transitionDuration: 'fast',
  transitionTimingFunction: 'out',

  _hover: {
    shadow: 'md',
    borderColor: 'fg.muted',
  },

  // Вход быстрый и резкий, обратный ход — по базовому переходу
  _active: {
    borderColor: 'fg.muted',
    shadow: 'none',
    transform: 'scale(0.97)',
    transitionDuration: 'faster',
    transitionTimingFunction: 'in',
  },

  _disabled: {
    cursor: 'not-allowed',
    transform: 'none',
    _hover: { shadow: 'none', borderColor: 'border' },
    _active: { transform: 'none' },
  },

  _motionReduce: {
    transitionDuration: 'fastest',
    _active: { transform: 'none' },
  },
}
```

Разбор по пунктам:

- **Отвечает больше одного канала.** Масштаб + тень + рамка. На тач-устройствах `_hover` не
  срабатывает вообще, поэтому если рамка меняется только на hover — при тапе от неё пользы нет.
  Пусть `_active` тоже подсвечивает рамку: тогда на десктопе это продолжение hover, а на тач —
  единственный сигнал, и он приходит.
- **Вход быстрее выхода.** Нажатие должно догонять палец (~90–100ms), возврат может быть
  спокойнее (базовые ~150–180ms). Одинаковая длительность в обе стороны читается как вязкость.
- **Тень схлопывается, а не растёт.** Поверхность «проваливается» в фон — это то же движение,
  что у физической клавиши.
- **Длительности и easing — токенами**, не литералами. Если в теме приложения нет подходящей
  ступени, заводится токен (`durations`/`easings`), а не пишется `0.09s cubic-bezier(...)`
  в одном месте.
- **`transitionProperty` списком.** `transition: 'all'` — самая частая находка в старом коде:
  вместе с нажатием анимируется смена текста, отступов и цвета контента.
- **`_motionReduce` обязателен.** Масштабирование — как раз то, что убирают по
  `prefers-reduced-motion`.

## Анти-паттерны

| Анти-паттерн                                | Почему плохо                                                                |
| ------------------------------------------- | --------------------------------------------------------------------------- |
| `_active: { transform: 'scale(0.99)' }`     | На поверхности 400px это 4px. Состояние есть, читаемости нет                |
| `transition: 'all 0.15s ease-out'`          | Анимирует смену контента; шорткат ещё и перетирает длинные свойства         |
| Ответ только через `_hover`                 | На тач-устройствах hover не наступает — нажатие не отвечает ничем           |
| Своя обёртка `'@media (hover: hover)'`      | Chakra v3 уже её ставит; см. смежный док — ломает типы в нетронутых строках |
| Литералы `90ms`/`cubic-bezier(...)` в стиле | Расходятся между местами использования, не переживают смену темы            |

## ⚠️ Layer style может быть объявлен и не использоваться

Перед тем как чинить `card.interactive` (или любой другой общий стиль), **проверь, кто его
использует**:

```bash
grep -rn 'layerStyle="card.interactive"' apps/<app>/src
```

Реальный случай (driving-school, 2026-08-19): layer style существовал, был кривой, и
**не использовался ни одним компонентом**. Интерактивные карточки повторяли inline-набор
`_hover={{ ... }} transition="all 0.2s" cursor="pointer"` — восемь дословных копий. Починка
одного layer style не изменила бы ничего: правка выглядела бы сделанной, а нажатие осталось бы
нечитаемым.

Поэтому задача «починить общий стиль» почти всегда состоит из двух частей: починить определение
и **привести к нему фактические места использования**.

## Проверка без браузера

Браузерная проверка `_active` неудобна (состояние живёт доли секунды, `getComputedStyle` врёт
при скрытой панели — см. [verification-pitfalls](/.claude/docs/verification-pitfalls.md)), а
иногда невозможна: dev-сервер приложения может не подниматься по причинам, к правке отношения
не имеющим.

Надёжнее — резолвить стиль прямо через систему темы. Разовый скрипт в корне приложения:

```ts
// probe-tmp.ts — удалить после проверки
import { system } from './src/theme'

console.log(JSON.stringify(system.css({ layerStyle: 'card.interactive' }), null, 2))
```

```bash
bun run probe-tmp.ts
```

На выходе — тот CSS, который реально получит элемент:

```json
{
  "borderColor": "var(--chakra-colors-border)",
  "transitionProperty": "border-color, box-shadow, transform",
  "&:is(:active, [data-active]):not(:disabled, [data-disabled], [data-state=open])": {
    "borderColor": "var(--chakra-colors-fg-muted)",
    "boxShadow": "var(--chakra-shadows-none)",
    "transform": "scale(0.97)",
    "transitionDuration": "var(--chakra-durations-faster)"
  },
  "@media (hover: hover)": {
    "&:is(:hover, [data-hover]):not(:disabled, [data-disabled])": { ... }
  }
}
```

Что этим видно сразу:

- **Нерезолвленный токен остаётся сырой строкой.** Так поймана опечатка `borderColor:
  'border.DEFAULT'` — в выводе она осталась `"border.DEFAULT"` вместо
  `"var(--chakra-colors-border)"`, при том что все соседние цвета резолвились. Ни typecheck, ни
  lint этого не ловят: строка валидна по типам, а в браузере даёт просто ненаступившее
  состояние. **Правило: в выводе не должно остаться ни одного значения без `var(--chakra-…)`,
  кроме заведомо литеральных (`1px`, `scale(0.97)`, `manipulation`).**
- Обёрнут ли `_hover` в `@media (hover: hover)` ровно один раз.
- Реальные селекторы состояний — включая `[data-active]`, по которому состояние удобно
  эмулировать в браузере атрибутом, если проверка всё-таки идёт живьём.

## Каскад: layer style побеждает recipe

Chakra v3 объявляет слои `reset, base, tokens, recipes`, а style-props (в том числе
`layerStyle`) эмитит **вне слоёв**. Нелейерные правила по спецификации CSS выигрывают у любого
слоя, поэтому длинные свойства перехода из layer style перекрывают шорткат вида
`transition: 'all 0.15s ease-out'`, оставшийся в `defineSlotRecipe`.

Проверить порядок слоёв конкретной версии — там же, через систему:

```ts
console.log((system as any).layers)
// { names: [ 'reset', 'base', 'tokens', 'recipes' ], atRule: '@layer reset, base, tokens, recipes;' }
```

Из этого не следует, что старый `transition: 'all'` в recipe можно оставлять: он продолжает
действовать на карточки, которые layer style не используют.

## Почему это правило, а не общий пресет в `libs/`

Паттерн реализован в нескольких приложениях независимо, и попытка вынести его в общую библиотеку
выглядит очевидной. Она неуместна:

- **Совпадает принцип, значения расходятся осмысленно.** Радиусы, тени, семантика рамки и
  наличие подъёма на hover у приложений свои. Параметризовать пришлось бы почти каждое
  значение — в общем пресете остался бы каркас из четырёх строк.
- **Глубина нажатия привязана к шкале кнопок конкретного приложения.** Общая библиотека эту
  связь разорвёт: поправят кнопки — карточка перестанет им соответствовать, и никто этого не
  заметит.
- **Дублирования почти нет.** Внутри приложения после правки остаётся одно определение. Второе
  живёт в другом приложении с другой темой — это не дубль, а два экземпляра паттерна.

Общим делается **правило** (этот документ), а не код.
