## Сетка 914 × 420 мм

ST-054: лист 914 × 420 мм заполнен 27 заготовками (9 × 3), 14 студийных и 13 личных.
ОБЕ стороны печатаются через ручную подачу; сначала выпустить с рулона лист с одной точкой.
Актуальное указание Kami заменяет прежнее сохранение двух рядов ST-053.
На внутреннем PDF тексты и утверждённые декоративные значки: никаких меток, номеров, крестов, линейки и служебных подписей.
Служебные элементы остаются снаружи. Старые комплекты на 18 карточек с этим оборотом не смешивать.

| Параметр                  | Значение, мм   |
| ------------------------- | -------------- |
| Грубая карточка           | 92 × 104       |
| Шаг столбцов / промежуток | 96 / 4         |
| Поля слева и справа       | 27             |
| Верх трёх рядов           | 22 / 136 / 250 |
| Шаг рядов / промежуток    | 114 / 10       |

Наружный лист: `x = 27 + 96 × c`, `y = 22 + 114 × r`, где `c = 0…8`, `r = 0…2`.
Первый ряд студийный, ID S01…S09 слева направо; второй личный, P01…P09.
Третий ряд чередует студийные S10…S14 и личные P10…P13, начиная со студийной.
Внутренний лист: `x = 914 − x_наружный − 92`, тот же y, ID сохраняются только в данных макета.
Слева направо на обороте номера идут S09…S01 и P09…P01.

Центры крестов только наружного листа: R1 (15; 12), R2 (899; 12), R3 (15; 372), R4 (899; 372).
Внутренних крестов нет; совмещение на бумаге проверять относительно заготовок на просвет.
Линейка снаружи y = 372, подпись y = 377, нижние инструкции y = 383; всё выше нижнего поля 400…420.

## Источники и файлы

Корень проекта: `C:/web/letar`. Артефакты: `C:/web/letar/.claude/artifacts/cards/`.
Артефакты игнорируются Git и могут отсутствовать на другой машине. Если их нет, геометрия

- `rakukan.html` — стороны визиток и небольшие пробные листы.

- `rakukan-914-outer.pdf` — первый ручной проход; `rakukan-914-inner.pdf` — второй, теперь 420 мм.
  В комплекте — копии с явным размером: `rakukan-914x420-outer.pdf` / `rakukan-914x420-inner.pdf`.
- `blank-914x420.pdf` — пустая страница без потока содержимого, аннотаций и печатных элементов;
  воспроизводится через `make-blank-sheet.py`, проверяется в `blank-sheet-checks.json`.
- **`feed-914x420-dot.pdf`** — актуальная замена для выпуска листа по просьбе Kami:
  одна чёрная точка 1 px при 600 dpi (0,0423 мм), в (5,08; 5,08) мм от верхнего левого угла.
  `make-blank-sheet.py --dot`, отчёт `feed-dot-checks.json`. Почти пустой лист пока не проверен
  на устройстве; полностью пустой, по наблюдению Kami, похоже, пропускался.
- `rakukan-914-inner-guides.png` и `rakukan-inner-card-guides.png` — экранные схемы зон.
- `PRINT-914-README.md` — инструкция двух проходов; `PRINT-README.md` — небольшие техпробы.
- `roll-layout-checks.json`, `roll-pdf-checks.json`, `roll-text-pdf-checks.json`,
  `roll-qr-checks.json` — результаты проверок.
- `qr-url-test.png` — крупные QR из итогового PDF для проверки камерой с экрана;
  `qr-url-preview.cjs` воспроизводит это изображение из рендера и координат QR.
- `studio-letar-preview.png` — лицо студии из итогового PDF, повёрнуто прямо для просмотра.
- **`rakukan-proba-914x420-27cards.zip`** — актуальный комплект ST-054: лист с точкой, оба PDF 420 мм,
  `PRINT-914-README.md`, проба QR, превью лица, цветовой полоски и полной раскладки.

Макеты открываются локально через браузер: `?roll=outer`, `?roll=inner`,
`?roll=inner&guides=1`. Прямые стороны: `?faces&seal=14`; это превью, а не спуск для печати.

Из корня проекта:

```powershell
node .claude/artifacts/cards/build-color-proof.cjs
node .claude/artifacts/cards/render-roll.cjs
# Python с pypdf; путь к runtime определить в текущем окружении.
python .claude/artifacts/cards/normalize-pdf.py --roll-only
python .claude/artifacts/cards/make-blank-sheet.py
python .claude/artifacts/cards/verify-pdf-text.py
pdftoppm -png -r 150 -singlefile .claude/artifacts/cards/rakukan-914-outer.pdf .claude/artifacts/cards/rakukan-914-outer-render
node .claude/artifacts/cards/check-qrs.cjs --roll
```

Текущий экспорт использует Playwright и установленный Chrome. Скрипт QR использует обычный
детектор ZXing без `PURE_BARCODE`, проверяет адрес из PDF и корректность полного https-URL.
В ST-050 адреса приведены к `https://kami.letar.best/` и `https://studio.letar.best/`:
байтовое кодирование, коррекция M, без заглавного `HTTPS://`. Это не заменяет проверку
открытия сайта камерой телефона. Сохраняй действующие средства экспорта; если меняешь среду,
проверь доступность зависимостей и пути вместо жёсткого копирования чужого runtime.

Текущий QR — 22 × 22 мм с защитным полем по 4 модуля; Byte, коррекция M.
В проверке фиксируй не только совпадение строки, но и её корректность как полного https-URL.
Наблюдение ST-050: сочетание `PURE_BARCODE` и `HybridBinarizer` на 150-dpi рендере нового кода
дало `FormatException`, хотя обычный детектор того же ZXing прочитал все 18 кодов. Поэтому
не используй этот специальный режим как единственный критерий читаемости. Позднее Kami
подтвердил открытие новых QR на Android; носитель не уточнён, iOS и бумажная приёмка остаются ST-038.

У «Ракукан» белый фон без заливок, чёрный текст; пробный красный ST-052 — **`#D63A2B`**,
прежний `#C23A2B` на бумаге темнее желаемого. Новый цвет ещё предстоит выбрать по высохшей пробе.

«сайты и веб-приложения · с 2003 года», 8 pt, базовая линия y = 30 мм.
Личная 神樂, студийная 悅; зафиксированные контуры и обработку краёв не перестраивать ради
технологической правки. Исходные `*-edges-red.svg` в папках `seals/v2/kagura/` и `seals/v2/etsu/`
сохраняют #C23A2B; в карточки подключены производные **`*-edges-print-red.svg`** с #D63A2B.

На наружном листе в отходах y = 358…372 мм — обе печати по 14 мм в цветах
#C23A2B / #D63A2B / #E43D30, подписи с кодами на y = 375 мм. Группы начинаются
на x = 27/127/227 мм; в каждой два рисунка с шагом 22 мм. SVG лежат в `seals/color-proof/`.
Они не пересекают карточки (последний ряд заканчивается на y = 354), кресты и линейку.
`color-proof-checks.json` фиксирует неизменность path; экспорт проверяет размещение в отходах.

У этих SVG видимое пятно занимает 90% холста. Для пятна 14 мм размер холста — `14 / 0,9` мм;
ориентируйся на пятно, не на белый холст. Якорь — правый нижний угол пятна (83; 43) мм,
текущее пятно x = 69…83, y = 29…43 мм. При изменении размера сохраняй поля по 7 мм и снова
проверяй пересечения с текстом. Коэффициент 0,9 относится только к этим исходникам.

У внутреннего `.inner-panel` сейчас верхний padding 0,9 мм: без него метрики заголовка
Literata выходили выше своей текстовой зоны. `Range.getBoundingClientRect()` проверяет
каждую строку относительно зоны, затем `verify-pdf-text.py` независимо сверяет границы
символов в нормализованном PDF. Сравнение с черновиком проверяет, что ручные переносы
не поменяли слова. После изменения шрифта или кегля эти проверки повторять.
