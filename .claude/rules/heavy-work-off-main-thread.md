# Тяжёлые операции — в отдельном потоке, не в основном

> Правило без `paths:` намеренно: тяжёлую операцию пишут в server action, роуте, кроне, либе,
> Electron-main или клиентском компоненте, то есть где угодно. Path-scoped правило в момент
> создания нового файла не подгружается (см. шапку [security.md](/.claude/rules/security.md)).
> Решение владельца, 2026-09-23.

**Основной поток только координирует и ждёт ввод-вывод.** Синхронная работа процессора дольше
~50 мс уходит в отдельный поток или процесс. Какой поток считается основным:

- **сервер (Next.js, Fastify)** — event loop Node. Прод-приложение обычно работает как один
  процесс: пока он считает, стоят запросы всех пользователей, а не только того, кто нажал кнопку;
- **браузер** — UI-поток: страница не реагирует на клики и скролл;
- **Electron main** — замирают все окна приложения.

## Что считать тяжёлым

- рендер PDF (`@react-pdf/renderer`, `pdfkit`);
- IFC, геометрия, glTF, триангуляция;
- разбор и генерация больших XLSX/CSV/ZIP, JSON на мегабайты;
- обработка изображений на JS. `sharp` сюда не входит: он уже работает в пуле потоков libuv;
- синхронная криптография (`scryptSync`, `pbkdf2Sync`) и хеширование больших буферов;
- расчёты по большим наборам данных в цикле (пересчёт графиков, смет, раскрой).

**Не тяжёлое:** ожидание БД, сети, файлов. Асинхронный ввод-вывод основной поток не блокирует,
выносить его в воркер бессмысленно.

## Куда выносить

| Где код             | Куда                                                                                                                            |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Сервер, в запросе   | пул `worker_threads` фиксированного размера (например `piscina`), не воркер на каждый запрос                                    |
| Сервер, можно позже | фоновая задача. ⚠️ `@letar/jobs` исполняет задачу **в том же процессе**: тяжёлый обработчик задачи тоже выносится в пул воркеров |
| Браузер             | Web Worker (для графики — `OffscreenCanvas`)                                                                                    |
| Electron main       | `utilityProcess` или `worker_threads`, не в main                                                                                |

Граница потока — сериализуемые данные, не функции и не JSX. Бинарный результат возвращается как
transferable (`ArrayBuffer`/`Uint8Array`), без копирования.

## ⚠️ Ловушки

- **Сборка Next.js.** Файл воркера и его ассеты (шрифты, `.wasm`) должны попасть в standalone:
  `new Worker(new URL('./x.worker.ts', import.meta.url))`, проверка по
  [prod-build-runtime-diagnosis-ladder](/.claude/docs/prod-build-runtime-diagnosis-ladder.md)
  до контейнера, не только в `next dev`. Смежное —
  [nextjs-standalone-tracing](/.claude/docs/nextjs-standalone-tracing.md).
- **Electron под `file://`** Worker не создаётся вообще —
  [electron-app-protocol](/.claude/docs/electron-app-protocol.md).
- **Размер пула** считать от реальных ядер хоста, а не от `os.cpus()`: на сервере ядра делят
  десятки контейнеров.

## Сначала замер

Не выносить наугад: сервер — `monitorEventLoopDelay()` из `node:perf_hooks` и `performance.now()`
вокруг операции; браузер — long tasks (>50 мс) во вкладке Performance или `PerformanceObserver`
с типом `longtask`. Операция на единицы миллисекунд остаётся в основном потоке.

**Известный долг:** рендер PDF в потоке запроса — в `libs/contract-generator` и в двух приватных
приложениях. Постановка перевода на общий пул — в приватном плане первого потребителя.
