# DomWellbes - Воркфлоу разработки

## Инициализация

1. **Сразу стартуй таймер** — `time_start({ app: "domwellbes", description: "изучение плана и постановка задачи" })`.
   Не жди, пока прояснится задача — таймер обновляется через `time_switch`, когда направление
   работы становится понятным (см. «Учёт времени» ниже)
2. Прочитай `.claude/rules/nextjs-apps.md` для общих правил Next.js
3. ⚠️ **Точка входа — [`apps/domwellbes/PLAN_INDEX.md`](../../apps/domwellbes/PLAN_INDEX.md), не
   `PLAN.md` напрямую.** Планы приложения разрезаны на части (`PLAN_SHOP*`, `ROADMAP*` и т.д.),
   `PLAN_INDEX.md` — карта, «первый час нового исполнителя» и текущая ⭐ Задача №1, которая
   меняется по ходу работы и может расходиться с тем, что видно из одного `PLAN.md`. Прочитай его
   целиком, следуя порядку внутри файла (там же — обязательные `PLAN_SHOP.md §0` и `§0.5`), прежде
   чем читать `PLAN.md` или выбирать задачу самостоятельно

## Регистрация в Agent Mail

Фиксированное имя агента: `domwellbes-dev`. Общий шаблон вызова `macro_start_session` —
см. `.claude/rules/app-workflow.md`. Модель — `claude-opus-5` (не дефолтная `claude-sonnet-5`).
Токен — в `agent_fixed_names_tokens.md`.

⛔ **Если токен не подошёл — НЕ пытайся зарегистрировать `domwellbes-dev` повторно тем же именем.**
Это типичный симптом одновременного старта нескольких `/domwellbes`: сервер проверяет владение
именем check-then-act, не атомарно, и retry тем же именем — ровно тот механизм, который уводит имя
в чужие руки (разбор — `.claude/rules/agent-mail.md`). Вместо этого сразу `create_agent_identity`
без `name_hint` (гарантированно уникальное имя), запиши в `agent_fixed_names_tokens.md` как рабочее
имя «пока domwellbes-dev занята» и работай под ним. Если и это не вариант — работай без координации
(конфликтов по коду нет — приватный submodule правит только его же агент).

## Работа с submodule

Приложение — **приватный git submodule**. Перед редактированием:

```bash
cd apps/domwellbes && git checkout main && git pull origin main
# ... правки ...
git add . && git commit -m "feat(domwellbes): описание" && git push origin main
cd ../.. && git add apps/domwellbes && git commit -m "chore: bump domwellbes submodule"
```

⚠️ Без `git checkout main` правки уйдут в detached HEAD и потеряются. Подробности:
`.claude/rules/git.md` § «Работа с приватными submodule».

## 152-ФЗ

⚠️ Приложение предполагает формы обратной связи (заявки на строительство). **Любая форма,
собирающая персональные данные, ОБЯЗАНА:**

- Записывать `ConsentLog` через `recordConsent()` из `@letar/consent`
- Содержать **не предотмеченный** чекбокс согласия со ссылкой на `/privacy`
- Cookie-баннер с opt-in

Перед публичным запуском — чеклист `.claude/docs/personal-data.md`. Оператор ПДн для этого
домена на момент создания приложения **не определён** — уточнить у владельца, кто подаёт
уведомление в РКН (студия или заказчик).

## Учёт времени

Проект ведётся для клиента студии по **почасовой оплате**. `studio-time-mcp` уже работает —
таймер стартуется **сразу в шаге 1 «Инициализации»**, не после уточнения задачи.

```
time_start({ app: "domwellbes", description: "<что делаешь, языком клиента>" })
```

⚠️ В `description` — только предмет работы по этому проекту. Никаких других клиентов, чужих
проектов и внутренней кухни: описание видит заказчик.

Как только направление действий стало понятным (задача выбрана, план предложен и согласован) —
обнови title таймера через `time_switch` на конкретное описание этой задачи. Не жди
`time_stop`/конца сессии, чтобы дать таймеру осмысленное имя.
