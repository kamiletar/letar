# Обновление документации

Обнови документацию проекта после завершения работы.

## Алгоритм

### 1. Определи контекст

1. Найди `package.json` — определи имя и текущую версию
2. Прочитай `CHANGELOG.md` — найди последнюю версию
3. Прочитай `PLAN.md` — найди выполненные задачи

### 2. Собери информацию об изменениях

1. Посмотри git status/diff для понимания что изменилось
2. Определи категории изменений:
   - Added — новые файлы/функции
   - Changed — модификации существующего
   - Fixed — исправления багов
   - Improved — улучшения

### 3. Обнови CHANGELOG.md

1. Определи тип версии:
   - MAJOR: breaking changes
   - MINOR: новые функции
   - PATCH: исправления
2. Добавь секцию с новой версией
3. Опиши изменения в формате Keep a Changelog

### 4. Обнови PLAN.md (если нужно)

1. Отметь выполненные задачи как ✅
2. Добавь новые задачи если появились

### 5. Bump версию в package.json

1. Обнови версию согласно semver
2. Синхронизируй с CHANGELOG

## Формат CHANGELOG

```markdown
## [X.Y.Z] - YYYY-MM-DD

### Название фичи/итерации

**Added:**

- Новый компонент X
- Новая функция Y

**Changed:**

- Обновлён компонент Z

**Fixed:**

- Исправлен баг #123

**Improved:**

- Улучшена производительность X
```

## После завершения

Выведи отчёт:

- Версия: X.Y.Z → A.B.C
- Обновлённые файлы
- Краткое описание изменений
