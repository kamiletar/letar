# Архивация выполненных задач и CHANGELOG

Перенеси выполненные задачи и старые записи CHANGELOG в архивные файлы для экономии контекста.

## Алгоритм

### 1. Найди файлы документации в приложении

```bash
# Структура документации приложения:
apps/<app>/
├── PLAN.md                  # Активный план
├── PLAN_COMPLETED.md        # Архив выполненных задач
├── E2E_PLAN.md              # План E2E тестов (если есть)
├── E2E_PLAN_COMPLETED.md    # Архив E2E (если есть)
├── CHANGELOG.md             # Активный changelog (последние ~20 версий)
└── CHANGELOG_YYYY_MM_DD.md  # Архив старых версий
```

### 2. Обработай PLAN.md

1. Прочитай `PLAN.md`
2. Найди секции с пометкой ✅, [x], "Выполнено", "Completed"
3. Перенеси их в `PLAN_COMPLETED.md`:
   - Добавь дату переноса
   - Сохрани структуру (заголовки, описания)
4. Удали перенесённые секции из `PLAN.md`
5. Оставь только активные/будущие задачи

### 3. Обработай E2E_PLAN.md (если есть)

1. Прочитай `E2E_PLAN.md`
2. Найди выполненные фазы/итерации (✅, "Completed", старые версии)
3. Перенеси в `E2E_PLAN_COMPLETED.md`:
   - История версий (v1.0 - v2.x)
   - Завершённые фазы
   - Исправленные проблемы
4. Оставь в E2E_PLAN.md только:
   - Текущую структуру тестов
   - Активные планы расширения
   - Команды запуска

### 4. Обработай CHANGELOG.md

1. Прочитай `CHANGELOG.md`
2. Посчитай количество версий (секций `## [X.Y.Z]`)
3. Если версий > 20:
   - Определи дату разделения (версии старше 1-2 месяцев)
   - Перенеси старые версии в `CHANGELOG_YYYY_MM_DD.md`
   - Добавь ссылку в конце CHANGELOG.md

**Формат архивного CHANGELOG:**

```markdown
# Changelog (Архив до YYYY-MM-DD)

> Продолжение основного CHANGELOG.md
> Версии: X.Y.Z — A.B.C

## [X.Y.Z] - YYYY-MM-DD

### Название фичи

...
```

**Ссылка в основном CHANGELOG.md:**

```markdown
---

Продолжение в ./CHANGELOG_YYYY_MM_DD.md
```

**Критерии разделения CHANGELOG:**

- Оставлять в основном файле: последние ~20 версий (1-2 месяца)
- Переносить в архив: версии старше 2 месяцев
- Если архив уже существует — добавлять в начало существующего

### 5. Формат архивных файлов PLAN

```markdown
# <App> — Выполненные задачи

> Архив выполненных задач из PLAN.md
> Последнее обновление: YYYY-MM-DD

## Фаза X: Название (дата завершения)

- [x] Задача 1
- [x] Задача 2

---

## Фаза Y: ...
```

### 6. Коммит

После архивации:

```bash
git add apps/<app>/PLAN*.md apps/<app>/E2E_PLAN*.md apps/<app>/CHANGELOG*.md
git commit -m "docs(<app>): архивировать выполненные задачи и старые записи CHANGELOG"
```

## Критерии переноса

### PLAN.md / E2E_PLAN.md

**Переносить:**

- Секции полностью помеченные как ✅
- Фазы где все задачи [x]
- История изменений старше 1 месяца
- Исправленные баги и проблемы

**Оставлять:**

- Текущие активные задачи
- Планы на ближайшее время
- Структуру проекта
- Команды и инструкции

### CHANGELOG.md

**Переносить:**

- Версии старше 1-2 месяцев
- Когда общее количество версий > 20
- Полные секции версий (не разрывать)

**Оставлять:**

- Последние ~20 версий
- Секцию `[Unreleased]`
- Заголовок и описание формата
