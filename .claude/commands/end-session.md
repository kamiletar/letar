Завершай сессию:

1. **Определи контекст работы** — над каким приложением/библиотекой шла сессия
2. **Обнови ПЛАН приложения** (не глобальный `PLAN.md` в корне репо):
   - `apps/<name>/PLAN.md` — отметь выполненные задачи как `[x]`
   - `apps/<name>/PLAN_COMPLETED.md` — добавь итоги сессии с деталями реализации
   - Если работали над несколькими приложениями — обнови каждый
3. **Глобальный `/PLAN.md`** обновляй только если сессия затрагивала кросс-приложенческую работу (auth, libs, инфра, деплой)
4. **Не ретирь фиксированную identity agent-mail** (`<app>-dev`, координаторы вроде
   `deploy-agent-dev`/`forms-coordinator-dev`/`animatrona-coordinator-dev`/`repo-dev`). Она
   персистентная и переиспользуется следующей сессией того же приложения — `retire_agent` на неё
   ничего не даёт (сервер сам ретирит по простою) и только плодит orphan-состояния, из которых
   потом приходится восстанавливать identity вручную (разбор — `PLAN-INFRA.md` §93). Так уже
   устроен `/deploy-agent`: на завершении `deploy-agent-dev` не ретирится,
   только broadcast «ухожу» — бери это за образец. `retire_agent`/`expire_window` вызывай только
   для по-настоящему одноразовой identity этой сессии (auto-generated adjective+noun через
   `create_agent_identity`, relay-имя, заведённое только на разовую задачу) — если такая была.
5. **Останови таймер тайм-трекера studio** — таймер ведётся по всем проектам репозитория, не
   только по клиентским с почасовой оплатой. Вызови `time_stop`, покажи итог сессии по проектам
   (`time_status` перед остановкой) и, если за сессию был задет не один проект,
   проверь, что для каждого переключения был вызван `time_switch` — забытое переключение приводит
   к тому, что время одного проекта записывается на другой. Один `Stop`-хук
   (`.claude/hooks/time-stop-check.js`) эту роль не закрывает: он срабатывает на конец **ответа
   агента**, а не на конец рабочей сессии — нужны оба механизма.
6. **Закоммить изменения** — добавь только файлы текущего приложения и закоммить их:
   ```bash
   git add apps/<name>/
   git commit -m "<type>(<scope>): <описание>"
   ```
   Следуй формату из `.claude/rules/git.md` (feat/fix/refactor/chore/style/docs).
7. **Оглянись на системные решения в монорепо** — просмотри код, к которому прикасалась сессия (и смежный контекст), на предмет:
   - дублирования логики/компонентов/утилит, которые стоит вынести в `libs/` и зашарить через `@letar/*` ([shared-first](/.claude/rules/shared-first.md) при наличии, иначе см. CLAUDE.md)
   - мест, которые пора отDRYть (повторяющиеся паттерны в 3+ местах)
   - разросшихся файлов/функций, которые стоит декомпозировать
   - паттернов, которые уже устоялись в приложении и заслуживают документации в `.claude/docs/`

   Если находки есть — не применяй изменения самостоятельно, а заведи для каждой отдельный чип
   через `spawn_task` (заголовок-глагол, самодостаточный prompt с путями файлов, короткий tldr) —
   так пользователь сможет запустить каждую находку отдельной новой сессией одним кликом. После
   этого кратко перечисли в тексте, что заведено (файл, что не так, что предлагается).
   Если находок нет — прямо напиши, что предложить нечего.

   ⚠️ **Такая находка запускается позже как отдельная новая сессия** — время её выполнения не
   входит в таймер текущей сессии (он уже остановлен к тому моменту). Поэтому в `prompt`
   `spawn_task` включай инструкцию для будущей сессии самой стартовать `time_start` в начале
   своей работы — иначе время на неё нигде не запишется.
8. **Открытые вопросы** — если за сессию остались нерешённые вопросы (недосказанность с
   пользователем, развилка, требующая его решения, недостающая информация) — не оставляй их
   только в чате. Занеси каждый как задачу в `apps/<name>/PLAN.md` (или в глобальный `PLAN.md`,
   если вопрос кросс-приложенческий) с пометкой `[ ] ⚠️ Открытый вопрос: <суть>` и кратким
   контекстом, почему он не решён сейчас. Так вопрос не потеряется между сессиями.
