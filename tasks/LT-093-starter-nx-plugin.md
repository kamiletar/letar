## Что и зачем

Часть [LT-091](LT-091-game-library-starter.md), решения — [LT-092](LT-092-starter-design.md).
Выделить переносимую основу, которая используется Letar и внешними проектами из одного источника.

## Приёмка

- [ ] Есть собираемый npm-артефакт плагина с явными exports и публичными зависимостями.
- [ ] Генераторы приложения/библиотеки работают вне Letar по контракту LT-092.
- [ ] Общие конфиги подключаются короткими пользовательскими обёртками.
- [ ] Нет неразрешимых workspace-ссылок, приватных путей или требований к сервисам Letar.
- [ ] Существующие генераторы Letar сохраняют поведение на проверенных сценариях.

## План

1. Прочитать принятые решения LT-092 и код существующих new-app/new-lib, описать точный scope
   файлов нового пакета и адаптеров. Зарезервировать пути через Agent Mail.
2. Создать Nx-библиотеку штатным генератором. Настроить сборку, экспорты, включаемые файлы,
   schema.json/generators.json и devkit-зависимости согласно выбранной версии Nx.
3. Выделить переносимую генерацию app/lib и разрешение настроек.
   Пути, scope пакетов, package manager, имена и env получать из опций/контекста проекта.
4. Сохранить специфичные для Letar операции в адаптере: приватные submodule, учёт времени,
   домены и деплой не должны становиться обязательными свойствами общего плагина.
   Не менять генераторы других приложений без необходимости.
5. Вынести общие lint/format/typecheck/test-настройки в публичные точки подключения;
   оставить возможность пользовательских расширений. Форматтер — dprint.
6. Подготовить pack-артефакт и тестовый внешний workspace без доступа к исходникам монорепо.
   Убедиться, что runtime читает файлы из установленного пакета, а не из исходного checkout.
7. Подключить общий код к минимальному существующему сценарию Letar и сравнить результат
   генерации до/после, особенно tsconfig, импорты, порты и состав зависимостей.
8. Обновить README/CHANGELOG затронутых пакетов и версии по правилам Letar.

## Проверки и границы изменений

- Владение: плагин и необходимые точечные адаптеры libs/generators; точные пути из LT-092.
- Тесты: генерация app/lib, отказ при совпадении имени, корректный внешний scope и отсутствие
  внутренних интеграций; проверка разрешения exports и файлов из tarball.
- Запустить scoped format, lint, typecheck и профильные тесты через Nx; проверить diff генерации.
- Не публиковать пакет и не запускать массовое перегенерирование существующих приложений.
- Если размер превышает M, до start разделить задачу через tasks new.
