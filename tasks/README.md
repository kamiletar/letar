# Очередь задач монорепо Letar

Проект `letar`, префикс `LT`. Здесь задачи самого монорепо: инфраструктура, общие библиотеки,
инструменты, а также очередь перевода остальных проектов на этот же формат.

## Как пользоваться

Задача — один файл `tasks/LT-NNN-slug.md` со статусом в шапке; закрытые лежат в `tasks/done/ГГГГ-ММ/`.
Списка в файле нет, его собирает команда:

```bash
bun scripts/tasks.mjs next letar
```

Дальше: `show LT-NNN`, `start LT-NNN --owner <имя>`, `note`, `done --summary`. Все команды и
формат: [tasks-per-file](/.claude/docs/tasks-per-file.md).

## Текущий фокус

- **LT-001** — этот инструмент и пилот на корне (в работе).
- **LT-031** — следующий шаг: перевести domwellbes (префикс `DW`), отдельной сессией.
- **LT-002** — сборка на s1, релиз на s2 (прежний «следующий старт» из `PLAN.md`).

Что ждёт владельца: `bun scripts/tasks.mjs waiting letar --on kami`.

## Справка (замороженные планы)

- `PLAN.md` — план единой авторизации и 152-ФЗ. Источник для задач `--area auth` и `compliance`.
- `docs/plans/PLAN-INFRA-1…7.md` — инфраструктурный журнал по `§NN` до октября 2026.
  Целиком не читать: `grep -n '^## §'` и `Read` с `offset` на секции из поля `source` задачи.
- Приватное (журнал сквозных сессий, реквизиты, 152-ФЗ) — `.claude/private/`.

Замороженные файлы не растут: хук не пропустит рост больше чем на 5 строк.

## Три правила

1. Репозиторий публичный. По приватным приложениям в задаче только имя и типовой чек-лист:
   без цифр, доменов и деталей бизнес-логики.
2. Одна задача — одна сессия. Размер `L` режется на части до `start`.
3. Нашёл что-то по ходу — `tasks new`, а не абзац в плане. Журнал и итог пиши в файл задачи.
