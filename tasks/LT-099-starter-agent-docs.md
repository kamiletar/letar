## Что и зачем

Часть [LT-091](LT-091-game-library-starter.md), решения — [LT-092](LT-092-starter-design.md).
Подготовить инструкции, с которыми новичок и его агент понимают проект и могут безопасно его развивать.

## Приёмка

- [ ] README доводит чистый checkout до рабочего CRUD без знания Letar.
- [ ] Описаны модели, app → lib и путь schema.zmodel → форма → сервер → БД.
- [ ] Общие правила агента отделены от пользовательских и привязаны к версии стартера.
- [ ] Указаны реальные команды и границы generated-файлов; нет внутренних обязательных сервисов.
- [ ] Есть учебное расширение модели и необязательные рецепты продвинутых форм.
- [ ] Инструкции проверены на сгенерированном проекте, а не только прочитаны.

## План

1. Составить карту файлов и команд итогового workspace: создание, БД, seed, dev, generate,
   migration, format/lint/typecheck/test, build и обновление.
2. Написать короткий первый маршрут: запуск → регистрация/вход → поиск игры →
   добавление версии → изменение статуса → оценка.
   Указать prerequisites, значения env и типовые локальные ошибки.
3. Описать предметную модель и права без неявных допущений: игра против платформенной версии,
   справочники, личная запись и проверка параметров одной версии.
4. Подготовить AGENTS.md и управляемую общую часть по LT-092.
   Явно описать расположение пользовательских дополнений, generated-файлов и правила проверки.
   Убедиться, что выбранные агенты действительно читают/подхватывают общую часть.
5. Извлечь переносимые инструкции Letar: архитектура Nx, shared-first, формы/валидация,
   политики, миграции, форматирование, scope-коммиты и работа с env.
   Не копировать приватные сведения, токены, личную память Kami, серверные пути и требования
   к Agent Mail/таймеру/deploy-agent как обязательные для внешнего проекта.
6. Добавить учебный пример расширения: новое поле платформенной версии, метаданные,
   generate, миграция, форма, фильтр и проверка результата.
   По отдельности объяснить AutoFields, явную форму, справочник и повторяемую группу.
7. Добавить короткие рецепты rich text / файлов / многошаговых форм как дальнейшие возможности,
   без включения дополнительных инфраструктурных зависимостей в базовый запуск.
8. Проверить команды и задание на свежем workspace; зафиксировать результат walkthrough.
   Указать правила локальных/production-БД и отсутствие универсального db:push для production.

## Проверки и границы изменений

- Владение: README/agent-файлы/навыки/рецепты/шаблоны документации стартера.
- Не менять глобальные инструкции Letar и личные файлы Kami.
- Проверить ссылки, команды, отсутствие секретов и согласованность с версией пакета.
- dprint по своим файлам; новые .claude/docs индексировать по правилам Letar.
- Передать LT-100 точный перечень управляемых агентских файлов и пользовательских дополнений.
