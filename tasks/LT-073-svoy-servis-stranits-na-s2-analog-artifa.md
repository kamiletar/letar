## Что и зачем

Страницы с планами, схемами и замерами сейчас публикуются на claude.ai (Artifact). Нужен свой аналог на s2: приватные страницы по ссылке, вход через Ключницу, публикация одной командой из сессии, без заявки на деплой на каждое обновление. Сам сервис ставится один раз через `deploy-agent-dev`.

## Приёмка

- [ ] `page_publish` в MCP `letar` загружает html (и файлы рядом), возвращает адрес и номер версии
- [ ] Повторная публикация в тот же slug создаёт новую версию, старые доступны
- [ ] Без входа через Ключницу страница не открывается; публичной её можно пометить явно
- [ ] Страница открывается в тёмной и светлой теме и на телефоне, внешние скрипты по CSP только с cdnjs
- [ ] Страницы из claude.ai (плана tasks-per-file) перенесены как первая проверка

## План

Решения владельца: сервер s2; доступ через Ключницу; публикация инструментом MCP `letar`.

1. **Сервис `pages`** (Fastify, как media-server, без БД): каталог `/data/pages/<slug>/<версия>/…`, файл `current` указывает на актуальную версию. `GET /p/<slug>/…` отдаёт файлы статикой, `POST /api/pages/<slug>` принимает архив/файлы по токену публикации.
2. **Вход.** Окно в Ключницу по OIDC: сессионный cookie, проверка email из белого списка владельца. Для публичных страниц флаг `public` в `meta.json`. Опираться на готовый клиент OIDC из приложений монорепо, не писать новый.
3. **MCP.** Инструмент `page_publish({ slug, filePath, files?, title, description, public? })` и `page_list`, `page_delete` в `.claude/mcp/letar.ts`; токен публикации в env MCP, не в репозитории (`.env.local`, генератор токена из `security.md`).
4. **Заголовки.** CSP как у Artifact: скрипты только с cdnjs/jsdelivr, стили с Google Fonts, остальное inline; `X-Frame-Options`, `Referrer-Policy`.
5. **Установка один раз:** compose, домен, запись в `S2_APPS`, redirect URI в Ключнице, заявка `deploy-agent-dev`. Дальше публикации идут по HTTPS без деплоя.
6. **Перенос** страницы tasks-per-file и страниц планов приложений (notebook и др.), ссылки в доках заменить.

Риски: вход через Ключницу на staging у notebook уже ломался (NB-001), поэтому сначала проверить вход на тестовой странице; страницы делят s2 с боевыми приложениями, нужен лимит размера загрузки (например 5 МБ на версию).
