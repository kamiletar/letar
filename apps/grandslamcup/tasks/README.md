# Очередь задач Grandslamcup

Проект `grandslamcup`, префикс `GS`. Сайт турнира поэтических слэмов (Кубок Большого Слэма), по
решению владельца разворачивается в платформу фестов (`resentiment`); стихи и кабинет поэта
переезжают в приложение-преемник (`apps/mugcup`). Next.js, живой скоринг матча, админка, кабинет
тренера, Telegram-интеграция.

## Как пользоваться

Задача — один файл `tasks/GS-NNN-slug.md` со статусом в шапке; закрытые лежат в
`tasks/done/ГГГГ-ММ/`. Список собирает команда из корня монорепо:

```bash
bun scripts/tasks.mjs next grandslamcup
```

Дальше: `show GS-NNN`, `start GS-NNN --owner grandslamcup-dev`, `note`, `done --summary`. Формат и
все команды: [tasks-per-file](/.claude/docs/tasks-per-file.md).

## Справка (замороженные планы)

Перенесено только живое: «Открытые вопросы», незакрытые пункты фаз 5 и 6, открытое из
`PLAN_TESTING.md`. Фазы 9–15 ТЗ не начаты и сведены в идеи (GS-016…GS-022), нарезать при старте.
Остальное остаётся справкой и расти не может:

- `PLAN.md` (265 КБ), `PLAN_COMPLETED.md`, `PLAN_TESTING.md` — журнал и архивы. Целиком не читать:
  `grep -n '^## '` и `Read` с `offset`. План пивота («ОПЕРАЦИЯ РАЗВОРОТ», R.0–R.14) и наследное ТЗ
  КБС (разделы 1–12) лежат там же как справка.
- `CHANGELOG*.md` целиком не читать: нужная запись ищется `grep`.
- Веха стартовала, а задач по ней нет — режь её на задачи через `tasks new … --source`.

## Правила

1. Нет ответа в планах и решение не твоё — `tasks new … --status blocked --blocked-by "kami: …"`
   и бери следующую задачу.
2. Не делать без слова владельца: `git push`, bump SHA submodule в letar, `bun install` и
   `bun.lock`, deploy-request, работа с прод-базой и секретами на сервере, правки в чужих `libs/*`.
3. Данные организаторов (составы, блокировки игроков, правила) вносятся только с их слова и
   формулировок; имена игроков и команд в задачи не писать, ссылка на пункт `PLAN.md`.
4. Один пункт — один коммит в submodule `main`: файлы поимённо, версия в `package.json`, запись в
   `CHANGELOG.md`, перед коммитом `format`, `lint`, `typecheck:tsgo`. Новая политика доступа —
   `auth-policy-validator` до коммита.
