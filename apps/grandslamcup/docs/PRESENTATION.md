## О платформе

**Кубок Большого Слэма (КБС)** — это веб-приложение для проведения командных поэтических турниров в формате poetry-clash. Платформа полностью покрывает жизненный цикл турнира: от заявок и составов до live-судейства на площадке и публикации итогов.

- **Города-участники.** Санкт-Петербург (Round-Robin) — действующий пилот. Москва — масштабирование на Swiss System + Double Elimination.
- **Тип приложения.** PWA (Progressive Web App) — работает офлайн на смартфонах судей и счетоводов, добавляется на главный экран как обычное приложение.
- **Доступ.** Открытый для зрителей, единый вход (SSO «Ключница») для поэтов, тренеров, организаторов и админов.
- **Аудитория.** Поэты, тренеры, жюри, ведущие, скореры (счетоводы), организаторы города, администраторы платформы, зрители на сайте и в зале.

## Турнирная логика

### Иерархия турнирных сущностей

```mermaid
graph TD
  Season -->|1:N| League
  Season -->|1:N| Stage[Stage<br/>GROUP / PLAYOFF_UPPER / LOWER / GRAND_FINAL]
  Stage -->|1:N| Round
  Round -->|1:N| Tour
  Tour -->|1:N| Match
  Match -->|1:N| Lineup[MatchLineup]
  Match -->|1:N| Performance[PlayerPerformance]
  Performance -->|1:N| JudgeVote
  Performance -->|1:N| AudienceVote
```

### Форматы турниров

| Формат                 | Город              | Структура                                                 |
| ---------------------- | ------------------ | --------------------------------------------------------- |
| **Round-Robin**        | СПб                | Каждый с каждым 1–2 раза, очки 1 / 0.5 / 0                |
| **Swiss System**       | Москва (групповой) | Пары по W-L записи, проверка повторов, авто-bye           |
| **Double Elimination** | Москва (плей-офф)  | Upper Bracket + Lower Bracket + Grand Final, на 16 команд |

### Расчёт оценки выступления

```mermaid
flowchart LR
  J1[Судья 1: 4] --> SORT
  J2[Судья 2: 5] --> SORT
  J3[Судья 3: 3] --> SORT
  J4[Судья 4: 4] --> SORT
  J5[Судья 5: 5] --> SORT
  SORT[Сортировка<br/>3, 4, 4, 5, 5] --> DROP[Отбросить min и max<br/>остаётся 4, 4, 5]
  DROP --> SUM[Сумма = 13<br/>textAdjusted]
  SUM --> TOTAL[totalScore = text + delivery<br/>максимум 30]
```

- 5 судей оценивают **текст** и **подачу** независимо по шкале 1–5.
- Отбрасываются максимум и минимум — остаются 3 средние оценки → сумма.
- Текст (макс 15) + Подача (макс 15) = **totalScore до 30 баллов**.
- Сумма выступлений всех поэтов команды = счёт команды.
- При ничьей: либо 0.5:0.5 (если разрешено сезоном), либо **tiebreak** — 11-я пара поэтов.

### Антифрод

- **Cookie-fingerprint судей** за 30 дней — предупреждение скореру при повторе устройства.
- **Уникальный ключ голоса** на уровне БД: одно устройство = один голос за одно выступление.
- **Зрительское голосование** анонимное (sessionToken), физически не влияет на результат — параллельная статистика «народного жюри».

### Самоорганизация товарищеских матчей: биржа счетоводов и ведущих (Фаза 15)

Сейчас для проведения товарищеского матча нужен администратор — он вручную назначает счетовода и ведущего. **Фаза 15** убирает этот bottleneck: тренер проходит весь путь самостоятельно, система автоматически рассылает токены.

```mermaid
flowchart LR
  A[Тренер А<br/>создаёт вызов] --> B[Тренер Б<br/>принимает]
  B --> PUB[Платформа публикует<br/>в «бирже волонтёров»]
  PUB -->|Push / Telegram| V1[Счетовод<br/>откликается]
  PUB -->|Push / Telegram| V2[Ведущий<br/>откликается]
  V1 --> CONF[Тренер А<br/>подтверждает]
  V2 --> CONF
  CONF --> READY[Матч создаётся автоматически]
  READY --> TOKENS[Токены → Счетоводу и Ведущему по email]
  READY --> NOTIF[Уведомления → всем участникам]
```

**Биржа волонтёров** — страница `/volunteer` со списком зарегистрированных счетоводов и ведущих по городам:

| Поле      | Описание                                   |
| --------- | ------------------------------------------ |
| Рейтинг ★ | Средняя оценка тренеров после матчей (1–5) |
| Роль      | 📊 Счетовод / 🎙️ Ведущий / оба              |
| Статус    | «Принимаю запросы» / «Занят»               |
| История   | Сколько матчей провёл                      |

**После матча** оба тренера оценивают работу счетовода и ведущего — рейтинг накапливается, лучшие волонтёры получают признание.

- **Полная автономность** — администратор не требуется на протяжении всего флоу.
- **Уведомления на каждом шаге** — Push + email + Telegram для всех участников.
- **Авто-создание матча** при подтверждении волонтёров: токены рассылаются мгновенно.
- Срок разработки: **~2–3 недели**.

### Планирование тренировок команды (Фаза 10)

Тренер собирает команду между матчами без созвонов в Telegram:

```mermaid
flowchart LR
  P1[Игрок 1<br/>пн 19-22, ср 20-23] --> AVAIL[Команда:<br/>14 дней × 24 часа<br/>доступности]
  P2[Игрок 2<br/>вт 18-21, чт 19-22] --> AVAIL
  P3[Игрок 3<br/>пн 19-23, пт весь день] --> AVAIL
  P4[Игрок 4<br/>...] --> AVAIL
  AVAIL --> HEAT[Тепловая карта<br/>у тренера]
  AVAIL --> ALGO[Алгоритм<br/>timeline-sweep]
  ALGO --> TOP5[Топ-5 слотов<br/>6+ игроков, 19-21]
  HEAT --> COACH[Тренер выбирает]
  TOP5 --> COACH
  COACH --> SESSION[Тренировка<br/>дата + место]
  SESSION --> NOTIF[Push / Email / Telegram<br/>всем игрокам]
  NOTIF --> RSVP[RSVP: иду / может быть / не приду]
```

- **Игрок** размечает свободные слоты на 14 дней вперёд: календарная сетка дни × часы, drag-to-select.
- **Тренер** видит тепловую карту доступности всей команды + **топ-5 предложенных системой** оптимальных слотов: «6 игроков свободны 21 мая с 19:00 до 22:00 — Денис, Светлана, Александра, Ваня, Иван, Даша».
- **Алгоритм** учитывает: количество свободных игроков (приоритет №1), близость к «уютному» времени 19–21 (приоритет №2), отдалённость от матчей (приоритет №3).
- **Один клик** на предложении → тренировка создана + приглашения разосланы push / email / Telegram.
- **RSVP**: каждый отвечает «иду / может быть / не приду», тренер видит реальный состав.
- **Напоминания** автоматически за 24 ч и 2 ч до тренировки. Тренировки экспортируются в iCal-календарь вместе с матчами.
- Срок разработки: **~2 недели**.

### Видео матчей и каналы поэтов / команд (Фаза 11)

Раскрывает зрелищность турнира — каждое выступление можно пересмотреть, поделиться, разобрать.

- **Видео с матчей**: организатор после игры вставляет URL с YouTube / VK Video / RuTube / Telegram / Vimeo — система автоматически парсит обложку, длительность, делает responsive embed.
- **Отметка поэтов**: админ или тренер размечает таймкодами, какой поэт где выступает. На профиле поэта видео появляется автоматически с прямой ссылкой на нужный фрагмент.
- **Личный канал поэта**: на своей странице каждый поэт сам публикует видео — выступления с других площадок, клипы, демо. Раздел «Видео» на профиле.
- **Канал команды**: тренер ведёт командный канал — «лучшее за сезон», бэкстейдж, промо.
- **Короткие клипы** (≤ 60 сек) можно загружать прямо на платформу — для «хайлайтов» матча без зависимости от YouTube.
- **SEO-бонус**: структурированные данные `VideoObject` + `og:video` дают красивые превью при шеринге в Telegram / VK / WhatsApp.
- **Модерация**: жалобы на видео, whitelist провайдеров (нельзя вставить произвольную ссылку), rate-limit от спама.
- Срок разработки: **~2–3 недели** (без native upload — он опционально).

### Telegram Mini App — КБС прямо внутри Telegram (Фаза 14)

Telegram Mini App (TMA) — это веб-приложение, встроенное в мессенджер. Пользователь не скачивает ничего: бот отправляет сообщение в канал с кнопкой «Открыть» — и поэт / зритель / судья попадает в полноценный интерфейс платформы, не выходя из Telegram.

```mermaid

  BTN --> TMA[Telegram Mini App<br/>grandslamcup.letar.best/tma/]
  TMA --> LIVE[Live-счёт матча<br/>обновляется в реальном времени]
  TMA --> VOTE[Зрительское голосование<br/>без регистрации]
  TMA --> STAND[Турнирная таблица]
  TMA --> SCHED[Расписание + .ics в календарь]
  TMA --> PROF[Профиль поэта + стихи]
  TMA --> JURY[Жюри по deep link<br/>вместо QR-кода]
  TMA -->|авторизация| AUTH[Telegram initData<br/>без пароля / Ключницы]
```

**Ключевые экраны TMA:**

| Экран                     | URL                    | Кто открывает                        |
| ------------------------- | ---------------------- | ------------------------------------ |
| Live-счёт матча           | `/tma/match/[id]`      | Зрители из канала по кнопке в анонсе |
| Зрительское голосование   | `/tma/match/[id]/vote` | Зрители во время матча               |

| Профиль поэта             | `/tma/player/[slug]`   | Все                                  |
| Вход для жюри (deep link) | `/tma/jury?token=xxx`  | Судьи — QR заменяется ссылкой в боте |

**Преимущества перед PWA и Android:**

- **Нулевой порог входа** — Telegram уже установлен у 100% участников.
- **Авторизация одним тапом** — `initData.user` приходит автоматически, пользователь ничего не вводит.
- **Haptic Feedback** — вибрация при голосовании и подтверждении действий.
- **Нативный back gesture** — кнопка «Назад» в шапке Telegram.
- **Тёмная/светлая тема** — TMA автоматически подхватывает системную тему Telegram.
- **Срок реализации MVP: 1–2 недели** (существующий PWA оборачивается в TMA-layout, добавляется route-группа `/tma/`).

### Android-приложение для поэтов, тренеров и организаторов (Фаза 12)

PWA удобна зрителю в зале, но активные роли — поэт, тренер, организатор — заслуживают полноценного нативного опыта: надёжные push, иконка на экране, системные камера и галерея, биометрический вход, deep links из Telegram.

```mermaid
graph LR
  WEB[Существующий PWA<br/>grandslamcup.letar.best] --> WRAP[Capacitor 6 wrapper]
  WRAP --> NATIVE[Android-приложение]
  NATIVE --> P[Поэт]
  NATIVE --> C[Тренер]
  NATIVE --> O[Организатор]
  NATIVE --> PUSH[FCM push<br/>надёжно через MIUI / EMUI]
  NATIVE --> CAM[Камера и галерея<br/>системный picker]
  NATIVE --> BIO[Biometric login<br/>отпечаток / Face]
  NATIVE --> DEEP[Deep links<br/>матч из Telegram → в приложение]
  NATIVE -->|выпуск| RUSTORE[RuStore — главный канал РФ]
  NATIVE -->|выпуск| PLAY[Google Play]
  NATIVE -->|выпуск| APK[APK с сайта]
```

- **Ядро приложения** — три кита, без которых не выпускаем:
  1. **Полноценный чат** на уровне Telegram (свайп для reply, long-press меню, реакции, цитирование, inline-превью ссылок, pinned, поиск, прикрепление фото с камеры). Все 10 типов чатов Фазы 9 работают нативно.
  2. **Push-уведомления о сообщениях и упоминаниях** — отдельный высокоприоритетный канал FCM `mentions`, badge с числом непрочитанных на иконке приложения, **inline-ответ из шторки** без открытия приложения (Android Direct Reply).
  3. **Уведомления о тренировках и матчах** — приглашение на тренировку с кнопками «Иду / Может быть / Не приду» прямо в шторке, напоминания за 24 ч и 2 ч до тренировки/матча с открытием места в Яндекс.Картах одним тапом.
- **16 категорий push-уведомлений** разнесены по FCM Notification Channels: пользователь в системных настройках Android выключает шумные категории (новости города), оставляя важные (упоминания, тренировки, матчи). Тихие часы 22:00–08:00 настраиваются в приложении.
- **Стратегия:** Capacitor 6 оборачивает существующий PWA — 95% UI работает «as is», добавляется доступ к нативным API через 14 плагинов (push, камера, файлы, биометрия, share-sheet, vibration, secure storage, app badge, keep-awake).
- **Аутентификация:** Better Auth → токен в Android Keystore → biometric prompt при повторном запуске.
- **Push через FCM** (Firebase Cloud Messaging) — расширение существующей модели `PushSubscription` полями `fcmToken` и `platform`. Те же события (новое сообщение, приглашение на тренировку, скоро матч) приходят надёжно даже на Xiaomi / Huawei, где web-push нестабилен.
- **Deep links** через App Links: ссылка на матч из Telegram открывается прямо в приложении.
- **Не делаем сразу нативное**: Capacitor закрывает 90% потребностей за 10% усилий. Если экран жюри потребует абсолютной отзывчивости — React Native + Expo вторым этапом.
- **iOS — отдельная фаза** (Apple Developer Account, Mac для билда). Делаем после Android, по фидбеку.
- **Срок разработки этапа 1 (MVP с Capacitor): 2–3 недели.**
