# Driving School Platform

Веб-приложение (PWA с оффлайн-режимом) для управления расписанием занятий в школах вождения. Платформа связывает учеников и инструкторов, автоматизирует планирование занятий, ведёт учёт посещаемости и финансов.

> **Текущая версия:** 0.183.0
> **Технологический стек:** Next.js 16, React 19, Chakra UI v3, PostgreSQL, Prisma, ZenStack

## 🚀 Быстрый старт

### Разработка

```bash
# Запуск dev-сервера
nx dev driving-school  # порт 3003

# База данных
nx zenstack:generate driving-school  # Генерация Prisma + Zod схем
nx db:push driving-school            # Синхронизация БД (dev)
nx db:migrate driving-school         # Создание миграции (prod)
nx db:studio driving-school          # Prisma Studio

# Тестирование
nx lint driving-school               # Линтинг
nx typecheck:tsgo driving-school     # Проверка типов (tsgo - 9x быстрее!) ⚡
nx typecheck driving-school          # Проверка типов (tsc - обычная скорость)
nx format driving-school             # Форматирование
nx test driving-school               # Unit-тесты
nx e2e driving-school-e2e            # E2E тесты (Playwright)
```

### Деплой

```bash
# Деплой приложения
./deploy-affected.sh --app driving-school

# Dry run (показать что будет задеплоено)
./deploy-affected.sh --dry-run

# Принудительная пересборка
./deploy-affected.sh --app driving-school --skip-cache
```

> **Важно:** Перед деплоем ознакомьтесь с [DEPLOY.md](./DEPLOY.md)

## 📖 Основные разделы ТЗ

### Роли пользователей

**Платформенные роли:**

- USER — базовый пользователь
- FREELANCE_INSTRUCTOR — независимый инструктор
- MODERATOR — модератор контента
- OWNER — владелец платформы

**Школьные роли:**

- ADMIN — полный доступ к школе
- MANAGER — управление без настроек
- INSTRUCTOR — инструктор практики
- THEORY_INSTRUCTOR — преподаватель теории
- STUDENT — ученик школы

### Ключевые функции

- ✅ Аутентификация (email + OAuth: Google, Яндекс, VK)
- ✅ Профили учеников и инструкторов
- ✅ Связь ученик-инструктор (приглашения, баланс)
- ✅ Расписание и автогенерация слотов
- ✅ Управление занятиями (CRUD, статусы, отмена, перенос)
- ✅ Финансы (предоплата, штрафы, баланс)
- ✅ Автошколы (роли, учебные группы, теория, экзамены)
- ✅ Уведомления (Push, Email, Telegram)
- ✅ PWA и оффлайн-режим
- ✅ Чаты (приватные, групповые, real-time)
- ✅ Рейтинги и отзывы
- ✅ Поиск инструкторов и школ
- ✅ Public API v1 для интеграций
- ✅ Импорт/Экспорт данных (Excel, CSV)

## 💡 Методология разработки

Проект следует принципам:

- **TDD (Test-Driven Development)** — сначала тест, потом код
- **Планирование в PLAN.md** — вся функциональность документируется
- **Автоматические коммиты** — после успешного завершения задачи
- **Семантическое версионирование** — patch/minor/major по характеру изменений
- **Линтинг и типизация** — обязательная проверка перед коммитом

### 📝 Обновление документации при изменениях

При внесении изменений в проект необходимо обновлять соответствующие файлы документации:

| Изменение                    | Файлы для обновления                                                                       |
| ---------------------------- | ------------------------------------------------------------------------------------------ |
| **Новая фича**               | `PLAN.md`, `PLAN_COMPLETED.md`, `CHANGELOG.md`, `PLAN_TESTING.md`, `package.json` (версия) |
| **Баг-фикс**                 | `CHANGELOG.md`, `package.json` (patch версия)                                              |
| **Изменения БД**             | `docs/DATABASE.md`, `schema.zmodel`                                                        |
| **Новые тесты**              | `PLAN_TESTING.md`, `docs/testing/PHASE*.md`                                                |
| **Изменения безопасности**   | `docs/SECURITY.md`                                                                         |
| **Изменения деплоя**         | `DEPLOY.md`                                                                                |
| **Изменения API**            | `docs/` (если есть API docs), страница `/developers`                                       |
| **Общие улучшения/прогресс** | `README.md` (секция прогресса, статистика тестов)                                          |

**Порядок обновления при завершении фичи:**

1. Обновить `package.json` — версия (semver)
2. Обновить `PLAN.md` — отметить фичу как выполненную (✅ + версия)
3. **Перенести детали фичи в `PLAN_COMPLETED.md`** — сразу после завершения, чтобы PLAN.md оставался компактным
4. Обновить `CHANGELOG.md` — добавить запись о релизе
5. Обновить другие файлы по необходимости
