## Текущее состояние

Базовый Public API (только чтение) реализован в Фазе 8 (v0.78.0-v0.82.0):

- OpenAPI спецификация генерируется автоматически из schema.zmodel

## Реализованный Public API

**Технология:** ZenStack REST handler с автогенерацией из schema.zmodel

**Формат ответов:** JSON:API стандарт

**Доступные модели:**

- `school` — информация о школе
- `schoolMembership` — участники школы
- `schoolLocation` — локации школы

**Пример запроса:**

```bash
curl -X GET "https://api.example.com/api/v1/school" \
  -H "X-API-Key: your-api-key"
```

**Документация:**

- `/api-docs` — Swagger UI (интерактивная документация)
- `/developers` — руководство с примерами

## Сплитскрин-режим (чат + интерфейс)

**Описание:**

Режим одновременного отображения чата с инструктором/учеником и основного интерфейса приложения на одном экране. Позволяет общаться и работать с расписанием/занятиями без переключения между вкладками.

**Сценарии использования:**

1. **Инструктор** обсуждает с учеником время занятия → сразу видит своё расписание
2. **Ученик** задаёт вопрос инструктору → параллельно смотрит свой прогресс
3. **Администратор** решает вопрос с инструктором → видит загрузку и финансы
4. **Менеджер** координирует несколько учеников → быстро переключается между чатами

**Варианты реализации:**

| Вариант                     | Описание                                                    | Плюсы                        | Минусы                         |
| --------------------------- | ----------------------------------------------------------- | ---------------------------- | ------------------------------ |
| **Боковая панель**          | Чат как выдвижная панель справа/слева                       | Простая реализация           | Сужает основной контент        |
| **Нижняя панель**           | Чат внизу экрана (как в IDE)                                | Не мешает боковой навигации  | Занимает вертикальное место    |
| **Ресайзабл сплит**         | Разделитель между чатом и контентом с возможностью изменить | Гибкость, пользователь решит | Сложнее реализация             |
| **Плавающее окно (PiP)**    | Чат как перетаскиваемое окно поверх контента                | Максимум гибкости            | Может перекрывать важное       |
| **Вкладки внутри страницы** | Переключение чат/контент без ухода со страницы              | Не сужает экран              | Нет одновременного отображения |

**Рекомендуемый подход: Ресайзабл боковая панель**

- Панель чата справа, по умолчанию 350px
- Пользователь может изменять ширину (200-600px)
- Кнопка сворачивания до иконки
- Сохранение размера в localStorage
- На мобильных — полноэкранный режим с кнопкой "назад"

**Технические детали:**

- **Компонент:** `<SplitScreenLayout>` с children и chatPanel
- **Состояние:** Zustand store для открытости и ширины панели
- **Ресайз:** CSS `resize: horizontal` или библиотека react-resizable-panels
- **Responsive:** На экранах < 1024px автоматически сворачивать в overlay
- **Анимация:** Framer Motion для плавного открытия/закрытия
- **Роутинг:** Сохранять активный чат в URL query param (?chat=userId)

**Интеграция с существующим чатом:**

- Текущий чат (`/messages/*`) переиспользуется как содержимое панели
- Добавить режим "embedded" без header/sidebar
- Синхронизация непрочитанных сообщений
- Push-уведомления при свёрнутом чате

**Примерная структура:**

```tsx
// Использование в layout
<SplitScreenLayout chatEnabled={true} defaultChatWidth={350} minChatWidth={200} maxChatWidth={600}>
  {children}
</SplitScreenLayout>
```

**Этапы реализации:**

| Этап | Задачи                                                 | Оценка |
| ---- | ------------------------------------------------------ | ------ |
| 1    | SplitScreenLayout компонент с фиксированной шириной    | 4 часа |
| 2    | Ресайзабл разделитель с сохранением в localStorage     | 2 часа |
| 3    | Адаптация существующего чата для embedded режима       | 4 часа |
| 4    | Responsive поведение (мобильный overlay)               | 3 часа |
| 5    | Интеграция с роутингом (query params, глубокие ссылки) | 2 часа |
| 6    | Индикатор непрочитанных и уведомления                  | 2 часа |
| 7    | Тестирование и полировка UX                            | 3 часа |

**Всего:** ~20 часов

## Webhooks

**События для уведомлений:**

- `lesson.created` — создано новое занятие
- `lesson.confirmed` — занятие подтверждено
- `lesson.cancelled` — занятие отменено
- `lesson.completed` — занятие завершено
- `student.added` — добавлен новый ученик
- `payment.received` — получена оплата

**Формат:**

```json
{
  "event": "lesson.created",
  "timestamp": "2025-01-15T10:30:00Z",
  "data": {
    "lessonId": "...",
    "studentId": "...",
    "instructorId": "...",
    "startTime": "..."
  }
}
```

**Настройки:**

- URL для отправки (настраивается школой)
- Выбор событий для подписки
- Retry policy при ошибках
- Подпись запросов (HMAC)

## Интеграция с календарями

**Поддерживаемые сервисы:**

- **Google Calendar** — OAuth 2.0, Calendar API v3
- **Яндекс.Календарь** — OAuth 2.0, CalDAV
- **Apple Calendar (iCloud)** — CalDAV
- **Microsoft Outlook** — Microsoft Graph API
- **Любой CalDAV** — универсальный протокол (Nextcloud, Synology и др.)

**Функциональность:**

| Функция                 | Описание                                                   |
| ----------------------- | ---------------------------------------------------------- |
| **Экспорт занятий**     | Занятия автоматически появляются в личном календаре        |
| **Двусторонняя синхр.** | Изменения в календаре отражаются в платформе (опционально) |
| **Блокировка слотов**   | События из личного календаря блокируют слоты инструктора   |
| **Напоминания**         | Использование нативных напоминаний календаря               |
| **Цветовая маркировка** | Разные цвета для типов занятий (практика, теория, экзамен) |
| **Описание события**    | Имя ученика, тип занятия, адрес, контакты                  |

**Сценарии использования:**

1. **Инструктор** подключает Google Calendar → все занятия автоматически появляются в его календаре
2. **Инструктор** добавляет личное событие (врач, встреча) → слот автоматически блокируется
3. **Ученик** подключает Яндекс.Календарь → видит свои занятия среди других дел
4. **Школа** создаёт общий календарь для всех инструкторов → менеджер видит загрузку

**Настройки пользователя:**

- Выбор календаря для синхронизации (рабочий / личный)
- Какие события синхронизировать (занятия / экзамены / теория)
- Направление синхронизации (только экспорт / двусторонняя)
- Время напоминания (за 1 час / за 1 день / без напоминания)
- Блокировка слотов по событиям из календаря (вкл/выкл)

**Технические детали:**

- OAuth 2.0 для авторизации (без хранения паролей)
- Refresh tokens для фоновой синхронизации
- Webhook/push уведомления от календарей (где поддерживается)
- Периодическая синхронизация как fallback (каждые 15 мин)
- Обработка конфликтов при двусторонней синхронизации
- iCal (.ics) экспорт как универсальный fallback
