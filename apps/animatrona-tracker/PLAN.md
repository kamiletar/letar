## Фаза N: Шеринг, тайм-коды, настройка дорожек и комментарии с привязкой ко времени (план, без реализации)

Источник: пожелание Ками — кнопка «Поделиться», ссылки с привязкой ко времени, настройки дорожек
(аудио/субтитры) сохраняемые в ссылке, комментарии к франшизе/аниме/серии с текстовыми
тайм-кодами (`6:46`), возможность вставить текущее время просмотра одной кнопкой, и встроенный
чат по образцу `driving-school` (Socket.IO + SSE, см. ниже).

### N.1 Кнопка «Поделиться» + ссылки с привязкой ко времени и настройками дорожек

**Идея:** одна ссылка полностью восстанавливает состояние просмотра — эпизод, момент времени,
выбранная аудиодорожка/субтитры.

- [x] **Формат URL** — `?t=<секунды>&audio=<index>&sub=<index|off>` на
      `/watch/[animeId]/[episode]`. Разбор на сервере в `page.tsx` (валидация индексов против
      `manifest.audioTracks`/`subtitleTracks`), переопределяет и восстановленный из БД прогресс,
      и дефолты манифеста.
- [x] **Кнопка «Поделиться» в плеере** — иконка в `headerRightSlot` (`tracker-video-player.tsx`),
      рядом с `TrackSelector`. Строит URL из `videoRef.currentTime`/`audioTrackIndex`/
      `subtitleTrackIndex`, вызывает `useShare()` (готовый хук из `@letar/ui`, не писали заново) —
      `navigator.share` с фоллбэком на копирование + toast «Ссылка скопирована». Без модалки.
- [x] **Share для аниме/франшизы** — `ShareAnimeButton` (`_components/share-anime-button.tsx`,
      общий для `anime/[id]` и `anime/franchise/[key]`) — канонический URL без тайм-кода, тот же
      `useShare()`.
- [ ] **OG-превью для расшаренных ссылок** — не сделано, опционально, не блокирует MVP.
- [x] **Web Share API на мобильных** — закрыто самим `useShare()` (уже был в `@letar/ui`, с
      фоллбэком на `useCopyToClipboard`) — не пришлось выносить в libs, готовое переиспользовано.

### N.2 Настройка дорожек — сохранение выбора

- [x] **Персистентность выбора дорожек.** Точный ручной выбор (`audioTrackIndex`/
      `subtitleTrackIndex`, не только грубый RU/EN `trackMode`, который уже персистился раньше)
      теперь сохраняется в `localStorage` per-anime (`animatrona-tracks-<animeId>`) при каждом
      изменении через `TrackSelector`. Подставляется на клиенте только когда сервер отдал чистые
      дефолты манифеста (нет прогресса по этому эпизоду и нет `&audio=`/`&sub=` в ссылке) —
      закрывает переход между эпизодами одного аниме без сброса на дефолт манифеста. Явная ссылка
      и уже существующий per-episode прогресс в БД (см. ниже) — приоритетнее localStorage.
- [x] **UI настроек дорожек** — сверено: `TrackSelector` уже существовал, дублирования нет,
      реально не хватало только формата URL и localStorage-фолбэка (как и предполагал сам пункт).
      Также обнаружено при сверке: точная позиция (`audioTrackIndex`/`subtitleTrackIndex`) уже
      сохранялась в БД per-episode через `/api/watch-progress` каждые 5с (`use-watch-progress.ts`)
      и восстанавливалась в `page.tsx` — это работало и раньше для залогиненных пользователей на
      уже начатом эпизоде; новый localStorage-слой закрывает то, что БД не покрывала (первый заход
      на новый эпизод без прогресса, анонимные пользователи).

### N.3 Комментарии с тайм-кодами — модель и три уровня (франшиза / аниме / серия)

**Текущее состояние:** `AnimeComment` в `schema.zmodel` привязан только к `animeId`, без эпизода
и без тайм-кода. `comments-section.tsx`/`comment-card.tsx` уже есть на `anime/[id]`.

- [ ] **Расширить модель вместо трёх новых** — добавить в `AnimeComment` опциональные поля
      `episodeId String?` (relation на `AnimeEpisode`, для комментария к конкретной серии) и
      `timestampSec Int?` (для тайм-кода в этой серии). Комментарий без `episodeId` — комментарий к
      аниме целиком (текущее поведение не ломается). Комментарий к франшизе — отдельный вопрос:
      либо новая модель `FranchiseComment` с `franchiseKey String`, либо (проще) считать
      франшизу-уровень отдельной лёгкой сущностью без БД (не откладывать в MVP, обсудить при
      реализации какой вариант нужнее Ками).
- [ ] **Парсинг тайм-кода в тексте** — при вводе комментария пользователь пишет свободный текст
      вида `6:46` или `1:02:15` — парсер (`mm:ss` / `h:mm:ss`) находит такие паттерны в тексте и
      на рендере оборачивает их в кликабельную ссылку `<button>`, которая делает `seek()` в плеере
      (если комментарий открыт на странице с плеером) либо ведёт на `/watch/.../?t=406` (если
      комментарий открыт на странице аниме без плеера — переход на серию с нужным временем).
      Реализация — небольшая regex-утилита + компонент `TimestampLink`, можно вынести в `libs/`
      (переиспользуемо для описаний, чата — везде, где может быть тайм-код в тексте).
- [ ] **Кнопка «Вставить текущее время» в форме комментария** — когда форма комментария/чата
      открыта на странице с активным плеером (серия), рядом с textarea — кнопка (иконка часов),
      которая на клик вставляет в курсор текст `6:46` (текущее `video.currentTime`, форматированное
      `mm:ss`/`h:mm:ss`). Плеер и форма должны быть в общем React-контексте (аналог
      `active-chat-context.tsx` из driving-school) — `active-player-context.tsx` с текущим временем
      и методом `seekTo(sec)`, который читают и форма комментария, и (в будущем) чат.
- [ ] **UI списка комментариев с тайм-кодами** — на странице серии (`watch/[animeId]/[episode]`)
      под плеером или в боковой панели — комментарии именно к этой серии, отсортированные, с явным
      бейджем времени (не просто текст «6:46» — визуальный чип типа YouTube «▶ 6:46» перед текстом).
      На странице аниме (`anime/[id]`, `comments-section.tsx`) — общие комментарии + опционально
      фильтр «показывать по сериям».
- [ ] **Права на комментарии к сериям** — те же ZenStack policies, что у `AnimeComment` сейчас
      (`check(anime)` для read, `auth() != null` для create) — расширить `check` под `episodeId`
      если модель эпизода имеет свои policies видимости.

### N.4 Встроенный чат — по образцу driving-school

**Референс изучен:** `apps/driving-school` — модели `Chat/ChatParticipant/ChatMessage/
MessageReaction` с ZenStack access policies вместо ручной модерации; реалтайм гибрид —
**Socket.IO** (`src/app/api/socket/route.ts`, Redis-адаптер для multi-instance) для самих
сообщений + **SSE** (`src/lib/sse/chat-sse-manager.ts`, singleton через `globalThis`, переживает
HMR) только для лёгких уведомлений (счётчик непрочитанных), не гружая сокетом весь сайт. История
сообщений — SSR + Server Actions (`_actions/chat-messages.action.ts`), live-обновления — сокеты.
Клиентский хук `use-chat-socket.ts` держит буфер `MAX_MESSAGES=200`.

- [ ] **Определить масштаб чата для tracker** — в отличие от driving-school (личные/групповые
      чаты по ролям), здесь нужен, вероятнее всего, **чат по аниме/серии** (публичный, как
      комментарии, но live) — ближе к «чат трансляции», чем к личным сообщениям. Уточнить у Ками при
      реализации: чат = live-обсуждение под конкретной серией (открыт пока страница открыта, без
      истории после закрытия?) или полноценная история как у комментариев, но с realtime-доставкой
      новых сообщений участникам, которые сейчас на странице.
- [ ] **Минимальный вариант (MVP)** — не тащить Socket.IO+Redis сразу: чат к серии/аниме как
      `AnimeComment` с `createdAt`, но с **поллингом через TanStack Query** (`refetchInterval`,
      как уже принято для списков в этом приложении — см. `data-fetching.md`) вместо сокетов.
      Взвесить при реализации: если нагрузка/отзывчивость не требуют «печатает…»/мгновенной
      доставки, поллинг проще эксплуатировать (без Redis-адаптера, без отдельного порта в
      Docker) и уже есть паттерн в приложении.
- [ ] **Полный вариант (если MVP не хватит)** — Socket.IO с Redis-адаптером аналогично
      driving-school: `api/socket/route.ts`, `lib/socket/chat-handler.ts`, клиентский хук с буфером
      сообщений. Требует нового порта в `docker-compose.production.yml` (по аналогии с тем, как это
      настроено в driving-school) и записи в `.claude/rules/deploy-coordination.md`-стиле проверки
      перед деплоем.
- [ ] **Тайм-коды в чате** — переиспользовать `TimestampLink`-утилиту из N.3 — сообщения в чате
      парсятся так же, кликабельные тайм-коды работают одинаково в чате и в комментариях.
- [ ] **Права/модерация чата** — те же роли, что в остальном приложении (ADMIN/модератор может
      удалять сообщения), без отдельной системы ролей чата как в driving-school (там `isAdmin` на
      участнике нужен из-за приватных групповых чатов — здесь чат публичный к аниме/серии, роль
      берётся из существующего `User.role`).

**Открытые вопросы для обсуждения с Ками перед реализацией** (мои рекомендации даны в сессии
2026-09-08 (3), но владельцем не подтверждены — вопросы остаются открытыми):

1. Комментарии к франшизе — новая модель или пропустить (франшиза уже показывает связанные
   аниме, комментарии могут остаться только на уровне аниме/серии)?
   **Рекомендация:** пропустить. Франшиза — производная сущность, комментарии естественно живут
   на аниме/серии.
2. Чат — реалтайм (Socket.IO) с самого начала или сперва поллинг, апгрейд по факту нагрузки?
   **Рекомендация:** поллинг через TanStack Query. Socket.IO + Redis-адаптер ради публичного чата
   под серией — несоразмерная эксплуатационная цена (отдельный порт в compose, Redis-адаптер).
3. Формат тайм-кода в URL — `?t=406` (секунды) или `?t=6m46s` (читаемый)?
   **Снят:** `?t=<секунды>` уже реализован в N.1, менять нечего.
4. `ShareButton`/`useShare` — сразу в `libs/@letar/ui` (shared-first) или сначала в
   animatrona-tracker, вынос потом?
   **Снят:** `useShare()` уже был в `@letar/ui`, переиспользован как есть.

## Dev-аккаунт

Для локальной разработки создан seed с dev-пользователем:

```
Email: admin@dev.local
Пароль: admin123
Роль: ADMIN
```

Запуск: `nx db:seed animatrona-tracker`

⚠️ `.env.local` должен содержать `BETTER_AUTH_URL=http://localhost:3009` (порт dev-сервера, не production 3010).

## Команды разработки

```bash
# Запуск
nx dev animatrona-tracker

# База данных
nx zenstack:generate animatrona-tracker
nx db:push animatrona-tracker
nx db:seed animatrona-tracker
nx db:studio animatrona-tracker

# Проверки
nx format animatrona-tracker
nx lint animatrona-tracker
nx typecheck:tsgo animatrona-tracker

# Сборка
nx build animatrona-tracker
```
