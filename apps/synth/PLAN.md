# PLAN — synth (музыкальная студия)

> Это **не типовое CRUD-приложение монорепо**: нет ZenStack/Postgres в v1, ядро — Web Audio / Web MIDI / синтез звука. Стандартный шаблон `/create:new-app` применяем выборочно (см. «Отличия от шаблона монорепо»).

## 🎯 Видение

Личная браузерная студия для **синтеза, исполнения и записи звука**, построенная вокруг аппаратной клавиатуры **M-VAVE SMK-37 PRO** (встроенный FM-движок класса DX7). Плюс **публичная open-source витрина** — но публикация **поштучно и только по желанию автора** (см. «Приватность и публикация»).

Пользователь — телесный, потоковый музыкант: фаер-перформер (пои), хочет виджеить. Поэтому студия — не только про звук, но и про **живой перформанс**: реактивные визуалы выносятся в полноэкранный **VJ-режим** (Фаза 5), реактивный к звуку и MIDI. Принцип всего интерфейса: простота и поток, никакой сложности «платного VJ-софта». Дальняя цель — **единое сольное выступление**: свои биты + стихи в микрофон + визуалы на проекторе + танец с поями (огонь). Все части проектируем так, чтобы однажды срослись в один live.

Двойная роль ассистента: **архитектор** (технически) + **музыкальный ментор** (ненавязчиво учит языку музыки через метафоры и ощущения, ведёт дневник успехов `JOURNAL.md`).

**Профиль пользователя:** веб/нэйтив-архитектор, тончайший слух и вкус; цвет в звуке **не видит**, но остро чувствует «правду/фальшь» звука и **слышит пространство/объём** («сцену»); **не знает нот и сольфеджио** — работает на слух и на глаз. Эстетика: «живой» звук Nord (virtual analog) + стеклянные тембры DX-7 (FM). Подробности — в `claude.md`.

## 🎨 Эстетика и философия

Концептуальный север: **«звук становится геометрией и пространством»** (не цветом — пользователь НЕ видит цвет в звуке, но остро слышит **объём/«сцену»** и чувствует «правду» звука).

Его картина мира — петлевая квантовая гравитация: всё из **геометрии пространства**, спиновой пены и сетей графов (узлы, рёбра; вихри-узлы из фотонов скручивают граф-пространство → масса; бегущие волны = фотоны; гравволны меняют длину рёбер).

> Совпадение, на котором держится визуал: **FM-движок сам по себе граф** — операторы это узлы, «алгоритм» это рёбра (кто кого модулирует). Структура звука, его картина мира и визуал — одна форма: сеть.

- **Палитра:** тёмная пустота (Малевич / космос) + светящееся вихревое движение (Ван Гог / фотоны) + золотой орнамент-мерцание (Климт) + кишащая сюрреал-деталь (Босх).
- **Визуал = реактивный спин-граф:** узлы пульсируют от нот, рёбра растягиваются (как гравволны меняют длину рёбер), бас скручивает вихри-узлы, волны бегут по рёбрам — **глубина/пространство важнее цвета**.
- **Мотив/лого:** **Звезда Давида из двух невозможных треугольников Пенроуза** (невозможный гексаграм) — Пенроуз же и автор спиновых сетей, двойная связь с его ТВ; ветвление многомирия как паттерн для VJ-сцен.
- **Тон:** студия — поток и тело, не таблицы; допустим космический юмор в духе его гонзо-sci-fi (в copy и пустых состояниях).
- **Визуал рождает сюжет:** абстракция, в которую зритель проецирует эмоцию и историю (визуализация WMP однажды без слов вызвала у него «диалог мужчины и женщины»). Два узла + ребро = «диалог» — отношения видны прямо на языке графа. Не случайные эффекты — оставляем место для смысла.

## 🎼 Музыкальный профиль и звуковые цели

Звук делаем не абстрактный, а **его**. Опора — слух (ловит «правду/фальшь»), пространство и вкус.

**Играет (на слух):** варган, диджериду, шаманский бубен (→ обертоны/дроны), дарбука, джембе, индийские таблы (→ грув/полиритм), фоно, гитара, флейта, труба (→ мелодия/дыхание). Эти инструменты — **готовые мостики к теории**: учим синтез через то, что руки уже знают.

**Жанры:** Drum and Bass, Breakbeat, Breakcore, Chillrave, IDM, LoFi Chill & Lounge, Hardcore.

**Ориентиры (для саунд-дизайна):** Йоко Канно, Таку Ивасаки, OST Death Note, **Ясунори Мицуда (Chrono Cross)**, Бетховен; The Chemical Brothers, Metrik, Blaerg, Carbon Based Lifeforms, Dead Can Dance, Juno Reactor, Beats Antique, Hol Baumann, Atlantida Project, **Йоши Хирокава** (за пространство/«сцену»).

**Любимый звук:** раскатистый бас.

### Звуковые приоритеты и первые патчи

1. **Раскатистый бас №1** — Reese/sub/growl (DnB). **Первый «геройский» патч**, с него начинаем.
2. **Дроны/обертоны** — эволюционирующие гармонически богатые текстуры (его диджериду/варган на слух).
3. **Органик-эмоциональный фьюжн** (à la Chrono Cross / Beats Antique) — струнные/лид + мировая перкуссия + пространство.
4. **Брейкбит/драм** — нарезка брейков, breakcore-ритмы (перкуссионный бэкграунд).
5. **Колокольчики / электропиано DX-7** — стеклянный FM.

Сквозные ценности: **раскатистый бас + объём/«сцена» (3D-звук) + полный динамический диапазон** (от LoFi-чилла до Hardcore) + **«правда» тембра** (фальшь — кринж, поэтому свой движок и придирчивая настройка).

### Сетап и устройства

- Сейчас: второй экран, наушники, ноутбук.
- Хочет (гик): Korg перкуссионный MIDI-пэд, микрофон (для Фазы 6), камера Canon EOS-R (вебкам для motion-входа / съёмка перформансов).
- → **MIDI-вход устройство-агностичный**: SMK-37 + Korg + любой class-compliant; не хардкодим одну клавиатуру.

## 🔒 Приватность и публикация (важно)

Студия — это **твоя закрытая комната**. Витрина — **дверь, которую открываешь только ты и только когда захочешь**.

- **По умолчанию ничего не публикуется.** Патчи и записи сохраняются локально (IndexedDB браузера) — физически не покидают машину.
- **Публикация — отдельное осознанное действие** на конкретный патч: только тогда его JSON попадает в публичный `patches/` (и в Git). Один патч за раз, в любой момент можно снять с публикации.
- **Open-source-миссия не требует обнажать личное.** «Паттерны, которые копируют другие» = код, синт-движок, формат патчей и патчи-шаблоны — а не обязательно твои личные треки. Витрина может стартовать пустой или с парой демо-патчей.
- **`JOURNAL.md` — приватный по умолчанию** (можно держать в `.gitignore` или приватно). Это безопасное пространство проб и ошибок.

> Технически: студия пишет в IndexedDB; кнопка «Опубликовать» экспортирует патч в `patches/<id>.json`. Публичная `/gallery` читает только содержимое `patches/`.

### Раскладка папок на диске

```
apps/synth/
├── .gitignore        # игнорирует private/
├── private/          # 🔒 НЕ коммитится — «закрытая комната»
│   ├── tracks/       #    сырые записи (WAV), черновики
│   └── patches/      #    черновики патчей
├── tracks/           # ✅ отслеживается — опубликованные треки
└── patches/          # ✅ отслеживается — опубликованные патчи (читает /gallery)
```

Рабочий цикл: пишешь/творишь → файл лежит в `private/…` (локально) → когда готов, **переносишь** в отслеживаемую папку (`private/tracks → tracks`, `private/patches → patches`) и коммитишь. Ничего не уходит наружу без твоего переноса.

## 🎹 Аппаратная база — M-VAVE SMK-37 PRO

| Параметр    | Значение                                                               |
| ----------- | ---------------------------------------------------------------------- |
| Клавиши     | 37, velocity-sensitive, 3 октавы                                       |
| Пэды        | 16 RGB backlit, velocity + aftertouch                                  |
| Энкодеры    | 8 × 360° бесконечных                                                   |
| Фейдеры     | 4 назначаемых → 8 через fader bank                                     |
| Дисплей     | OLED                                                                   |
| **Звук**    | **встроенный 6-операторный FM-движок, совместим с патчами Yamaha DX7** |
| Секвенсор   | 8 паттернов, режимы key/live/drum, до 64 шагов, swing/gate/tempo       |
| Прочее      | арпеджиатор, note repeat                                               |
| **Аудио**   | **3.5 мм выход (наушники/линия) + режим USB-аудиоинтерфейса**          |
| Подключение | USB-C + Bluetooth Wireless MIDI (Win/Mac/iOS/Android)                  |
| Патчи       | **загрузка по SysEx, в т.ч. с веб-страниц** с FM-коллекциями           |
| Редактор    | M-Vave MidiSuite (требует подключённого устройства)                    |

**Следствия для архитектуры:**

- Устройство = **источник звука И USB-аудиоинтерфейс** → аппаратный FM-голос пишется в браузер через `getUserMedia`.
- **Один FM-патч (формат DX7)** живёт в трёх местах: браузерный AudioWorklet (дизайн где угодно) · аппаратный движок (заливка по Web MIDI SysEx) · экспорт `.syx` (откроется на любом DX7-совместимом железе/плагине — Dexed, Volca FM, реальный DX7).
- Наличие реального железа даёт нам **эталон DX7-звука бесплатно** — можно A/B-сравнивать свой браузерный FM-движок с аппаратным и подтягивать точность.
- Субтрактивные (Nord-style) патчи аппаратного аналога не имеют → живут только в браузере + витрине (JSON + отрендеренное аудио).

⚠️ Точную SysEx-карту устройства (запрос дампа патча, управление LED пэдов, текст OLED, CC энкодеров/фейдеров) **подтвердить** по community-докам (`jonathaslacerda/smk-37-pro-docs`) и мануалу — задача Фазы 1.5.

## 🏗️ Архитектура (browser-first, слоями)

Нижние слои не зависят от верхних. Keystone — **модель патча**.

```
┌─ Фаза 1 (браузерная студия) ───────────────────────────────┐
│ 1. Модель патча (JSON, портативная)                         │
│    ├─ type: 'fm'         → маппинг в/из DX7 SysEx (155 байт) │
│    └─ type: 'subtractive'→ осцилляторы→фильтр→amp, LFO, ADSR │
│ 2. Аудио-движок (Web Audio; ядро DSP в AudioWorklet)        │
│    ├─ FM: 6 операторов, 32 алгоритма, EG на оператор         │
│    ├─ Subtractive: осц. + фильтр (cutoff/резонанс) + ADSR    │
│    └─ Drums: 16 пэдов → синт-перкуссия 808/909 + сэмплы      │
│ 3. Ввод (Web MIDI, sysex:true): клавиши/пэды/энкодеры/фейдеры│
│ 4. Реактивный UI (60fps, rAF + Canvas/SVG): клавиатура,      │
│    ручки; реактивный спин-граф (глубина/пространство)        │
│ 5. Запись: MediaRecorder (живая) + OfflineAudioContext (рендер)│
│ 6. Витрина /gallery (публичная): только опубликованные патчи │
│    + экспорт .syx + shareable-URL (состояние в #hash)        │
│ + IndexedDB (приватное хранилище) + JOURNAL.md (приватный)   │
└─────────────────────────────────────────────────────────────┘
┌─ Фаза 1.5 (мост к железу) ─────────────────────────────────┐
│ 7. Web MIDI SysEx ↔ аппаратный FM-движок (залить/прочитать  │
│    DX7-патч); запись аппаратного звука через USB-audio in     │
└─────────────────────────────────────────────────────────────┘
┌─ Фаза 2 (мост к FL Studio) ────────────────────────────────┐
│ 8. device_synth.py (Python в FL Studio) ↔ loopMIDI ↔        │
│    отдельный Node-процесс ↔ Next (WS/SSE): BPM/Play-Stop/трек │
└─────────────────────────────────────────────────────────────┘
┌─ Фаза 3 (MCP-сервер для Claude Desktop) ───────────────────┐
│ 9. JSON-RPC 2.0 (stdio/SSE): ресурс daw://current-state,    │
│    инструменты send_midi_sequence / generate_chord_pattern   │
└─────────────────────────────────────────────────────────────┘
```

### Транспорт (важно)

- Браузерное ядро (Фазы 1–1.5) **не требует своего сервера** — Web MIDI и Web Audio событийны в клиенте, 60fps через `requestAnimationFrame`. Кастомный сервер Next **не поднимаем**.
- Фаза 2: нативные MIDI-либы (node-gyp) и связь с FL Studio изолированы в **отдельном Node-процессе** (свой Nx-таргет), общается с Next по WS/SSE.

## 🎛️ Открытый формат патча (сердце витрины)

```jsonc
{
  "schemaVersion": 1,
  "id": "glass-bells-01",
  "name": "Стеклянные колокольчики",
  "author": "kami",
  "visibility": "private", // 'private' (по умолчанию) | 'public'
  "license": "CC0-1.0", // патчи — public domain / CC; код — MIT
  "type": "fm", // 'fm' | 'subtractive' | 'drumkit'
  "tags": ["bells", "dx7", "bright"],
  "createdAt": "2026-06-15",
  "engine": {
    // type:'fm' — параметры, изоморфные DX7-голосу (6 операторов,
    //   алгоритм 1–32, feedback, EG/levels, keyboard scaling, LFO, ...)
    // type:'subtractive' — осцилляторы, фильтр(cutoff,res), ADSR, LFO, fx
  },
  "render": { "previewWav": "glass-bells-01.preview.wav" }, // опц.
  "color": "#7cc8ff" // цвет-метка патча для витрины (UI-тег, не из синестезии)
}
```

- **FM-патчи** дополнительно экспортируются в стандартный `.syx` (DX7 single-voice: `F0 43 0n 00 01 1B …155 байт… checksum F7`; bulk-банк = 32 голоса × 128-байт пакеты = 4104 байт). Совместимы с любым DX7-движком и заливаемы в железо.
- Хранилище: IndexedDB (приватно) → публикуемые в `apps/synth/patches/*.json` (Git).
- Shareable-URL: всё состояние патча кодируется в `#hash` → ссылка открывает звук без бэкенда.
- **Драм-киты** — родственный артефакт (набор из 16 пэдов × звук), тот же JSON + витрина (`type: 'drumkit'`).

## 🧰 Технологический стек

| Слой            | Технология                                                                    |
| --------------- | ----------------------------------------------------------------------------- |
| Синтез          | **Web Audio API**, ядро DSP в **AudioWorklet** (sample-accurate); опц. WASM   |
| Ввод            | **Web MIDI API** (`requestMIDIAccess({ sysex: true })`)                       |
| Запись          | **MediaRecorder** (живая) + **OfflineAudioContext** (детерминированный → WAV) |
| Аппаратный звук | устройство как **USB-audio input** → `getUserMedia` → запись                  |
| Хранилище       | IndexedDB (приватно) + файлы `patches/` (публично)                            |
| Фронт           | Next.js 16 (App Router), React 19, **Chakra UI v3** (+ токены/recipes)        |
| Формы           | **@letar/forms** + Zod v4 (метаданные патчей)                                 |
| Графика         | Canvas/SVG, 60fps                                                             |
| Фаза 2          | Python (FL Studio MIDI Scripting API), loopMIDI, Node-процесс (WS/SSE)        |
| Фаза 3          | MCP SDK (JSON-RPC 2.0, stdio/SSE)                                             |

**Совместимость браузеров:** Web MIDI — только Chromium (Chrome/Edge 79+, Opera) и Firefox (с add-on). **Safari/iOS не поддерживают.** Chrome 124+ — весь Web MIDI за разрешением; SysEx требует `sysex: true`. → Целевой браузер: **Chrome/Edge на десктопе**. Витрина-просмотр (без MIDI) работает везде.

**Латентность:** потолок браузера на Windows — нет ASIO (≈10–30 мс). Серьёзный низколатентный трекинг — задача Фазы 2 (FL Studio + ASIO).

## 🎓 Программа обучения (ненавязчиво, 1–2 термина за веху)

Принцип **ear-first / eye-first**: сначала ощущение и цвет/форма, потом — название. Каждый термин — метафорой, демонстрируется в звуке, записывается в `JOURNAL.md`.

Дорожная карта терминов (см. 🎵 в фазах): тембр → ADSR → оператор/несущая/модулятор → cutoff/резонанс → velocity/transient → пространство/реверберация → spatialization (HRTF) → SysEx/алгоритм → BPM/транспорт → аккорд/интервал → лад/тональность/гамма/арпеджио → компрессия/gain-staging.

**Мостики из его инструментов:** диджериду/варган/бубен → обертоны и дроны (FM, фильтр); дарбука/джембе/таблы → грув и драм; труба/флейта → атака/огибающая; фоно → гармония. Учим теорию через то, что тело уже знает.

### `JOURNAL.md` — формат записи

```markdown
## 2026-06-15 — Первый колокольчик

**Создано:** патч `glass-bells-01` (FM, алгоритм 5).
**Услышал:** как feedback оператора добавляет «песок» в атаку.
**Новый термин:** оператор — генератор-синус; несущая звучит, модулятор её «трясёт».
**Метафора:** модулятор — рука, что быстро дёргает струну несущей.
```

## ⚠️ Риски и ограничения

- Web MIDI — нет Safari/iOS; нужен Chrome/Edge + разрешение (sysex). Витрина-просмотр кроссбраузерна.
- SysEx-карта SMK-37 PRO не задокументирована официально — нужна разведка; управление LED/OLED может не поддерживаться.
- Латентность браузера (нет ASIO) — низколатентный трекинг на Фазу 2.
- node-gyp/нативные MIDI-либы — только в изолированном Node-процессе Фазы 2.
- Точность браузерного FM vs реальный DX7 — при необходимости WASM-ядро Dexed (внимание: лицензия GPL).
