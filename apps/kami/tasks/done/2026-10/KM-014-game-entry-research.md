## Исследование — 2026-10-26

Это качественный обзор, не рейтинг популярности. Даты ниже относятся к публикациям/выходу игр,
а не к дате проверки. Все ссылки открыты 26 октября 2026 года.
Анализ статичных экранов не доказывает характер движения: видео нужно смотреть на этапе KM-015.

### Примеры и источники

1. **NieR:Automata — интерфейс как часть мира.** UI-дизайнер Кидзима объясняет,
   как строгая сетка, символы и тонко настроенные анимации создают ощущение системы;
   декоративные эффекты подчинены композиции. Для Kami полезны ритм и сдержанность,
   но не копирование бежевой палитры.
   [PlatinumGames, 25.08.2017](https://www.platinumgames.co.jp/dev-nier-automata/article/183).
   [Архив стартового экрана и загрузки](https://interfaceingame.com/games/nierautomata/)
   — самостоятельная подборка, игра 07.03.2017.
2. **Control — отделить заглавный экран от меню.** В архиве есть отдельные Main menu,
   Start screen и Loading. Это полезная декомпозиция состояний: каждое имеет назначение;
   сайт может сохранить разницу состояний, но не требовать дополнительного нажатия ради входа.
   [Экранный архив, игра 27.08.2019](https://interfaceingame.com/games/control/).
   По статичным кадрам не делаем выводов о длительности загрузки.
3. **Dragon Age: Inquisition — переход продолжает сцену меню.** В разборе Max Pears
   меню с марширующими персонажами становится началом события после выбора New Game.
   Для Kami: буквы не исчезают под новым hero, а освобождают место пунктам меню;
   для студии: включение монитора заканчивается рабочим CRT-интерфейсом.
   [Setting the Tone, 21.04.2016](https://www.gamedeveloper.com/design/setting-the-tone-main-menus-are-the-game).
4. **Splinter Cell: Conviction — выбор связан со сценой.** Тот же разбор показывает
   смену действия вслед за выбором меню. Переносимый принцип — обратная связь на выбор,
   а не буквальная камера: тонкое изменение глубины/свечения при focus и hover.
   На телефоне эффект должен работать по нажатию; hover не может быть обязательным.
   [Разбор Max Pears, 21.04.2016](https://www.gamedeveloper.com/design/setting-the-tone-main-menus-are-the-game).
5. **Halo Wars 2 — ожидание с содержанием.** Mike Ellis приводит брифинг как способ
   содержательно использовать загрузку. Для сайта информация полезнее пустого таймера:
   пока тяжёлый фон готовится, доступны имя, контакты и меню.
   Тот же автор предлагает проверять необходимость Press to Continue и заранее измерять ожидание.
   [Improving Player Experience Outside of Gameplay, 02.08.2017](https://www.gamedeveloper.com/design/improving-player-experience-outside-of-gameplay).
6. **HyperDot — возможность остановить движение.** XAG 117 показывает отключение
   Animate Background как конкретный игровой пример. Для сайта нужна ручная остановка фона
   вместе с поддержкой reduced-motion; движение под неподвижным текстом тоже отвлекает.
   [Microsoft XAG 117, обновлено 04.03.2026](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/117).

### Сценарии и границы

| Событие                          | Визуальная часть                                   | Доступ к содержанию                                |
| -------------------------------- | -------------------------------------------------- | -------------------------------------------------- |
| Прямой вход на главную           | Короткая последовательность входа                  | Меню и пропуск доступны без ожидания фона          |
| Reload главной                   | Новый запуск, как reset                            | Не зависит от флага «когда-то смотрел»             |
| Browser Back                     | Восстановленная сцена, без заставки                | Сразу прежнее меню/фокус, без повторного перехвата |
| Повторный новый прямой визит     | Вход снова по требованию владельца                 | Сохраняются настройки движения                     |
| Внутренняя ссылка Home / Forward | Предложение: краткий переход, без полной церемонии | Уточнить визуальный вариант в KM-018               |
| Медленная сеть / ошибка фона     | Статичный фон, честный статус загрузки ресурса     | Контакты и ссылки продолжают работать              |
| Reduced-motion                   | Сразу статичная композиция                         | Ни пролёта камеры, ни сборки букв                  |

### Три направления

| Направление          | Сценарий                                              | Сложность и риски                                                                               |
| -------------------- | ----------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| A. Живой терминал    | Поток букв → замедление → спокойное поле и меню       | Минимальная стоимость из трёх; нужен плавный цикл без резких стыков                             |
| B. Портрет автора    | Поток → силуэт/лицо из букв → освобождение зоны меню  | Выше стоимость; проверить узнаваемость и телефоны в KM-019                                      |
| C. Вход сквозь экран | Буквы в глубине → смена перспективы → стабильное меню | Самая высокая стоимость и чувствительность к движению; без WebGL до проверки простого прототипа |

**Рекомендация (проектное решение, не вывод источников):** начать с A.
Это даёт профессиональный результат за счёт непрерывности движения и ясного меню.
B прототипировать как отдельный акцент после проверки фотографии; C пока оставить альтернативой.
Для студии использовать тот же порядок состояний, сохраняя её CRT-эстетику.

### Storyboard направления A

1. С первого кадра: фон базового цвета, имя/пять ссылок уже в DOM; видимый «Пропустить».
2. Ориентир 0–400 мс: отдельные потоки букв проявляются, положение меню стабильно.
3. Ориентир 400–1100 мс: плотность и скорость мягко снижаются вокруг зоны меню,
   на периферии остаётся жизнь. Не анимировать само читаемое меню вместе с камерой.
4. Ориентир 1100–1500 мс: художественный вход завершён, остаётся слабый фоновый ритм.
   Эти времена — бюджет для прототипа, не искусственный таймер ожидания загрузки.
5. Выбор раздела: короткая реакция активного пункта и штатная навигация.
   Back восстанавливает меню без шагов 1–4.

### Критерии качества для следующих задач

- Меню работоспособно независимо от готовности canvas, портрета и шрифтов.
- Нет выдуманного процента; статус загрузки отражает реально отслеживаемый ресурс.
- Пропуск, Escape и отключение движения; при reduced-motion сразу финальный кадр.
- 320–430 px: пять пунктов читаются, от текста отделена спокойная зона;
  настройки не спрятаны за прохождением заставки.
- До реализации замерить бюджет на выбранном среднем телефоне: целевой кадр ≤ 16,7 мс,
  допустимый упрощённый режим ≤ 33,3 мс; при перегрузе уменьшать плотность/DPR.
  Это целевые бюджеты, текущих замеров новой анимации ещё нет.
- Не проигрывать звук без действия пользователя. Не заимствовать чужие ассеты/типографику.
- KM-015 сравнивает три прототипа, KM-017 реализует выбранный вход,
  KM-018 проверяет историю, KM-019 решает портрет; KM-023 связывает студию.
