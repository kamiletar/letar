## Что и зачем

Экран «Выберите путь» из церемонии — это и есть главное меню, отдельного шага нет.
Меню выглядит и ведёт себя как стартовое меню игры, но остаётся обычной навигацией из ссылок.
Главный пункт «Заказать сайт» стоит первым и ведёт на посадочную `/site/` (KM-029).

## Приёмка

- [x] Порядок: Заказать сайт, Обо мне, Блог, Контакты, Для друзей; один источник — `public-navigation.ts` (шапка, Drawer, подвал обновлены вместе).
- [x] «Заказать сайт» ведёт на `/site/` и `/en/site/` и визуально главный; остальные пункты вторичны.
- [x] У каждого пункта короткая подпись (что внутри); подписи видны всегда, без hover — трафик почти весь с телефона.
- [x] Маркер ▶ стоит у пункта в фокусе или под курсором, по умолчанию — у первого; стрелки ↑/↓ двигают фокус по кругу, Home/End — в начало и конец, Enter — штатный переход ссылки; Tab работает как обычно.
- [x] Выбор: реакция ~250 мс (маркер вспыхивает, буквы фона расходятся от пункта), затем переход; при reduced-motion — сразу переход. Переход не ломает ctrl/cmd-клик и среднюю кнопку.
- [x] Посадочная, открытая из меню в этой вкладке, набирает первый экран посимвольно (текст уже в DOM); прямой заход, reload и reduced-motion — статично.
- [x] Без JS: ссылки, подписи и порядок те же, маркера нет.
- [x] Umami `menu-select` с `{ key }`.
- [x] 320–430 px: пять пунктов с подписями читаются, цели ≥44 px; 1440 px; RU/EN; обе темы; Chromium и WebKit.

## План

1. `public-navigation.ts`: новый порядок, `order` → `/site/` (внутренняя ссылка через `@/i18n/navigation`;
   ветку `<a href>` для `order` в `hero.tsx` убрать). Проверить шапку, Drawer и подвал — там тоже
   первым станет «Заказать сайт»; если владелец захочет другой порядок в шапке — отдельное поле.
2. Подписи — `messages/*.json`, `home.hints.<key>`. Черновики: «цена, сроки и как идёт работа»,
   «кто я и чем занимаюсь», «заметки и разборы», «почта и Telegram», «что есть для друзей».
3. Клиентский компонент `hero/game-menu.tsx` поверх серверной разметки: roving focus по стрелкам
   (`keydown` на `<nav>`), маркер — псевдоэлемент или `<span aria-hidden>` по `:focus-visible`,
   `:hover` и `data-active`. Стиль главного пункта — заливка/толще рамка в токенах Kami, не новый цвет.
4. Реакция на выбор: перехват обычного клика (без модификаторов), 250 мс анимации, затем
   `router.push`; событие `kami:menu-select` с координатами пункта для фона (опционально в
   `matrix-rain.tsx`: локальный разлёт прозрачностью, геометрия по-прежнему от времени).
5. Набор первого экрана `/site/`: перед переходом записать в `sessionStorage`
   `kami.entry.from-menu = <время>:<performance.timeOrigin>`; hero посадочной проверяет свежесть
   (<10 с, та же вкладка — урок студии с флагом смены языка) и только тогда набирает текст.
   Флаг не снимается при чтении (Strict Mode, повторный монтаж).
6. Umami `menu-select`.
7. **Клик по меню во время церемонии** (решение сеньора 2026-10-27). Сейчас `onClick` в
   `matrix-rain.tsx` любой клик по пункту меню превращает в пропуск входа. Правило: пункт, который
   уже проявился (`menuItems[i] ≥ 0,5` в `getCeremonyState`), — пропуск входа и сразу выбор этого
   пункта (реакция 250 мс из п. 4, затем переход); пункт, который ещё не виден, — только пропуск,
   без перехода. Клик с модификаторами и средняя кнопка — штатное поведение браузера всегда.
   В e2e: клик по видимому пункту на ~4,0 с ведёт на страницу пункта, клик по невидимому на ~1 с — нет.
8. Проверка по приёмке, снимки `.claude/artifacts/km031-*.png`; обновить `references/public-entry.md`
   (порядок меню, подписи, флаг). Версия minor, CHANGELOG, проверки, коммит.
