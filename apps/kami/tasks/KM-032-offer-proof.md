## Что и зачем

Доказательства на посадочной — только реальные: проекты, которые владелец сам отметил в админке.
У модели `Project` (`schema/portfolio.zmodel`) уже есть `featured` и чекбокс «Избранный проект» в
`/admin/projects`, публично флаг пока нигде не читается. Схему менять не нужно.

## Приёмка

- [ ] Секция «Проекты» на `/site/` выводит `featured`-проекты по `order`; нет ни одного — секции и строки доказательства в hero нет.
- [ ] Карточка: название и описание в локали, картинка через `next/image` с alt, ссылки демо/кейс, если заданы; технологии — не больше трёх меток.
- [ ] Число в строке доказательства hero («N сделанных проектов») считается из БД, а не пишется в тексте.
- [ ] Подпись чекбокса в админке поясняет: «Показывать на посадочной „Заказать сайт“».
- [ ] Страница `force-dynamic` (данные из админки, см. nextjs-apps.md), обе локали проверены после правки в админке.
- [ ] Отзывы (модель `Testimonial`) — только если в БД есть опубликованные; иначе блока нет. Решение о показе отзывов — за владельцем, по умолчанию выключено.

## План

1. Запрос в `offer-projects.tsx` (слот из KM-029): `prisma.project.findMany({ where: { featured: true }, orderBy: { order: 'asc' }, select: … })`
   по образцу `src/app/[locale]/projects/page.tsx`.
2. Карточки в стиле стеклянных пунктов меню; сетка 1 колонка на телефоне, 2–3 на компьютере.
3. Счётчик для hero — тот же запрос `count`, передаётся пропсом.
4. Подпись чекбокса в `admin/projects/_components/project-form.tsx`.
5. Проверка: без избранных → секции нет; с двумя → карточки и число 2; RU/EN.
6. Версия patch/minor, CHANGELOG, проверки, коммит.

Связь: портфолио студии берёт проекты из Kami (ST-066) — при выборе API учесть, что флаг может
понадобиться и там, но в этой задаче API не делать.
