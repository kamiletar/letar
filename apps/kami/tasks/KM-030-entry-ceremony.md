## Что и зачем

Многоэкранный вход на главную, как у студии, но своим сюжетом: буквы «собирают систему».
Поток букв → строки загрузки kami.os с реальными статусами → буквы ловятся на места и
складывают KAMI → печатается роль → проявляется меню. Полная версия ~4,2 с, короткая ~1,5 с.
Выбор полной/короткой и Back — KM-018; игровое поведение меню — KM-031. Эта задача отдаёт
им API `mode: 'full' | 'short' | 'none'`.

## Приёмка

- [ ] Таймлайн полной версии укладывается в 4,2 ± 0,3 с при быстрых событиях, короткой — в 1,5 ± 0,2 с (Playwright, Chromium и WebKit).
- [ ] Строки boot-лога появляются только после реального события (`warm()` атласа, `document.fonts.ready`); событие не пришло за 2,5 с — строка «позже», меню не ждёт.
- [ ] Имя, роль и пункты меню на финальных местах с первого кадра; анимируются только `opacity`/`transform`; CLS < 0,1.
- [ ] Без JS и при reduced-motion — сразу финальный кадр; CSS-страховка показывает меню через 5 с, если JS завис.
- [ ] «Пропустить», Escape и клик по пустому месту — финальный кадр за ≤0,6 с; клик не переходит по ссылке.
- [ ] Слои церемонии `aria-hidden`; скринридер получает h1, роль и меню сразу; фокус не перехватывается.
- [ ] Геометрия по-прежнему зависит только от времени; unit-тесты на непрерывность и фазы, существующие 21 тест зелёные.
- [ ] 390 и 1440 px × RU/EN × обе темы; стоимость кадра записана; физический телефон — отдельным пунктом журнала (замер на компьютере его не заменяет).
- [ ] Umami: `entry-complete` и `entry-skip` с `{ mode }`.

## План

Перед началом: KM-028 (таймлайн), `.claude/skills/kami/references/public-entry.md` (раздел «Вход»),
`.claude/docs/kami-letter-motion-prototypes.md`, текущие `src/lib/matrix-scene.ts`,
`src/app/_components/matrix-rain.tsx`, `src/app/_components/hero/{hero,entry-skip}.tsx`.
Для ориентира по ощущению — входы студии (приватные задачи ST-067), но сюжет и код не копировать.

1. **Чистая модель таймлайна** `src/lib/entry-ceremony.ts` (без DOM):
   ```ts
   export type EntryMode = 'full' | 'short' | 'none'
   export interface CeremonyEvents {
     atlasReadyAt: number | null
     fontsReadyAt: number | null
   }
   /** Состояние каждого слоя в момент elapsed; одна функция — один источник правды для тестов. */
   export function getCeremonyState(elapsed: number, mode: EntryMode, events: CeremonyEvents): {
     bootLines: { key: string; visible: number; status: 'wait' | 'ok' | 'later' }[]
     nameLetters: number[] // 0..1 на каждую букву KAMI
     role: number // доля напечатанных символов
     menuItems: number[] // 0..1 на каждый пункт, шаг 60 мс
     calm: number // для entryFactor фона (KM-017)
     done: boolean
   }
   ```
   Фазы и времена — из таблицы KM-028; короткая версия пропускает boot-лог.
   Строка лога видна с `max(запланированное время, время события)`; потолок 2,5 с → `later`.
   Тесты в `entry-ceremony.test.ts`: монотонность, конец фаз, короткая без лога, медленное
   событие не задерживает меню, `none` — всё равно 1.
2. **Строки лога:** `kami.os <версия из package.json>`, `глифы … ok`, `шрифты … ok`,
   `язык … ru|en`, `тема … тёмная|светлая` (en: glyphs/fonts/language/theme). Короткие строки
   ≤28 символов, чтобы помещались на 320 px. Тексты — `messages/*.json`, namespace `home.boot`.
3. **Слой лога** — DOM `<div aria-hidden>` поверх hero, моноширинный шрифт, абсолютное
   позиционирование (не сдвигает раскладку). Строка печатается пачкой символов, курсор один.
   После сборки имени лог уходит вверх и гаснет.
4. **Сборка KAMI:** настоящий `<h1>` остаётся в DOM; буквы оборачиваются в `<span>` (для
   скринридера текст цельный: `aria-label` на h1 либо визуальные спаны `aria-hidden` + скрытый
   текст). Canvas рисует для каждой буквы «ловца» — глиф из ближайшего потока, который за
   ~0,25 с летит к центру спана (координаты меряются в `resize`, как зона меню в KM-017);
   по прилёту спан проявляется (`opacity` 0→1, `transform` scale .96→1), глиф гаснет.
   Траектория — функция времени, без накопления состояния.
5. **Роль** печатается посимвольно через `clip-path`/маску или по спанам; текст в DOM целиком.
6. **Меню:** пункты проявляются по `menuItems[i]` (opacity + translateY 8 px → 0). Само игровое
   поведение (маркер, стрелки) — KM-031; здесь только появление.
7. **Ранний флаг до отрисовки.** Инлайн-скрипт в `<head>` главной (по образцу ранних скриптов из
   `.claude/docs/react-ssr-scripts-and-popstate-order.md`) ставит на `<html>`
   `data-kami-entry="full|short"` только при JS, без reduced-motion и на главной; CSS скрывает
   слои по этому атрибуту. Страховка: `animation: kami-entry-failsafe 0s 5s forwards` делает всё
   видимым. Решение full/short пока — всегда `full`; правило повтора добавит KM-018.
8. **Связка с фоном:** `matrix-rain.tsx` получает `mode` и события; `entryFactor` использует
   `calm` из `getCeremonyState`. Убедиться, что часы входа по-прежнему стартуют после `warmed`.
9. **Пропуск:** существующий `EntrySkip` и Escape переводят `elapsed` в конец (а не ×6),
   плюс клик по фону вне ссылок. `data-kami-entry` снимается в конце.
10. **Umami:** `entry-complete`/`entry-skip`.
11. **Проверка:** Playwright (в скрытой панели Claude Browser rAF не идёт), кадры на 0,3/1,2/2,5/3,4/4,3 с,
    запись времени кадра, no-JS, reduced-motion, skip. Снимки — `.claude/artifacts/km030-*.png`.
12. Обновить `references/public-entry.md` (раздел «Вход»), версия minor, CHANGELOG, проверки, коммит.

Задел под портрет (KM-019, решение владельца 2026-10-26): фазы в `getCeremonyState` задаются
таблицей с началом и длительностью, а не константами в коде, — тогда KM-019 вставит фазу
`portrait` между boot-логом и сборкой имени и сдвинет остальные, не переписывая модель.
«Ловцы» для букв KAMI берутся из функции-источника (сейчас — ближайший поток; KM-019 подставит
буквы лица).

Не делать: сам портрет (KM-019), звук, правило повтора и Back (KM-018), порядок меню (KM-031).
