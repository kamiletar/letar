---

## 1. Общее описание проекта

### 1.1 Назначение

**Kami** — персональный сайт-портфолио фронтенд-архитектора, демонстрирующий профессиональные навыки, проекты и уникальный подход к разработке. Сайт служит интерактивной визитной карточкой и заменяет традиционные этапы собеседования.

### 1.2 Ключевая идея

Сайт должен производить впечатление **"гения веб-разработки и UI/UX"** через:

- Эффектную визуализацию (Matrix-эффект на canvas)
- Интерактивные элементы и микро-анимации
- Продуманный UX и безупречную производительность
- Демонстрацию владения современными технологиями
- Уникальную фичу — использование Claude Code как инструмента архитектора

### 1.3 Уникальное торговое предложение (УТП)

- **"Сайт = Собеседование"** — весь сайт демонстрирует навыки вместо словесных описаний
- **AI-native архитектор** — активное использование Claude Code как конкурентное преимущество
- **Условия на своих условиях** — 4 дня × 4 часа, прозрачная форма найма

## 4. Функциональные требования

### 4.1 Главная страница (Hero)

#### 4.1.1 Matrix-эффект (Canvas)

```
Требования:
├── Падающие символы в стиле "Матрицы" на canvas
├── Производительная анимация (requestAnimationFrame)
├── Адаптация под размер экрана (resize)
├── Возможность остановки/паузы для accessibility
├── Кастомизация: цвет (зелёный → золотой для бренда?)
└── Trail-эффект через полупрозрачный fillRect
```

**Технологии:** HTML5 Canvas, vanilla JS или Three.js для 3D-варианта

#### 4.1.2 Hero-секция

- Имя/позиция с анимацией появления (Framer Motion)
- Краткое описание (typewriter-эффект?)
- CTA-кнопки: "Познакомиться" → О себе, "Позвать на работу" → Форма
- Индикатор прокрутки (scroll indicator)

### 4.2 Страница "О себе" (About)

```
Структура:
├── Фото (с hover-эффектом или параллаксом)
├── Краткая биография (100 слов макс)
├── Ключевые факты (иконки + числа)
│   ├── Лет опыта
│   ├── Завершённых проектов
│   └── Технологий в стеке
```

### 4.7 "Позвать на работу" (Hire Me)

#### 4.7.1 Многошаговая форма (Wizard)

```
Шаги формы:
├── Шаг 1: О компании
│   ├── Название компании
│   ├── Сайт (опционально)
│   ├── Размер команды (выбор)
│   └── Индустрия (выбор)
├── Шаг 2: Состав команды
│   ├── Количество фронтендеров
│   ├── Количество бэкендеров
│   ├── Есть ли дизайнер
│   └── Роль в команде (лид/член)
├── Шаг 3: Технический стек
│   ├── Фреймворк (React, Vue, Angular, etc.)
│   ├── Язык (TypeScript, JavaScript)
│   ├── Стейт-менеджмент
│   └── Тестирование
├── Шаг 4: Условия работы
│   ├── Формат (удалёнка/офис/гибрид)
│   ├── График (full-time/part-time)
│   ├── Готовы ли к 4×4 (да/нет/обсуждаемо)
│   └── Тип оформления (ТК/ИП/ГПХ)
├── Шаг 5: Компенсация
│   ├── Вилка зарплаты
│   ├── ДМС (да/нет)
│   ├── Бонусы
│   └── Отпуск
├── Шаг 6: Процесс найма
│   ├── Сколько этапов собеседования
│   ├── Есть ли тестовое
│   ├── Сайт = собеседование? (чекбокс)
│   └── Дополнительные комментарии
└── Шаг 7: Контакты
    ├── Имя
    ├── Email
    ├── Telegram (опционально)
    └── Согласие на обработку данных
```

#### 4.7.2 UX требования к форме

- **Прогресс-бар** — визуальное отображение прогресса
- **Сохранение прогресса** — localStorage для незавершённых форм
- **Валидация** — real-time + на каждом шаге
- **Навигация** — "Назад"/"Далее", возможность перехода к любому шагу
- **Адаптивность** — mobile-first
- **Анимации** — плавные переходы между шагами (Framer Motion)

#### 4.7.3 После отправки

- Красивая страница "Спасибо"
- Email-уведомление владельцу
- Опционально: Telegram-уведомление

## 5. Нефункциональные требования

### 5.1 Производительность

| Метрика                        | Целевое значение |
| ------------------------------ | ---------------- |
| LCP (Largest Contentful Paint) | < 2.5s           |
| FID (First Input Delay)        | < 100ms          |
| CLS (Cumulative Layout Shift)  | < 0.1            |
| Time to Interactive            | < 3s             |
| Lighthouse Performance         | ≥ 90             |

### 5.2 PWA и Offline

```
Требования:
├── Service Worker (Workbox)
├── Стратегии кеширования:
│   ├── Cache-first для статики
│   ├── Network-first для API
│   └── Stale-while-revalidate для контента
├── Manifest.json
├── Installable на устройство
├── Offline-страница (кастомная)
└── Background Sync для форм
```

### 5.3 SEO

```
Требования:
├── Semantic HTML5
├── Meta-теги (title, description, keywords)
├── Open Graph теги
├── Twitter Cards
├── Structured Data (JSON-LD)
│   ├── Person
│   ├── WebSite
│   ├── BlogPosting
│   └── BreadcrumbList
├── Sitemap.xml
├── robots.txt
├── humans.txt (креативный!)
└── Canonical URLs
```

### 5.4 Accessibility (a11y)

```
Требования:
├── WCAG 2.1 AA compliance
├── Keyboard navigation
├── Screen reader support
├── Focus indicators
├── Color contrast ratio ≥ 4.5:1
├── Alt-тексты для изображений
├── ARIA-labels
├── Reduced motion support
└── Skip to content link
```

### 5.5 Интернационализация (i18n)

```
Языки:
├── Русский (основной)
├── English (вторичный)
└── Переключатель в header

Реализация:
├── next-intl или react-i18next
├── Отдельные URL (/ru, /en)
├── hreflang теги
└── Локализация дат и чисел
```

### 5.6 Темизация

```
Темы:
├── Светлая (по умолчанию при prefers-color-scheme: light)
├── Тёмная (по умолчанию при prefers-color-scheme: dark)
└── Системная (следует за ОС)

Реализация:
├── CSS Variables
├── Плавный переход (transition)
├── Сохранение в localStorage
└── Переключатель в header
```

### 5.7 Адаптивность

```
Breakpoints:
├── Mobile: < 640px
├── Tablet: 640px - 1024px
├── Desktop: 1024px - 1440px
└── Wide: > 1440px

Требования:
├── Mobile-first approach
├── Touch-friendly (44px min touch target)
├── Hamburger menu на mobile
└── Тестирование на реальных устройствах
```

## 10. Методология разработки

### 10.1 TDD (Test-Driven Development)

Все фичи разрабатываются через TDD:

```
Цикл разработки:
1. Red   — пишем тест, который падает
2. Green — пишем минимальный код для прохождения теста
3. Refactor — улучшаем код, сохраняя тесты зелёными
```

**Unit-тесты (Jest/Vitest):**

- Компоненты React (Testing Library)
- Хуки и утилиты
- Серверные экшены
- Валидация форм (Zod-схемы)

**E2E-тесты (Playwright):**

- Навигация и роутинг (i18n)
- Многошаговая форма найма
- Переключение темы/языка
- PWA-функциональность
