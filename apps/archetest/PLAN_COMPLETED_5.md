## Сессия 2026-07-09 — Этап 5.6.5: Ipsative-скоринг + доверительные интервалы (v0.21.0) 📐

Закрыт **последний P0-хвост спринта**: реализовано решение 5.6 от 2026-06-18 («% от
максимума несопоставим между шкалами — ipsative-ранжирование + доверительные интервалы
сейчас, нормативные перцентили при N ≈ 200–300»). Заодно разблокированы и написаны оба
отложенных unit-пункта 5.8.

### Чистое ядро скоринга — `_lib/scoring-core.ts` (рефакторинг 5.6)

- `computeScoresCore(answered, data)` — авторитетный подсчёт raw/normalized/levels/confidence
  без next/db-зависимостей; вход — уже разрешённые вопросы (`sortOrder`, `selectedOption`,
  `options`), загрузка из БД осталась снаружи.
- Справочник максимумов **инжектируем** (`ScoringData`), дефолт — `BANK_SCORING_DATA`
  из JSON психолога: unit-тесты работают на синтетических данных, прод — на реальном банке.
- `calculateScores` в `quiz.action.ts` — тонкая обёртка (БД → ядро); формулы и поведение
  не изменены, типы (`QuizScores`, `ScaleConfidence`…) реэкспортируются — внешние импорты
  не тронуты. `getAveragedScores` переведён на `computeActualMax` из ядра.
- Новое поле `QuizScores.relevantCounts` — число отвеченных релевантных вопросов по шкалам
  (вход для интервалов), прокинуто через все три пути сабмита и кумулятивный профиль.

### Ipsative-слой — `_lib/ipsative.ts`

- Интерпретационный слой ПОВЕРХ normalized по образцу `interpretation-rules.ts`: чистая
  функция, вход не мутируется, **raw/normalized в БД не затронуты — миграция не нужна**.
- `computeIpsativeRanking`: ранги шкал внутри профиля (сортировка по normalized,
  детерминированный tie-break по коду), 95%-интервалы точности (приближение Уилсона
  на n отвеченных релевантных вопросов шкалы; n=0 → честные [0, 100]), tie-группы —
  цепочки соседей с перекрывающимися интервалами.
- Ipsative = сравнение шкал ВНУТРИ человека; сравнение с другими людьми появится
  с нормативными перцентилями (5.6.2/Фаза 3) — оговорено в JSDoc и в UI-подписи.

### UI «Ведущие черты» по ipsative-рангу

- `ProfileDetails` (результаты квиза + «Мой профиль» на интро): топ-3 строится по
  ipsative-рангу; между соседями с перекрывающимися интервалами — честная пометка
  «≈ эти черты выражены примерно одинаково — порядок может меняться от сессии к сессии»
  вместо ложной точности «61,2% > 60,8%».
- Методологическая подпись: «шкалы сравниваются внутри вашего профиля, а не с другими
  людьми; диапазон — 95%-ориентир точности, сужается с числом отвеченных вопросов».
- `DevelopmentalProfileCard`: диапазон `ciLow–ciHigh%` рядом с баллом (новые пропсы).
- Клиентский фолбэк (гость / сетевая ошибка — нет `relevantCounts` с сервера) — прежняя
  сортировка по normalized без интервалов.
- Dev-превью `/dev/developmental` дополнено ipsative-секцией (MAC 72% и SZD 66% при n=40
  неразличимы, OBC 30% — отдельная группа).

### Тесты (5.8 закрыт полностью)

- `scoring-core.test.ts` (**13 unit**): raw/нормализация/уровни/достоверность на
  инжектированном справочнике, границы порогов, relevantCounts, невалидный индекс опции,
  отсутствие мутации, smoke реального банка + сценарий **«пересчёт гостевой сессии»**
  (баллы восстанавливаются только из ответов — отложенный пункт 5.8).
- `ipsative.test.ts` (**12 unit**): интервал Уилсона (n=0, вложенность p, сужение с n,
  края p=0/1, зажим), ранжирование, exclude состояний, tie-группы, детерминизм, мутации.
- Итого **130 unit + 7 E2E**. Прогоны: unit / lint / typecheck:tsgo — зелёные.
- Проверка в preview (`/dev/developmental`): ранги 1–3 = MAC (57–84%) → SZD (51–79%) →
  OBC (18–45%) — интервалы совпали с ручным расчётом Уилсона; тай-нота ровно одна
  (между 1 и 2); ошибок в консоли нет.

### Решения сессии

- Ipsative-ранги и интервалы — интерпретационный слой, НЕ замена normalized в БД:
  история сессий, графики динамики и гексаграмма продолжают работать на прежних данных.
- Интервал Уилсона — честное приближение (баллы вопросов не бинарны), в UI подписан
  как «ориентир точности», не как строгая статистика.
- Кабинет психолога получает `relevantCounts` в `QuizScores` автоматически (через
  `calculateScores`), но UI-подключение интервалов в кабинете — отдельная задача Фазы 3.

### Интеграция в origin и передача деплоя

При push вскрылось, что **`origin/main` отставал от локального на 50 коммитов** по всему
монорепо (archetest v0.10–v0.23, synth, forms, animatrona, mandala, kami, dashboard и др.) —
предыдущие сессии коммитили локально, но не пушили; origin застыл на 5 июля (`3dce5b1`,
dashboard-agent, запушен из отдельного worktree). Причина — процессный пробел: шаг
`local → origin push` без владельца, а деплой тянет origin (значит деплои шли по устаревшему коду).

Интегрировал **аккуратно, без force и без касания чужой WIP**: чистый worktree на `1ad30ea`,
`merge origin/main` (3dce5b1, коммит слияния `cf4383b`, конфликтов нет — файлы непересекающиеся),
fast-forward push. Незакоммиченную правку другого агента (`backup-architecture.md`,
`dashboard-agent/database.ts`) не трогал; локальный main оставлен на `1ad30ea` (ff-able до `cf4383b`).

Деплой **не выполнял** (запрещён напрямую). Координация с BlackCove через Agent Mail упёрлась в

## Сессия 2026-07-28 — Фаза 3: Индекс «Тёмное ядро» (приближение D) (v0.24.0) 🕳️

**Первая задача Фазы 3.** Выбрана как единственная из фазы без внешних блокеров: считается
из уже имеющихся шкал, новых вопросов нет → ревьюер-психолог не нужен, выборка не нужна,
миграций нет, `QUESTION_BANK_VERSION` не тронут. При этом даёт отдачу к фесту — усиливает
раздел «Методология», который читают психологи-скептики.

### Научная база (сверена по первоисточникам)

### Что сделано

- **`_lib/dark-core.ts`** — чистая функция `computeDarkCore` (интерпретационный слой поверх
  `normalized`, вход не мутируется, БД не затрагивается). Считает: уровень ядра
  (unit-weighted composite), «вкусы» (отклонение шкалы от ядра со знаком), размах,
  интервалы Уилсона (переиспользован `wilsonInterval` из `ipsative.ts`), агрегированную
  достоверность (минимум по измеренным + `weakestCode`) и ipsative-контекст.
- **`DarkCoreBlock`** на странице клиента — только психологу, клиенту не показывается.
  Порядок блоков: структурный вердикт → вкусы → число → чувствительность → оговорка.
- **Dev-превью `/dev/dark-core`** — все пять структурных веток (в `/dev/experimental`
  четвёртый квадрант не покрыт — здесь эту недоработку не повторили).
- **24 unit-теста** (итого 171).

### Ключевые решения

1. **Ярлыка абсолютного уровня нет вообще — как отсутствующее поле в типе, а не как
   «не рендерим».** `normalized` — процент от максимума по отвеченным пунктам, не перцентиль;
   «высокое тёмное ядро» — утверждение о положении в популяции, а референсного распределения
   нет до 5.6.2. Переиспользовать `getScaleLevel` (он выдаёт `'extreme'` на ≥80) здесь было
   бы особенно опасно: психолог якорится на ярлыке, а не на сноске, и цена ложноположительной
   «тёмности» несимметрично выше. Главный вывод — структурный: `even` / `flavored` /
   `polarized` / `muted` / `insufficient`. Он ipsative-корректен уже сейчас и не изменится,
   когда появятся нормы — добавится только абсолютная привязка.
2. **Порядок ветвления структуры — по ПОЛОЖИТЕЛЬНЫМ отклонениям.** Наивное правило
   «|отклонение| ≥ порога, и таких ≥ 2 → поляризация» ломается на 90/30/30/30: центрирование
   даёт `+45, −15, −15, −15`, то есть порог превышают все четыре. Закреплено регрессионным
   тестом.
3. **Измеренность шкалы — по `relevantCounts >= 3`, а не по «балл > 0».** `normalized = 0`
   бывает и при `actual_max = 0` («нет данных»), и при честном нуле — различает их только
   число ответов. Банк асимметричен: MAC — 73 релевантных вопроса, NAR — 949, ANT — 987,
   **SAD — 21**. При n = 1 один ответ двигал бы ядро на десятки пунктов.
4. **Порог чувствительности к нарциссизму выводится, а не назначается.** При всех четырёх
   измеренных выполняется тождество `core − core₃ = deviation(NAR) / 3`, поэтому флаг
   «нарциссизм двигает оценку» математически эквивалентен «вкус NAR выражен» — ровно то,
   о чём пишет Hilbig et al. (2023). Тождество проверяется тестом.
5. **Unit-веса, а не взвешивание по n.** Взвешивание превратило бы индекс в «NAR+ANT»,
   то есть в две DSM-5 шкалы, и от тетрады ничего не осталось бы. Асимметрия банка раскрыта
   в оговорке, а не спрятана.
6. **`confidence` не блокирует расчёт.** В этом приложении `confidence` — покрытие банка,
   а не надёжность измерения (`confidenceFromCount` делит на `totalRelevantByScale`; чтобы
   ANT дошёл до `'low'`, нужно ≥ 99 ответов). У почти всех клиентов будет `'insufficient'`,
   и отказ считать по нему убил бы фичу. Он только красит блок и включает оговорку.
7. **MAS в ядро не входит** — деструкция направлена на себя, а D по определению это ущерб
   другим. Закреплено регрессионным тестом.
8. **У SAD «вкус» помечен `source: 'extrapolated'`.** У Bader et al. садизма нет — их
   разложение покрывает только триаду. Выдавать экстраполяцию за источник нельзя, поэтому
   в типе есть поле происхождения, UI печатает бейдж, а тест это проверяет.
9. **`caveat` — обязательное поле результата, а не UI-константа**: оговорка о метрике
   приходит из модуля вместе с числом и не может потеряться при рендере.

### Попутно

- **`generateMetadata` для `/for-professionals`** — у главной B2B-страницы не было
  собственных метаданных вовсе (они были только у `/`, `/express`, `/privacy`), она
  наследовала общий title из layout и была почти невидима в поиске. Добавлены
  title/description/OpenGraph на обе локали и canonical.
- **Все 15 источников «Методологии» стали кликабельными DOI.** Каждый сверялся вручную —
  и это окупилось: у SSIS (садизм) в ходу неверный DOI, правильный `10.1037/a0022400`.
- **Закрыт долг v0.23.0**: раздел «Методология» утверждал, что MAS — единственный конструкт
  без валидированного прототипа, и ничего не знал о трёх экспериментальных шкалах и индексе
  «Броня и Радар». Реализация была, маркировка на публичной странице отставала.
- **Якорь `#methodology`** — для ссылок из презентации и раздатки.
- **В кабинете заработало ipsative-ранжирование.** `ProfileDetails` вызывался без
  `relevantCounts`, из-за чего `computeIpsativeRanking` молча не срабатывал и топ-3
  сортировался просто по баллу — без интервалов и tie-групп. Прокидка `relevantCounts`
  и `confidence` из `getClientDetailAction` починила это бесплатно.
- **Фикс**: `ExperimentalScalesBlock` скрывал «Броню и Радар» при истинном нуле по оси
  (`phys > 0 && aff > 0` не отличало «не отвечено» от нуля) — та же ошибка, которую новый
  модуль обходит по построению.

### Проверки

171 unit (+24) / lint 0 ошибок / typecheck:tsgo / `nx build` — зелёные. Отдельно проверено,
что справочник максимумов (462 КБ) **не утёк в клиентский бандл**: из `scoring-core` берётся
только `import type`. Проверка с положительным контролем — сигнатуры JSON (`"SPEC_INT":3`,
ключи `"2125"`/`"2126"`) найдены в серверном бандле (2 файла) и отсутствуют в клиентском.
Наивная проверка по ключу `per_question_max` не годится: webpack вырезает его tree-shaking'ом.
Dev-превью `/dev/dark-core` — все пять веток; числа ядра, чувствительности и ipsative-рангов
сошлись с ручным расчётом.

### Что осталось спорным (осознанно)

- **Jangle fallacy.** Возможно, индекс измеряет просто антагонизм под модным именем. Проверить
  на наших данных нельзя — шкалы Доброжелательности/HEXACO в тесте нет. Вынесено в докстринг
  модуля и на публичную страницу, а не замолчано.
- **Усреднение несопоставимых процентов-от-максимума.** Постоянный сдвиг шкалы из-за
  формулировок пунктов неотличим от индивидуального «вкуса». Снимается только нормами (5.6.2).
- **Порог вкуса 15 — прагматический**, как `ARMOR_RADAR_THRESHOLD = 50`. Параметризован,
  перепроверить при первых нормах.
- **Динамики по сессиям нет**: `QuizSession.scores` хранит только `raw`, `relevantCounts`
  по сессии не персистится. Индекс кумулятивный; динамика потребовала бы миграции.
