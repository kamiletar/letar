## Обзор

Связанные поля автоматически загружают опции из связанных моделей базы данных. Работают через `RelationFieldProvider` и директиву `form.relation` ZenStack.

## Полный пример

Полный пример из песочницы `form-develop-app`, прочитан напрямую из исходников на сборке.

<SkinCodeFile chakra="apps/form-develop-app/src/app/relation-demo/page.tsx" />

## Настройка схемы

```prisma
model Recipe {
  categoryId String @meta("form.title", "Категория") @meta("form.relation.labelField", "name")

  category Category @relation(fields: [categoryId], references: [id])
}
```

⛔ `@meta("form.relation", { labelField: "name" })` с объектным литералом ломает
`zenstack generate` целиком (`Unsupported attribute arg value: ObjectExpr`) — используйте только
плоский dot-path, как выше, по одному вызову `@meta` на ключ.

## RelationFieldProvider

Оберните форму для предоставления данных связей:

```tsx
import { RelationFieldProvider } from '@letar/forms'

;<RelationFieldProvider
  relations={[{ model: 'Category', useQuery: useFindManyCategory, labelField: 'name' }]}
>
  <Form schema={RecipeCreateFormSchema} onSubmit={save}>
    <Form.Field.String name="title" />
    <Form.Field.Select name="categoryId" />
    <Form.Button.Submit>Сохранить</Form.Button.Submit>
  </Form>
</RelationFieldProvider>
```

## Связи из схемы: useZenStackRelations

Писать `relations` руками — значит заводить адаптер `useFindMany` на каждую модель. С ZenStack `useZenStackRelations`
из `@letar/forms-query/zenstack` собирает список из самой form-схемы: обходит поля с `fieldProps.relation` и берёт
`useFindMany` модели из схемы ZenStack.

```tsx
import { schema } from '@/generated/schema'
import { useZenStackRelations } from '@letar/forms-query/zenstack'

// Вне компонента: литерал в JSX пересобирал бы массив на каждом рендере
const overrides = { Category: { queryArgs: { orderBy: { name: 'asc' } }, descriptionField: 'note' } }

function RecipeForm() {
  const relations = useZenStackRelations(schema, RecipeCreateFormSchema, { overrides })

  return (
    <RelationFieldProvider relations={relations}>
      <Form schema={RecipeCreateFormSchema} onSubmit={save}>
        <Form.AutoFields />
      </Form>
    </RelationFieldProvider>
  )
}
```

- Одна модель у нескольких полей грузится один раз.
- Поля с ключом реестра `createForm` (`Select.Category`) пропускаются: такой компонент грузит данные сам.
- Модели нет в схеме ZenStack — исключение со списком доступных моделей.
- Два поля просят разные `labelField` одной модели: побеждает первое, печатается предупреждение — подпись задай в
  `overrides`.
- Третий аргумент принимает `overrides`, `exclude` и `clientOptions` (второй аргумент `useClientQueries`).

## Вторая строка опции: descriptionField

`descriptionField` — поле записи справочника, которое `Select` и `Combobox` (Chakra и shadcn) рисуют **второй строкой
под подписью в выпадающем списке**. В кнопке и в поле после выбора остаётся только подпись. Задаётся в схеме, без
кода поля:

```prisma
categoryId String @meta("form.relation.labelField", "name") @meta("form.relation.descriptionField", "note")
```

`descriptionField` в `RelationConfig` (или в `overrides` у `useZenStackRelations`) сильнее, чем в схеме. Пустое
значение — без второй строки. Локальный поиск находит и по описанию; `searchInDescription={false}` у поля это
отключает. Живой пример — `/relation-demo` в `form-develop-app`.

## Хук useRelationOptions

Доступ к опциям связей из кастомных компонентов:

```tsx
const { options, isLoading } = useRelationOptions('category')
```

## HOC withRelations

Альтернатива обёртке RelationFieldProvider:

```tsx
const RecipeForm = withRelations(BaseRecipeForm, {
  category: { useQuery: useFindManyCategory, labelField: 'name' },
})
```
