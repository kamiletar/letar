## Обзор

`@letar/zenstack-form-plugin` генерирует типобезопасные Zod v4 схемы с `.meta({ ui: {...} })` прямо из `schema.zmodel` — без ручного написания схем.

```bash
npm install @letar/zenstack-form-plugin
```

## Конфигурация

Добавьте плагин в `schema.zmodel`:

```prisma
plugin formSchema {
  provider = '@letar/zenstack-form-plugin'
  output = './src/generated/form-schemas'
}
```

Затем запустите:

```bash
npx zenstack generate
```

## Директивы `@meta("form.*", value)`

Используйте field-атрибут `@meta` прямо на поле для настройки поведения формы:

```prisma
model Product {
  id    String @id @default(cuid())

  name  String @meta("form.title", "Название товара") @meta("form.placeholder", "Введите название")

  price Decimal @meta("form.title", "Цена") @meta("form.fieldType", "currency")
    @meta("form.props.min", 0)

  categoryId String @meta("form.title", "Категория") @meta("form.relation.labelField", "name")

  createdAt DateTime @default(now()) @meta("form.exclude", true)
}
```

⛔ **Объектный литерал в `@meta` ломает `zenstack generate` целиком** — `Unhandled error:
Unsupported attribute arg value: ObjectExpr`. Это ограничение upstream-генератора TS-схемы самого
ZenStack, не нашего плагина. Поэтому `form.props` и `form.relation` (у которых объект был бы
естественным контейнером) заданы **плоским dot-path**, по одному вызову `@meta` на ключ, как
выше — никогда `@meta("form.props", { min: 0 })`. Скаляры и массивы в `@meta` работают без
проблем — блокирован только «голый» объектный литерал.

### Доступные директивы

| Директива                                | Описание                | Пример                                         |
| ------------------------------------------ | ------------------------- | ----------------------------------------------- |
| `@meta("form.title", "...")`               | Заголовок поля            | `@meta("form.title", "Название")`              |
| `@meta("form.placeholder", "...")`         | Placeholder               | `@meta("form.placeholder", "Введите...")`      |
| `@meta("form.description", "...")`         | Подсказка                 | `@meta("form.description", "Пояснение")`       |
| `@meta("form.fieldType", "...")`           | Тип компонента            | `@meta("form.fieldType", "tags")`              |
| `@meta("form.props.<dotpath>", ...)`       | Constraints + UI props    | `@meta("form.props.min", 1)`                   |
| `@meta("form.relation.<dotpath>", ...)`    | Настройки relation        | `@meta("form.relation.labelField", "name")`    |
| `@meta("form.exclude", true)`              | Исключить из формы        | `@meta("form.exclude", true)`                  |

### Legacy-синтаксис (продолжает работать, но deprecated)

Старые `///` doc-комментарии перед полем по-прежнему работают — плагин читает оба синтаксиса,
`@meta` побеждает при конфликте на одном ключе одного поля. `nx zenstack:generate` печатает
deprecation-warning при обнаружении `@form.*`-комментариев, но сборку не ломает:

```prisma
model Product {
  /// @form.title("Название товара")
  /// @form.placeholder("Введите название")
  name String
}
```

Новый код пишите на `@meta`; переписывать существующие `@form.*`-комментарии вручную не нужно,
если модель и так не редактируется.

## Генерируемый код

Для модели `Product` выше плагин генерирует:

```typescript
// src/generated/form-schemas/Product.form.ts
import { z } from 'zod/v4'

export const ProductCreateFormSchema = z.object({
  name: z.string().meta({
    ui: { title: 'Название товара', placeholder: 'Введите название' },
  }),
  price: z
    .number()
    .min(0)
    .meta({
      ui: { title: 'Цена', fieldType: 'currency' },
    }),
  categoryId: z.string().meta({
    ui: { title: 'Категория', fieldType: 'relation', fieldProps: { labelField: 'name' } },
  }),
})

export const ProductUpdateFormSchema = ProductCreateFormSchema.partial()
export type ProductCreateForm = z.infer<typeof ProductCreateFormSchema>
```

## Метки Enum

Doc-комментарии перед значениями enum становятся опциями select:

```prisma
enum Status {
  /// Активный
  ACTIVE
  /// В архиве
  ARCHIVED
  /// Черновик
  DRAFT
}
```

Генерирует:

```typescript
export const StatusFormSchema = z.enum(['ACTIVE', 'ARCHIVED', 'DRAFT']).meta({
  ui: {
    options: [
      { value: 'ACTIVE', label: 'Активный' },
      { value: 'ARCHIVED', label: 'В архиве' },
      { value: 'DRAFT', label: 'Черновик' },
    ],
  },
})
```

## Наследование нативных ZModel-атрибутов валидации

**Рекомендуемый путь.** Задавайте валидацию через нативные атрибуты ZModel, а не через
`form.props` — ORM уже применяет их на `create`/`update` через `@zenstackhq/zod`, плагин
форм наследует те же constraints в клиентскую Zod-схему, так что источник валидации остаётся
один:

```prisma
portions Int @gte(1) @lte(100) @meta("form.title", "Количество порций")

slug String @startsWith("recipe-") @trim() @lower() @meta("form.title", "Slug")

email String @email @meta("form.title", "Email")
```

Генерирует:

```typescript
portions: z.number().int().min(1).max(100).meta({ ui: { title: 'Количество порций' } })
slug: withNative(z.string(), (s) => ZodUtils.addStringValidation(s, [...])).meta({ ui: { title: 'Slug' } })
email: z.string().email().meta({ ui: { title: 'Email' } })
```

Поддерживаются: `@email`, `@length`, `@gte`/`@gt`/`@lte`/`@lt`, `@regex`, `@startsWith`,
`@endsWith`, `@contains`, `@datetime`, `@date`, `@time`, `@url`, `@phone`, `@trim`, `@lower`,
`@upper`. `@length` на списке (`String[]`) валидирует количество элементов, а не длину строки.
`Decimal`-поля поддерживают только `@gte`/`@gt`/`@lte`/`@lt` (несовместимость
`ZodUtils.addDecimalValidation` с контрактом формы `Decimal → z.number()`).

`form.props` с тем же ключом-constraint (`min`, `startsWith` и т.д., заданным через
`@meta("form.props.min", ...)`) побеждает нативный атрибут — осознанный escape hatch для
намеренного расхождения клиент/сервер, не способ задать constraint по умолчанию.

## Кросс-полевая валидация: `@@validate`

Проверки, зависящие от нескольких полей сразу, задаются на уровне модели, не поля:

```prisma
model Booking {
  id       String   @id @default(cuid())
  title    String
  startsAt DateTime
  endsAt   DateTime

  @@validate(endsAt > startsAt, "Дата окончания раньше начала", ["endsAt"])
}
```

Генерирует:

```typescript
export const BookingCreateFormSchema = withNative(
  BookingBaseSchema,
  (s) => ZodUtils.addCustomValidation(s, [{ name: '@@validate', args: [...] }]),
)
```

Сигнатура — `@@validate(condition: Boolean, message: String?, path: String[]?)`, как в стандартной
библиотеке ZModel. `condition` — произвольное булево выражение над полями модели (сравнения,
`&&`/`||`, вызовы вроде `length`/`startsWith`). `message`/`path` работают как у Zod `.refine()` —
`path` привязывает ошибку к конкретному полю вместо ошибки уровня формы.

**Ограничения:**

- **Проверку получает только `{Model}CreateFormSchema`.** `{Model}UpdateFormSchema` строится из
  внутреннего, не экспортируемого `{Model}BaseSchema` (до `.refine()`) через `.partial()` —
  у `ZodEffects` (что возвращает `.refine()`) нет метода `.partial()`, а частичный payload часто
  физически не может удовлетворить проверке, рассчитанной на полную модель. Если форме
  редактирования тоже нужна эта проверка — добавьте её отдельно на уровне формы.
- **`MemberAccessExpr` (проход через relation, `related.field`) не поддержан** — не встречался в
  `@@validate` моделей форм-плагина. Попытка его сериализовать кидает понятную ошибку кодогена, а
  не тихо портит рантайм-поведение.

### `@@strict()` — реализован, но недоступен на `model`

Кодогенерация под `@@strict()` (`z.strictObject(...)` вместо `z.object(...)`) в плагине есть, но
включить её на реальной модели нельзя: стандартная библиотека ZModel разрешает `@@strict()`
только на `type`-определениях (`zenstack generate` останавливается с «attribute '@@strict' can
only be used on type definitions» при попытке поставить его на `model`). Это ограничение самого
языка ZModel, найденное живым прогоном генерации, а не риск в коде плагина — кодогенерация
покрыта юнит-тестами и остаётся на будущее, если ZenStack расширит область действия атрибута.

## Умное разделение Props

Значения `form.props` автоматически разделяются на **Zod constraints** и **UI props**:

```prisma
portions Int @meta("form.props.min", 1) @meta("form.props.max", 100) @meta("form.props.showValue", true)
```

Генерирует:

```typescript
portions: z.number()
  .int()
  .min(1) // ← Zod constraint
  .max(100) // ← Zod constraint
  .meta({ ui: { fieldProps: { showValue: true } } }) // ← UI prop
```

**Zod constraints:** `min`, `max`, `step`, `minLength`, `maxLength`, `pattern`, `email`, `url`, `uuid`
**UI props:** всё остальное (`count`, `allowHalf`, `showValue`, `layout` и т.д.)

## Использование с @letar/forms

Сгенерированные схемы работают напрямую с `Form.FromSchema`:

```tsx
import { Form } from '@letar/forms'
import { ProductCreateFormSchema } from '@/generated/form-schemas/Product.form'

function CreateProductForm() {
  return (
    <Form.FromSchema
      schema={ProductCreateFormSchema}
      onSubmit={async (data) => createProduct(data)}
      submitLabel="Создать товар"
    />
  )
}
```

## i18n поддержка

Включите мультиязычные метки:

```prisma
plugin formSchema {
  provider = '@letar/zenstack-form-plugin'
  output = './src/generated/form-schemas'
  i18n = true
  i18nOutput = './messages/form-schemas'
  defaultLocale = 'ru'
  locales = 'ru,en'
}
```

Генерирует файлы переводов:

```json
// messages/form-schemas/ru.json
{
  "Product": {
    "name": { "title": "Название товара", "placeholder": "Введите название" }
  }
}
```

Локаль по умолчанию **перезаписывается** при каждой генерации. Другие локали используют **merge стратегию** — сохраняя ваши переводы.

## Кастомные переводы валидации

Английские и русские сообщения валидации встроены. Для других языков создайте файл переводов:

```typescript
// i18n/form-validations.js
export default {
  de: {
    required: 'Pflichtfeld',
    too_small: {
      string: 'Mindestens {minimum} Zeichen',
      number: 'Mindestens {minimum}',
    },
    too_big: {
      string: 'Maximal {maximum} Zeichen',
      number: 'Maximal {maximum}',
    },
    invalid_format: {
      email: 'Ungültige E-Mail-Adresse',
      url: 'Ungültige URL',
    },
  },
}
```

Укажите путь в schema.zmodel:

```prisma
plugin formSchema {
  provider = '@letar/zenstack-form-plugin'
  output = './src/generated/form-schemas'
  i18n = true
  defaultLocale = 'en'
  locales = 'en,de'
  validationTranslationsPath = './i18n/form-validations.js'
}
```

**Приоритет:** custom файл → встроенные (en, ru) → English fallback.

Тип `ValidationTranslations` экспортируется из пакета для типизации.

## Автоматически исключаемые поля

- `id` — первичные ключи
- `createdAt`, `updatedAt` — системные поля
- Поля с атрибутом `@id`
- Поля с атрибутом `@relation`
- Поля с атрибутом `@omit` (скрыты из ORM-клиента целиком)
- Поля с атрибутом `@computed` (вычисляются сервером)
- Поля с `@meta("form.exclude", true)` (или legacy `/// @form.exclude`)
