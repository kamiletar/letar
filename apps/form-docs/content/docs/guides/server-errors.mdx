## Overview

`mapServerErrors()` automatically detects the error format and maps it to form fields. No manual switch/case needed.

```tsx
import { applyServerErrors, mapServerErrors } from '@letar/forms'

;<Form
  schema={UserSchema}
  onSubmit={async ({ value }) => {
    try {
      await createUser(value)
    } catch (error) {
      const mapped = mapServerErrors(error, {
        fieldMap: {
          email: { field: 'email', message: 'This email is already registered' },
        },
      })
      applyServerErrors(form, mapped)
    }
  }}
>
  <Form.Field.String name="email" />
  <Form.Errors />
  <Form.Button.Submit>Create</Form.Button.Submit>
</Form>
```

## With the declarative `<Form>`

The example above uses the low-level `useAppForm` hook, where `form` is available directly from closure. The declarative wrapper (`createForm()` → `<Form onSubmit={(data) => ...}>`) is different: its `onSubmit` receives only `data`, no form instance — error handling instead goes through `middleware.onError`, which receives whatever `onSubmit`/the Server Action threw (`FormSimple` catches the exception and calls `middleware.onError`, see `libs/forms/src/lib/declarative/form-root/form-simple.tsx`).

To call `mapServerErrors`/`applyServerErrors` here, get the form instance via `useFormRef()`:

```tsx
import { applyServerErrors, mapServerErrors, useFormRef } from '@letar/forms'

function MaterialForm() {
  const formRef = useFormRef()

  async function handleSubmit(data: MaterialFormData) {
    // The Server Action just throws (Prisma/ZenStack/Error) — no manual wrapping needed
    await createMaterial(data)
  }

  return (
    <Form
      schema={MaterialSchema}
      initialValue={initialValue}
      onSubmit={handleSubmit}
      formRef={formRef}
      middleware={{
        onError: (error) => {
          const mapped = mapServerErrors(error, {
            fieldMap: { sku: { field: 'sku', message: 'This SKU is already in use' } },
          })
          if (formRef.current) {
            applyServerErrors(formRef.current, mapped)
          }
        },
      }}
    >
      <Form.Errors />
      <Form.Field.String name="sku" />
      <Form.Button.Submit>Save</Form.Button.Submit>
    </Form>
  )
}
```

Key points:

- `formRef` is passed to `<Form>` **and** used inside `middleware.onError` — without it, `applyServerErrors` has nothing to apply errors to.
- The Server Action called from `onSubmit` shouldn't catch and wrap the error itself — `mapServerErrors` parses raw Prisma/ZenStack/Zod exceptions directly.
- Don't forget `<Form.Errors />` in JSX, or `formErrors` (e.g. `P2025`/`rejected-by-policy`) get applied but never render.
- Working example: `apps/domwellbes/src/app/(admin)/admin/materials/_components/material-form.tsx`.

## useFormServerAction — the same wiring in one call

The sections above give full control over `formRef` + `middleware.onError` +
`mapServerErrors`/`applyServerErrors` — useful when error handling differs by error type. For the
typical case (just apply the error to fields + show pending + an optional toast),
`useFormServerAction` (`@letar/forms-react`) collapses this ceremony into one hook:

```tsx
import { Form, useFormRef, useFormServerAction } from '@letar/forms'

function SignupForm() {
  const formRef = useFormRef()
  const { run, pending } = useFormServerAction(formRef, {
    fieldMap: { email: { field: 'email', message: 'This email is already registered' } },
    toaster,
    successMessage: 'User created',
  })

  return (
    <Form schema={SignupSchema} initialValue={{ email: '' }} formRef={formRef}
      onSubmit={async (data) => {
        await run(() => createUser(data))
      }}
    >
      <Form.Errors />
      <Form.Field.String name="email" />
      <Form.Button.Submit loadingText="Submitting...">Create</Form.Button.Submit>
    </Form>
  )
}
```

- `run(action, onSuccess?)` calls `action`; on error it applies `mapServerErrors`/
  `applyServerErrors` and shows the toast, then **rethrows the original error** — this is
  required, not cosmetic: if `run` swallowed the error, `<Form>` would treat the submit as
  successful and its post-submit `reset()` would wipe the field errors just applied before the
  user got to see them. You still don't need your own `try/catch` in `onSubmit` — `<Form>`
  catches the exception from `onSubmit` in the same place it already catches `throw` from
  `middleware.onError`.
- On error — the same `mapServerErrors` + `applyServerErrors(formRef.current, mapped)` as above,
  plus `toaster.create({ type: 'error', ... })` if `toaster` is passed (the title comes from
  `formErrors`, falling back to the first `fieldErrors` message, then `defaultMessage`).
- On success — an optional `toaster.create({ type: 'success', title: successMessage })` and a
  call to `onSuccess?.(result)` with whatever `action` returned.
- `pending` is a boolean flag for the duration of `action`, for a custom indicator next to
  `<Form.Button.Submit loadingText="...">`.
- The low-level path (`middleware.onError` from the section above) stays fully supported — use it
  when error handling needs to differ by error type (e.g. suppress the toast for some errors).

## Rejecting a Server Action with a value — `ActionFailure`

⚠️ **In production Next.js strips the text of any error thrown from a Server Action** — the client
sees "Minified React error" (code 441) instead of the reason. So an *expected* failure (a business
rule, a duplicate of a unique value) is **returned as a value**, and the form turns it back into an
exception on the client — a client-side `throw` is not stripped. Real faults are still thrown: their
text is not for the user and belongs in the logs and error tracker.

**Server** (import from `@letar/forms/server-errors` — no React or Chakra):

```ts
'use server'
import { catchActionFailure, UserFacingError } from '@letar/forms/server-errors'

export async function createCategory(input: CategoryInput) {
  return catchActionFailure(async () => {
    if (await isNameReserved(input.name)) {
      throw new UserFacingError('This name is reserved', 'name') // the field is optional
    }
    return db.category.create({ data: input, select: { id: true } })
  }, {
    // your own texts for a duplicate: the key is the field, or fields joined by "_"
    uniqueMessages: { slug: 'This address is taken — pick another' },
    locale: 'en', // language of the generic duplicate message
  })
}
```

`catchActionFailure` catches **only** `UserFacingError` and a unique violation (SQLSTATE `23505`);
everything else is rethrown. To reject directly, `return actionFailure('Cannot delete', 'id')`.

**Client** — two ways, both put the reason under the field and into `<Form.Errors />`:

```tsx
// 1. useFormServerAction: run recognises the returned failure and throws ActionFailureError
const { run, pending } = useFormServerAction(formRef, { toaster })
await run(() => createCategory(data), () => router.push('/admin/categories/'))

// 2. Low-level: unwrapActionResult + middleware.onError
const { formRef, middleware } = useActionFormErrors()
<MyForm formRef={formRef} middleware={middleware}
  onSubmit={async (data) => { unwrapActionResult(await createCategory(data)) }}>
  <MyForm.Errors />
```

`onSuccess` and the success toast are not called on a failure.

**The marker.** A failure is `{ success: false, error: string, field?: string }`. The explicit
`success: false` matters: a successful result that happens to carry an `error` field
(`{ items, error: 'some rows skipped' }`) is **not** treated as a failure. Build it with
`actionFailure(error, field?)`, not by hand.

**Which field a duplicate lands on.** Prisma names the constraint `<Table>_<field>_key`. The field
is derived **only when the name is unambiguous** — three parts (`MaterialCategory_slug_key` →
`slug`). A composite key, a `@@map("snake_case")` table or a `@map` column has no field: `_` cannot
tell them apart from an underscore inside a name, and an error under the wrong field is worse than
a generic message. The message then comes from `uniqueMessages` (matched against the tail of the
constraint name) or falls back to a generic one.

## Supported Formats

| Format            | Example                                                 | Result                                   |
| ----------------- | ------------------------------------------------------- | ---------------------------------------- |
| Prisma P2002      | `{ code: 'P2002', meta: { target: ['email'] } }`        | `fieldErrors: [{ field: 'email' }]`      |
| Prisma P2003      | `{ code: 'P2003', meta: { field_name: 'categoryId' } }` | `fieldErrors: [{ field: 'categoryId' }]` |
| Prisma P2025      | `{ code: 'P2025' }`                                     | `formErrors: ['Record not found']`       |
| ZenStack policy   | `{ reason: 'rejected-by-policy' }`                      | `formErrors: ['Access denied']`          |
| ZenStack db-query | `{ reason: 'db-query-error', code: 'P2002', meta }`     | Delegates to Prisma parser               |
| Zod flatten       | `{ fieldErrors: { email: ['msg'] } }`                   | Direct mapping                           |
| ActionResult      | `{ success: false, error: 'msg' }`                      | `formErrors: ['msg']`                    |
| ActionFailure     | `{ success: false, error: 'msg', field: 'slug' }`       | `fieldErrors` + `formErrors`             |

## API

### mapServerErrors(error, config?)

```typescript
const mapped = mapServerErrors(error, {
  fieldMap: Record<string, { field: string; message: string }>,
  format: 'auto' | 'prisma' | 'zenstack' | 'zod' | 'action-result',
  locale: 'ru' | 'en',
  defaultMessage: 'An error occurred',
})
// Returns: { fieldErrors: FieldError[], formErrors: string[] }
```

### applyServerErrors(form, mapped)

Applies errors to TanStack Form instance via `form.setFieldMeta` and `form.setErrorMap`.

### fieldMap

Custom mapping for specific constraints:

```typescript
{
  // Single field unique constraint
  email: { field: 'email', message: 'Email already registered' },
  // Composite unique constraint (joined with _)
  organizationId_name: { field: 'name', message: 'Name already taken' },
  // Foreign key
  categoryId: { field: 'categoryId', message: 'Select a valid category' },
}
```
