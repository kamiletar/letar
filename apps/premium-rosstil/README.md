## 🚀 Быстрый старт

### Разработка

```bash
# Запуск dev-сервера
nx dev premium-rosstil  # порт 3000

# База данных
nx zenstack:generate premium-rosstil  # Генерация Prisma + Zod схем
nx db:push premium-rosstil            # Синхронизация БД (dev)
nx db:migrate premium-rosstil         # Создание миграции (prod)
nx db:studio premium-rosstil          # Prisma Studio

# Тестирование
nx lint premium-rosstil               # Линтинг
nx typecheck:tsgo premium-rosstil     # Проверка типов (tsgo - быстрее!) ⚡
nx typecheck premium-rosstil          # Проверка типов (tsc - обычная скорость)
nx format premium-rosstil             # Форматирование
nx test premium-rosstil               # Unit-тесты
nx e2e premium-rosstil-e2e            # E2E тесты (Playwright)
```

### Деплой

```bash
# Деплой приложения
./deploy-affected.sh --app premium-rosstil

# Dry run (показать что будет задеплоено)
./deploy-affected.sh --dry-run

# Принудительная пересборка
./deploy-affected.sh --app premium-rosstil --skip-cache
```

## 📝 Методология разработки

Проект следует принципам:

- **TDD (Test-Driven Development)** — сначала тест, потом код
- **Планирование в PLAN.md** — вся функциональность документируется
- **Автоматические коммиты** — после успешного завершения задачи
- **Семантическое версионирование** — patch/minor/major по характеру изменений
- **Линтинг и типизация** — обязательная проверка перед коммитом

### 📝 Обновление документации при изменениях

При внесении изменений в проект необходимо обновлять соответствующие файлы документации:

| Изменение                    | Файлы для обновления                                                    |
| ---------------------------- | ----------------------------------------------------------------------- |
| **Новая фича**               | `PLAN.md`, `PLAN_COMPLETED.md`, `CHANGELOG.md`, `package.json` (версия) |
| **Баг-фикс**                 | `CHANGELOG.md`, `package.json` (patch версия)                           |
| **Изменения БД**             | `schema.zmodel`, `ZENSTACK_USAGE.md` (если меняется логика)             |
| **Новые тесты**              | `TESTING_PLAN.md`                                                       |
| **Изменения деплоя**         | `DEPLOYMENT.md`                                                         |
| **Изменения аутентификации** | `../../.claude/docs/auth.md` (общая документация)                       |
| **Общие улучшения/прогресс** | `README.md` (секция "Текущее состояние")                                |

**Порядок обновления при завершении фичи:**

1. Обновить `package.json` — версия (semver)
2. Обновить `PLAN.md` — отметить фичу как выполненную (✅ + версия)
3. **Перенести детали фичи в `PLAN_COMPLETED.md`** — сразу после завершения, чтобы PLAN.md оставался компактным
4. Обновить `CHANGELOG.md` — добавить запись о релизе
5. Обновить `README.md` — если изменилось текущее состояние

> Подробнее о правилах документации: [CLAUDE.md](../../CLAUDE.md) — раздел "Правила документации приложений"
