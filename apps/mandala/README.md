## 🚀 Быстрый старт

### Разработка

```bash
# Запуск dev-сервера
nx dev mandala

# База данных
nx zenstack:generate mandala  # Генерация Prisma + Zod схем
nx db:push mandala            # Синхронизация БД (dev)
nx db:migrate mandala         # Создание миграции (prod)
nx db:studio mandala          # Prisma Studio

# Тестирование
nx lint mandala               # Линтинг
nx typecheck:tsgo mandala     # Проверка типов (tsgo - 1.6x быстрее!) ⚡
nx typecheck mandala          # Проверка типов (tsc - обычная скорость)
nx format mandala             # Форматирование
```

### Деплой

```bash
# Деплой приложения
./deploy-affected.sh --app mandala

# Dry run (показать что будет задеплоено)
./deploy-affected.sh --dry-run

# Принудительная пересборка
./deploy-affected.sh --app mandala --skip-cache
```

## 📝 Методология разработки

Проект следует принципам:

- **TDD (Test-Driven Development)** — сначала тест, потом код
- **Планирование в PLAN.md** — вся функциональность документируется
- **Автоматические коммиты** — после успешного завершения задачи
- **Семантическое версионирование** — patch/minor/major по характеру изменений
- **Линтинг и типизация** — обязательная проверка перед коммитом

### 📝 Обновление документации при изменениях

При внесении изменений в проект необходимо обновлять соответствующие файлы документации:

| Изменение                    | Файлы для обновления                                    |
| ---------------------------- | ------------------------------------------------------- |
| **Новая фича**               | `PLAN.md`, `PLAN_COMPLETED.md`, `package.json` (версия) |
| **Баг-фикс**                 | `package.json` (patch версия)                           |
| **Изменения БД**             | `schema.zmodel`, `PLAN.md` (раздел "Схема БД")          |
| **Общие улучшения/прогресс** | `README.md` (секция прогресса)                          |

**Порядок обновления при завершении фичи:**

1. Обновить `package.json` — версия (semver)
2. Обновить `PLAN.md` — отметить фичу как выполненную (✅ + версия)
3. **Перенести детали фичи в `PLAN_COMPLETED.md`** — сразу после завершения, чтобы PLAN.md оставался компактным
4. Обновить `README.md` — если изменился прогресс
