## Версии 0.5.1–0.6.2 (2026-09-08) — главы OP/ED + два раунда живого GUI-фидбека

### Главы OP/ED (§7)

Кнопка «Пропустить опенинг/эндинг» и маркеры глав на прогресс-баре. Главы — через ffprobe
(`main/services/ffmpeg/chapters.service.ts`), т.к. `mediainfo.js` их сознательно не отдаёт.
Классификация — `detectChapterTypes` из `@letar/video-player-react` (была реализована и
протестирована, но не экспортирована публично — попутно найденный и исправленный баг
библиотеки, 0.2.1 → 0.2.2). Чистая логика вынесена в `shared/chapter-mapping.ts` — конвенция
репозитория: `vitest.config.mts` этого класса Electron-приложений не включает `renderer/**`.

### Первый живой GUI-прогон (§14) — постер, меню, иконки сборки

Первый реальный запуск вне сендбокса (`nx dev`) дал три замечания разом. Закрыто два:

- **Постер не подгружался** — `EpisodeSidebar.posterUrl` нигде не передавался; фикс — локальный
  поиск `poster/cover/folder.jpg|png|webp` в корне папки (`fs:findPoster`), без внешних API
  (Shikimori-опознание из `animatrona` для этого приложения принципиально неприменимо).
- **Стандартное меню Electron** («File Edit View Window») убрано — `Menu.setApplicationMenu(null)`.
- Дополнительно исправлен `build:win`, падавший на отсутствующих `resources/icon.ico`/`icon-*.png`
  — скрипт генерации существовал, но никогда не запускался для этого приложения.
- Осталось открытым: выбор аудио/сабо-дорожек не начат — нужен урезанный `TrackSelector` без
  IPFS/dub-групп-веток `animatrona`; неоднозначность «кнопка закрытия» не переспрошена.

### Второй живой GUI-прогон (§15) — реальные баги плеера, не только косметика

- **Периодический спиннер посреди воспроизведения** (плеер играл ~5 сек, спиннер, продолжал с
  той же позиции — повторялось весь сеанс). Причина — `startTime` в deps главного эффекта
  `useShakaPlayer` (`@letar/video-player-react`): фоновое автосохранение прогресса просмотра
  меняло `resumeTime`, что триггерило полную пересборку Shaka Player. Фикс — снапшот через
  `startTimeRef`, эффект реагирует только на реальную смену `src`. Самый ценный фикс сессии —
  баг общей либы, не специфика приложения.
- **История открытых папок не сохранялась между перезапусками** — эффект загрузки в
  `useFolderHistory` (`@letar/folder-player-react`) имел `deps: []`, срабатывал один раз всегда
  с ещё не подменённой SSR-заглушкой (`mounted ? window.localStorage : noopStorage`). Фикс —
  `deps: [storage]`.
- **Кнопки перемотки ±10 сек нечитаемы** — `LuSkipBack/LuSkipForward` визуально совпадали с
  соседними кнопками навигации по сериям. Заменены на `LuRotateCcw/LuRotateCw` + число секунд
  поверх иконки (`SharedPlayerControls`).

Оба поведенческих бага (спиннер, история) покрыты регресс-тестами в соответствующих либах.
Выбор дорожек по-прежнему не реализован — снова назван первым пунктом фидбека, остаётся
самой заметной незакрытой дырой.

## Версии 0.2.0–0.4.0 (2026-09-08) — закрытие ограничений v0.1.0

Три задачи из списка «Известные ограничения v0.1.0» ниже закрыты последовательно в одной сессии.

### `app://` вместо `file://` (0.2.0)

Привилегированная схема `app://` (`main/protocols/app.protocol.ts`) раздаёт статический экспорт
Next.js из `renderer/out/`, с защитой резолва пути от path traversal. Снимает блокировку
Worker/WASM (нужна для будущего SubtitlesOctopus) и хак `assetPrefix: './'`. `background.ts`
грузит `loadURL('app://local/index.html')` вместо `loadFile()`.

### Детекция неподдерживаемых кодеков (0.3.0)

`renderer/app/_lib/codec-support.ts` — детерминированная проверка по данным пробы (без
`navigator.mediaCapabilities`, см. обоснование в PLAN.md §6): AVC/H.264 10-bit (Hi10P) и звук
AC3/E-AC3/DTS/DTS-HD/TrueHD блокируются, HEVC — нет (аппаратная поддержка зависит от системы).
При несовместимости вместо чёрного экрана — сообщение и кнопка «Открыть в системном плеере»
(новый IPC `app:openInSystemPlayer` → `shell.openPath`). Системные кодек-паки (K-Lite и т.п.)
не расширяют возможности Chromium изнутри — только через этот фоллбэк.

### UX-минимум плеера (0.4.0)

`fileAssociations` в `electron-builder.yml`, открытие файла двойным кликом
(`process.argv`/`open-file`/`second-instance`), `app.requestSingleInstanceLock()` (второй клик —
в уже открытом окне), drag&drop файла/папки (`webUtils.getPathForFile`), `powerSaveBlocker`
(экран не гаснет во время воспроизведения) + `backgroundThrottling: false`.

**Не проверено на этом этапе:** GUI-уровень всех трёх задач (реальная загрузка окна, чёрный
экран → сообщение → клик, двойной клик по файлу, drag&drop, спящий экран) — недоступно в
сендбоксе Claude Code, нужен живой прогон `nx dev`/`build:win` у владельца.

## Версия 0.1.0

### Реализовано (Фаза 2 — каркас, 2026-09-07/08)

- Каркас приложения сгенерирован генератором `@letar/generators:electron-app`, включая фикс
  реального бага генератора (`build:win` резолвил корень Next.js неверно из-за отсутствующего
  `renderer/package.json` — падало не только здесь, у любого свежесгенерированного
  Electron-приложения).
- Подключены общие библиотеки `@letar/folder-player-react` и `@letar/folder-scan` — сканирование
  локальной папки, выбор эпизода/дорожек, история просмотра, прогресс. IPC для диалогов выбора
  файла/папки и файловой системы (`dialog.*`, `fs.*`).
- Подключены `@letar/video-player-react`/`@letar/video-player-core` — тот же Shaka Player, что в
  `animatrona`/`animatrona-tracker`. Компонент `VideoPlayer`, общая тема (`playerSemanticTokens`
  из библиотеки, не продублирована локально).
- `MediaInfoWasmProber` — извлечение медиаданных без ffmpeg, через `mediainfo.js` (WASM).
  Реализует общий интерфейс `MediaProber` из `@letar/folder-scan`.
- Извлечение встроенных ASS/SRT-субтитров и шрифтов из MKV без ffmpeg — потоковый парсер
  `matroska-subtitles`, собственная сборка `.ass`/`.srt`-контента на стороне приложения (библиотека
  отдаёт только распарсенные поля, не готовый файл). Проверено не только typecheck/lint/build, а
  реальным воспроизведением через тот же движок рендеринга (libass), что и в проде.

### Переименование (2026-09-08)

Приложение переименовано `animatrona-player` → `animatrona-folder-player` (nx-проект, `package.json`,
`appId` в `electron-builder.yml`). Продуктовое имя «Animatrona Player» (то, что видит пользователь)
оставлено — это отдельное от внутреннего слага название.

### Исследование движка воспроизведения (2026-09-08 — 2026-09-09)

Сессия исследовательская — прикладной код не менялся, результат целиком в `PLAN.md` §20–§23.

**Задача от владельца:** плеер должен быть всеядным, как нативный. Нынешние ~4 минуты ожидания на
серию (перекодирование Hi10P в VP9, §17) — неприемлемы, а попытка потокового старта (§18) не
взлетела.

**Что установлено:**

- Транскодирование не нужно ни по какой технической причине: нативный ffmpeg декодирует Hi10P
  владельца в 25.3x реального времени многопоточно и в 4.5x — одним потоком. Это плата
  исключительно за отказ Chromium декодировать профиль, не за тяжесть формата.
- «HTML поверх видео в одном окне» в Electron невозможен (airspace problem): нативное дочернее
  окно всегда рисуется поверх HTML, `z-index` на него не действует. Эталон обратного —
  Jellyfin Media Player — работает потому, что собран на QtWebEngine, а не на Electron.
  Единственная известная реализация под Electron (Seanime, `@mpv-prism/*`) закрыта, прибита к
  Electron 42 и ставится тарболлами со своего зеркала.
- Патченный `libffmpeg.dll` отпадает: закрывает HEVC/AC3/E-AC3, но не Hi10P, и доступен только
  до Electron 29 (у нас 44).
- **libmedia (`@libmedia/avplayer` 1.3.1) сыграл в Chromium всё, что нашлось на диске** — Hi10P,
  HEVC Main 10 (x264- и x265-происхождения), MPEG-4 ASP в AVI, FLAC/AAC/AC3/E-AC3/DTS, ASS из
  контейнера, главы, переключение аудиодорожек (5–22 мс). Везде 24 fps, 0 пропусков, 0 ошибок.
  Загрузка CPU на 1080p 10 бит через WASM — примерно полядра.

**Два реальных пробела движка** (оба молчаливые, ошибок не дают):

1. Вшитые в контейнер шрифты не подключаются — слова `FontFace` нет во всей сборке libmedia.
   Диалог системным шрифтом выглядит верно, надписи дизайнерскими — нет. Чинится своим
   извлекателем вложений, который в приложении уже есть.
2. Нет API внешних аудиодорожек — только субтитры. Для папок с отдельной озвучкой синхронизацию
   придётся вести самим, против часов libmedia.

**Отдельная грабля API:** `seek()` требует BigInt; обычное число не бросает исключение, а
намертво вешает конвейер воспроизведения.

**Решение владельца:** libmedia основным движком, mpv — отдельным режимом «открыть в mpv» для
трёх остаточных случаев (внешние аудиофайлы, аппаратное декодирование на слабом железе, экзотика
вроде 4K HDR и субтитров картинкой). План перехода из восьми этапов — `PLAN.md` §23.
