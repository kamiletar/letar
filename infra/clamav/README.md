# ClamAV — сканирование загружаемых пользователями файлов

Один контейнер (`letar-clamav`) на s2, общий для приложений монорепо. Не привязан к конкретному
приложению — общая инфраструктура, поэтому живёт в `infra/`, а не внутри `apps/<name>/`.

Первый потребитель — `domwellbes` (вложения клиента в чат проекта, `ROADMAP_M8.md` §M8B.2).
Приложение подключается через `FileScanner`-интерфейс `src/lib/private-files/`, поэтому смена
сканера не трогает конвейер quarantine → scan → promote.

## Зачем он вообще нужен

Только для **недоверенного ввода** — файлов, которые загрузил не мы, а пользователь. Файлы,
которые приложение генерирует само (PDF договора, коммерческое предложение), проходят через
`origin=TRUSTED_RENDERER` и сканирование не запускают по дизайну — сканировать собственный вывод
рендерера бессмысленно.

⚠️ **Для изображений сканер — не главная защита и не лучшая.** Пересжатие картинки через `sharp`
надёжнее: на выходе получается новый файл из одних пикселей, любая вложенная нагрузка
уничтожается независимо от того, знает про неё сканер или нет. ClamAV нужен там, где пересжать
нельзя — PDF, документы, архивы.

## Честно о том, что ClamAV ловит

ClamAV уверенно находит массовое известное вредоносное ПО и заметно слабее коммерческих движков
на свежем и целевом. Это осознанный выбор: он бесплатный, работает у себя (данные не уходят
третьей стороне — существенно для 152-ФЗ), и для портала строительной компании такого уровня
достаточно. Если появится реальный поток чужих файлов — сравнивать с Kaspersky Scan Engine или
Dr.Web, они ставятся так же локально.

**Чего он не делает:** не защищает наш сервер от вредоносного файла, который бьёт по самой
обработке (уязвимость в парсере изображений) — от этого спасают лимиты размера и свежий `sharp`;
не мешает XSS через SVG/HTML — от этого спасают заголовки ответа (`Content-Disposition:
attachment` + `X-Content-Type-Options: nosniff`).

## Конфигурация

- **Память:** `mem_limit: 2g`. clamd держит распакованные базы сигнатур в памяти, это ~1.2 ГБ в
  покое. Лимит жёсткий намеренно: без него OOM-killer выбирает жертву сам и может унести
  приложение вместо сканера
- **Базы сигнатур:** том `clamav_signatures` на `/var/lib/clamav`, обновляет встроенный freshclam.
  Без тома каждый рестарт тянет ~250 МБ с зеркала, и первые минуты сканера фактически нет
- **Сеть:** `kami-network`, порт 3310 **не публикуется на хост**. У clamd нет никакой
  аутентификации — кто дотянулся до порта, тот сканирует. Тот же приём, что у `letar-redis`
- **Healthcheck:** `clamdcheck.sh` из образа спрашивает сам clamd, а не проверяет живость
  процесса — процесс жив и пока базы ещё грузятся. `start_period: 180s` под холодный старт

## Деплой

```bash
cd infra/clamav && docker compose -f docker-compose.production.yml up -d
```

Не входит в `deploy-affected.sh` — shared-инфраструктура поднимается отдельно и один раз,
приложения подключаются к работающему инстансу.

⚠️ Первый старт занимает до пары минут (загрузка баз). До перехода healthcheck в `healthy`
сканер отвечает ошибкой — приложение обязано трактовать это как `SCAN_FAILED`, а не как «чисто».

## Мониторинг

```bash
docker exec letar-clamav clamdcheck.sh
docker exec letar-clamav clamdscan --version   # версия баз сигнатур
docker stats letar-clamav --no-stream          # фактическая память против лимита 2g
```

Проверка живым тестовым файлом (EICAR — безвредная строка, которую по договорённости детектируют
все антивирусы):

```bash
docker exec letar-clamav sh -c 'echo -n "X5O!P%@AP[4\PZX54(P^)7CC)7}\$EICAR-STANDARD-ANTIVIRUS-TEST-FILE!\$H+H*" > /tmp/eicar.txt && clamdscan /tmp/eicar.txt; rm -f /tmp/eicar.txt'
```

Ожидаемый ответ — `Eicar-Signature FOUND`. Если `OK` — сканер не работает, хотя контейнер жив.

## ⚠️ Место на диске

Базы сигнатур растут и обновляются ежедневно. На s2 диск уже доходил до 92% (разбор и чистка —
2026-08-28), поэтому при отладке проблем «сканер не отвечает» проверять `df -h /` в первую
очередь: freshclam при нехватке места молча оставляет старые базы.

## ⚠️ Правило для потребителя: отказ сканера — это не «чисто»

Единственный по-настоящему опасный способ сломать этот контур — при недоступности clamd
пропустить файл как чистый. Потребитель обязан отдавать `SCAN_FAILED` и оставлять файл в
карантине. В `domwellbes` это закреплено тестом (`scanner-clamav.spec.ts`).
