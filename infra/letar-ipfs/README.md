# letar-ipfs — основной узел Kubo на s3

Перенесено из `/opt/letar-ipfs` (жил вне git с момента создания, найдено PLAN-INFRA §60) —
теперь поднимается из клона `letar` на s3, `git pull` доезжает до сервиса.

## Данные и идентичность

`/data/ipfs` на хосте — **bind mount**, не именованный Docker-том. PeerId и ключи узла хранятся
в этом каталоге на диске сервера, а не в томе, привязанном к имени compose-проекта — перенос
compose-файла в другую директорию их не затрагивает и не пересоздаёт.

Проверить, что PeerId не изменился после переноса/пересоздания контейнера:

```bash
docker exec kubo ipfs id -f '<id>'
```

Baseline на момент переноса (2026-09-02): `12D3KooWM7KtRLjqRmJzva7Qy5KZzfaLES4Fk8GgnjabbWoo8A52`.

## Порты

- `4001` — p2p swarm, публичный
- `127.0.0.1:5001` — API, только localhost
- `127.0.0.1:8080` — Gateway, только localhost (перед ним nginx/Traefik)

## Не путать с

`infra/animatrona-pinner3/` и `infra/animatrona-pin-queue/` — другие Kubo-инстансы того же
монорепо (пиннер, не основной узел), исторически перепутанные при поиске файла для правки
`BIND_ADDR`/портов (см. PLAN-INFRA §60, «три промаха подряд»).
