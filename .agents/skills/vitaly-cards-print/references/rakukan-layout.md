## Сетка 914 × 280 мм

| Параметр                    | Значение, мм |
| --------------------------- | ------------ |
| Грубая карточка             | 92 × 104     |
| Шаг столбцов / промежуток   | 96 / 4       |
| Поля слева и справа         | 27           |
| Верх первого / второго ряда | 22 / 136     |
| Шаг рядов / промежуток      | 114 / 10     |

Наружный лист: `x = 27 + 96 × c`, `y = 22 + 114 × r`, где `c = 0…8`, `r = 0…1`.
Первый ряд студийный, ID S01…S09 слева направо; второй личный, P01…P09.
Внутренний лист: `x = 914 − x_наружный − 92`, тот же y, ID сохраняются.
Слева направо на обороте номера идут S09…S01 и P09…P01.

Центры крестов наружного листа: R1 (15; 12), R2 (899; 12), R3 (15; 258), R4 (899; 258).
На внутреннем листе для каждого креста x заменяется на `914 − x`, y сохраняется.
На просвет сверять R1 с R1 и т. д. Надписи с обратной стороны на просвет зеркальны — это нормально.

## Источники и файлы

Корень проекта: `C:/web/letar`. Артефакты: `C:/web/letar/.claude/artifacts/cards/`.
Артефакты игнорируются Git и могут отсутствовать на другой машине. Если их нет, геометрия
в скилле и этой справке достаточна для восстановления; отсутствие артефактов не повод
просить Kami повторить технологию.

- `rakukan.html` — стороны визиток и небольшие пробные листы.
- `rakukan-roll.js` — сетка 914 мм, перестановка оборотов и внутренние направляющие.
- `rakukan-inner.js` — внутренние тексты с ручными переносами.
- `render-roll.cjs` — экспорт и проверка координат, строк, ориентации и скрытия направляющих.
- `verify-pdf-text.py` — независимая проверка границ букв в финальном PDF.
- `rakukan-914-outer.pdf` — первый проход; `rakukan-914-inner.pdf` — второй.
- `rakukan-914-inner-guides.png` и `rakukan-inner-card-guides.png` — экранные схемы зон.
- `PRINT-914-README.md` — инструкция двух проходов; `PRINT-README.md` — небольшие техпробы.
- `roll-layout-checks.json`, `roll-pdf-checks.json`, `roll-qr-checks.json` — результаты проверок.

Макеты открываются локально через браузер: `?roll=outer`, `?roll=inner`,
`?roll=inner&guides=1`. Прямые стороны: `?faces&seal=14`; это превью, а не спуск для печати.

Из корня проекта:

```powershell
node .claude/artifacts/cards/render-roll.cjs
# Python с pypdf; путь к runtime определить в текущем окружении.
python .claude/artifacts/cards/normalize-pdf.py --roll-only
pdftoppm -png -r 150 -singlefile .claude/artifacts/cards/rakukan-914-outer.pdf .claude/artifacts/cards/rakukan-914-outer-render
node .claude/artifacts/cards/check-qrs.cjs --roll
```

Текущий экспорт использует Playwright и установленный Chrome. Скрипт QR использует ZXing
в режиме прямого квадрата `PURE_BARCODE`: он проверяет содержимое кода из PDF, но не заменяет
сканирование камеры на бумаге. Сохраняй действующие средства экспорта; если меняешь среду,
проверь доступность зависимостей и пути вместо жёсткого копирования чужого runtime.

## Оформление и актуальность

У «Ракукан» белый фон без заливок, чёрный текст, красная печать `#C23A2B`;
Literata и JetBrains Mono. Обе печати **14 мм** по решению Kami 2026-10-24 (ST-049),
справа и снизу на лице по **7 мм**. Имя на личной карточке увеличено до 19,2 pt.
Внутри Literata 8,7 pt / 1,26, заголовки 10 pt / 1,16; переносы заданы вручную.
Личная 神樂, студийная 悅; зафиксированные контуры и обработку краёв не перестраивать ради
технологической правки. Файлы — `seals/v2/kagura/*-edges-red.svg` и `seals/v2/etsu/*-edges-red.svg`.

Дизайн, задания и история: `apps/studio/docs/cards-rakukan-handoff.md`, ST-036/037/046/047.
Бумажная приёмка — ST-038. Внутренние тексты внесены в пробные PDF по поручению Kami в ST-049.
Старые brief-файлы описывают первоначальный односторонний вариант со склейкой и поворотами,
которые были заменены по фотографиям Kami. Для изготовления использовать актуальный скилл.
