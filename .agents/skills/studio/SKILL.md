# Studio Letar - Воркфлоу разработки

## Инициализация

1. Прочитай `.claude/rules/nextjs-apps.md` для общих правил Next.js
2. ⚠️ **Очередь задач — `apps/studio/tasks/`** (формат — [tasks-per-file](/.claude/docs/tasks-per-file.md)).
   Прочитай [`tasks/README.md`](/apps/studio/tasks/README.md) и выполни
   `bun scripts/tasks.mjs next studio`. Вызов с id (`/studio ST-003`) — сразу
   `bun scripts/tasks.mjs show ST-003`. `PLAN.md`, `PLAN_COMPLETED.md`, `PLAN_TESTING.md`
   **заморожены** и остаются справкой: целиком их не читать (370 КБ и больше), открывать только
   раздел из поля `source` выбранной задачи (`grep -n` и `Read` с `offset`)

## Регистрация в Agent Mail

Фиксированное имя агента: `studio-dev`. Общий шаблон вызова `macro_start_session` —
см. `.claude/rules/app-workflow.md`.

## Учёт времени

Сразу стартуй таймер `time_start({ app: "studio", ... })` — общий шаблон и правила
переключения/остановки см. `.claude/rules/app-workflow.md` и `.claude/rules/time-tracking.md`.

## Действия

После изучения документации:

- Выбери задачу из «можно брать», `start ST-NNN --owner studio-dev`
- План с acceptance-критериями запиши в раздел «План» файла задачи и предложи его
- Находку вне задачи заводи через `tasks new studio …`, не абзацем в плане

## После завершения задачи

`bun scripts/tasks.mjs done ST-NNN --summary "…"`, дальше общий чек-лист — `.claude/rules/app-workflow.md`.

## Деплой

Запрещено деплоить самостоятельно — см. `.claude/rules/app-workflow.md`.

## 152-ФЗ

⚠️ **Любая форма, собирающая персональные данные, ОБЯЗАНА:**

- Записывать `ConsentLog` (IP, user-agent, timestamp, тип согласия)
- Содержать чекбокс согласия с ссылкой на `/privacy/`
- Использовать `recordConsent()` из `src/lib/consent.ts`

Нарушение требований 152-ФЗ недопустимо.

## Особенности проекта

### Партнёрская программа

При запросах про партнёров, реферальные ссылки, начисления или вывод сначала прочитай
[references/partner-workflow.md](references/partner-workflow.md). Там указаны действующие
источники решений, порядок проверки банковского продукта и ошибки прошлой проработки.
При возвратах, миграциях финансового журнала и тестах его прав доступа прочитай также
раздел «Возвраты и проверка журнала» в этом справочнике.
Бизнес-правила и тарифы хранятся в документации Studio, а не в скилле.

### Визитки у Виталия

Для макетов, двух проходов на плоттере, переворота листа, сгиба и реза используй
[vitaly-cards-print](../vitaly-cards-print/SKILL.md). Там сохранён профиль 914 мм,
ориентация домиком и внутреннего текста; не восстанавливай технологию по старым brief-файлам.

### Роли

- `OWNER` — владелец студии (единственный, ты сам). Полный доступ: CRM, проекты, счета, финансы
- `CLIENT` — клиент студии. Только свои проекты и счета

### Личный кабинет владельца `/owner/`

- CRM клиентов, проекты, выставление счетов, финансы
- Только для роли `OWNER`

### Кабинет клиента `/cabinet/`

- Просмотр своих проектов и счетов
- Только для роли `CLIENT`

### Точка Банк интеграция

- OAuth 2.0 подключается один раз в `/owner/settings/`
- Webhook `POST /api/webhooks/tochka` — автозакрытие счетов при поступлении оплаты
- Логика в `src/lib/tochka/`
- Секрет подписи webhook: `TOCHKA_WEBHOOK_SECRET` в `.env.local`

### Счета

- Номера формата `INV-YYYY-NNN`
- Суммы хранятся в **копейках** (Int)
- Статусы: `DRAFT → SENT → PAID / OVERDUE / CANCELLED`
- При создании счёта — email клиенту со ссылкой на `/cabinet/invoices/[id]/`
