# Kami - Воркфлоу разработки

## Инициализация

1. Прочитай `.claude/rules/nextjs-apps.md` для общих правил Next.js
2. ⚠️ **Очередь задач — `apps/kami/tasks/`** (формат — [tasks-per-file](/.claude/docs/tasks-per-file.md)).
   Прочитай [`tasks/README.md`](/apps/kami/tasks/README.md) и выполни
   `bun scripts/tasks.mjs next kami`. Вызов с id (`/kami KM-003`) — сразу
   `bun scripts/tasks.mjs show KM-003`. `PLAN.md`, `PLAN_COMPLETED.md` и `PLAN_TESTING.md` **заморожены** и остаются справкой: целиком их не
   читать, открывать только раздел из поля `source` выбранной задачи (`grep -n` и `Read` с `offset`)

## Регистрация в Agent Mail

Фиксированное имя агента: `kami-dev`. Общий шаблон вызова `macro_start_session` —
см. `.claude/rules/app-workflow.md`.

## Учёт времени

Сразу стартуй таймер `time_start({ app: "kami", ... })` — общий шаблон и правила
переключения/остановки см. `.claude/rules/app-workflow.md` и `.claude/rules/time-tracking.md`.

## Действия

После изучения документации:

- Выбери задачу из «можно брать», `start KM-NNN --owner kami-dev`
- План работы запиши в раздел «План» файла задачи и предложи его
- Находку вне задачи заводи через `tasks new kami …`, не абзацем в плане

## После завершения задачи

`bun scripts/tasks.mjs done KM-NNN --summary "…"`, дальше общий чек-лист — `.claude/rules/app-workflow.md`.

## Главная, контакты и буквенный фон

При изменениях публичного меню или анимации прочитай [проверенные решения и границы приёмки](references/public-entry.md).

Обязательные условия текущего дизайна (меняются по новому указанию владельца):

- Контакты — отдельная страница `/contacts/`, английская `/en/contacts/`. Меню не заменяет её прокруткой главной.
- Адреса главной, шапки, Drawer и подвала берутся из `apps/kami/src/lib/public-navigation.ts`; стеклянные подложки относятся к пунктам главного меню.
- Буквенный фон сохраняет исходные тексты, поддерживает reduced-motion и не создаётся в админке.
- Замеры Canvas и мобильная раскладка на компьютере не подтверждают производительность физического телефона. Синтетические pagehide/pageshow не доказывают BFCache.

## Типичные ошибки и подводные камни

- Якорь `/#contacts` вместо самостоятельной страницы: используй общий источник навигации и проверь прямое открытие и reload обеих локалей (исправление владельца, KM-026).
- Приёмка анимации по одним headless-замерам: отдели доказанное от непроверенного и сохрани незавершённую проверку физических устройств в задаче. Порог автоматического снижения качества не равен измеренному FPS.
