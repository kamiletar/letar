# Обслуживание локального Agent Mail

Читай при повторных отказах регистрации/смены contact policy, настройке default или
восстановлении контейнера. Основание — выполненная задача LT-083, коммит `b7b71e15d` и
исправление Kami: настраивать нужный default на сервере вместо повторной смены в каждом чате.
Проверено на локальной Python-версии Agent Mail; на другую установку автоматически не переносить.

## Диагностика и выбор решения

1. Сопоставь ошибку с [.claude/rules/agent-mail.md](/.claude/rules/agent-mail.md) и
   [особенностями сервера](/.claude/docs/agent-mail-server-quirks.md). `Contact approval required`,
   несовместимое имя получателя и отказ автопроверки — разные причины.
2. Для повторяющегося отказа `set_contact_policy(open)` проверь стартовые инструкции и
   фактический default модели. В LT-083 нашли обязательный вызов в двух правилах и шести
   скиллах; в контейнере `Agent.contact_policy` был `Field(default="auto")`, настройки через
   окружение для него не было. Не предполагай, что другая версия сервера устроена так же.
3. По умолчанию используй поддерживаемый локальный патч из `infra/agent-mail/`, а не разовую
   смену политики в каждом чате. Default `open` относится к новым агентам; существующие записи
   сохраняют прежние значения. Отдельно согласуй проект и перевод существующих `auto`.

## Обязательные условия применения

- Сначала проверь поручение пользователя: само чтение этого справочника не разрешает менять
  политики, мигрировать БД, перезапускать общий сервер или обходить отказ автопроверки.
- При согласованной миграции используй `--migrate-auto --project <согласованный-slug>`:
  скрипт создаёт SQLite backup в `/data/backups/`, меняет только `auto` выбранного проекта и
  сохраняет `block_all`, `contacts_only` и другие проекты. Не выводи backup и токены в лог.
- Следуй [infra/agent-mail/README.md](/infra/agent-mail/README.md) для применения на контейнере.
  Без флага миграции патч меняет только модель. После применения к работающему контейнеру
  требуется restart; live-проверку выполняй после него.
- При пересоздании нужен `letar/agent-mail:open-default`: чистый апстрим вернёт `auto`.
  Сохрани текущие env, сеть, алиас, порт и volume `/data`. Dockerfile закрепляет upstream digest;
  обновление апстрима требует отдельной проверки совместимости патча.

Проверенные команды из корня репозитория:

```powershell
python -X utf8 -m unittest discover -s infra/agent-mail -p test_open_contact_default.py
docker build -t letar/agent-mail:open-default infra/agent-mail
```

Проверка собранного образа без сети, токенов и рабочей БД:

```powershell
docker run --rm --network none --entrypoint /app/.venv/bin/python letar/agent-mail:open-default -c 'from mcp_agent_mail.models import Agent; a=Agent(project_id=1,name="test",program="test",model="test"); assert a.contact_policy == "open"; assert a.attachments_policy == "auto"'
```

Проверяй отдельно модель в образе, модель рабочего контейнера после restart и агрегаты политик
БД. В LT-083 получили 426 `open` и сохранили 8 `block_all`; это исторический результат,
а не ожидаемые количества для следующих запусков. Не создавай тестовые identity в рабочей БД.

## Типичные ошибки и подводные камни

- Повторный `set_contact_policy(open)` при каждом старте вызывал отказы автопроверки. Локальный
  сервер уже создаёт агентов с `open`; правила и скиллы должны сохранять эту настройку.
- Собранный образ ещё не доказывает изменение работающего контейнера. Патч в писчем слое
  переживает restart, но не пересоздание из чистого апстрима. В LT-083 выполнен live-патч и restart;
  пересоздание из нового образа в этой сессии не проверялось.
- `with sqlite3.connect(...)` управляет транзакцией, но не закрывает соединение. На Windows
  из-за этого не удалялась временная тестовая БД; в патче и тестах использован `contextlib.closing`.
- `Path.write_text` на Windows создал CRLF, и pre-commit dprint отклонил скиллы. Записывай
  изменяемые текстовые файлы с `newline="\n"`, затем запускай `bun scripts/sync-agent-skills.ts`
  и `bun scripts/sync-agent-skills.ts --check`. Claude-копию руками не редактируй.
- Неизвестный default апстрима нельзя молча заменять на `open`: патч останавливается,
  сохраняя исходник, чтобы изменение семантики не прошло незамеченным.

## Изолированные сценарии

[../evals/evals.json](../evals/evals.json) содержит три промпта и команды воспроизведения
на временных моделях и SQLite. Команды запускай из указанного `cwd` относительно корня репо.
Они проверяют технические действия, а не самостоятельный выбор скилла другим агентом;
не выдавай успешный unittest за независимую оценку поведения модели.
