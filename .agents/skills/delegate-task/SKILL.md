# Делегирование задания чипом

Связка «сеньор → исполнитель»: сеньор решает и пишет задание, исполнитель делает по нему, сеньор
проверяет отчёт. Чип — отдельная сессия, которую владелец видит в сайдбаре. У `spawn_task` нет
параметра модели, поэтому модель ставится **после** старта, а первый ход исполнителя пустой.

## Чип или субагент

| Когда                                                        | Чем                                          |
| ------------------------------------------------------------ | -------------------------------------------- |
| Задание на часы, несколько этапов, владелец хочет видеть ход | чип (этот скил)                              |
| Кусок на минуты, результат нужен прямо в этом ходе           | субагент `middle-dev` (Agent tool, `sonnet`) |

## Какую модель брать

Решает сеньор по каждому заданию и пишет выбор с причиной в шапку задания.

| Модель, усилие                | Когда                                                                                                                                           |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `claude-sonnet-5-5`, `medium` | **по умолчанию** — решения приняты в задании: код и тесты по спецификации, замер по протоколу, правка доков                                     |
| `claude-sonnet-5-5`, `high`   | длинная цепочка этапов с приёмкой по цифрам; отладка внутри заданного плана                                                                     |
| `claude-opus-5-5`, `high`     | надо **выбрать** подход: архитектура, неясная причина сбоя, политики доступа и безопасность, миграция прод-данных, сквозной рефакторинг `libs/` |
| `claude-opus-5-5`, `xhigh`    | редко: исследование без готового ответа, высокая цена ошибки                                                                                    |

Если задание требует решать самому — это не задание мидлу. Сначала реши и допиши, потом отдавай.

## Где лежит задание

- **У проекта есть `tasks/`** — заданием служит файл задачи (`bun scripts/tasks.mjs show <ID>` печатает
  путь). Отдельный md не создаётся. Сеньор пишет решения в «План» (что делать, какие файлы, чего не
  делать) и «Приёмку» (как проверить), ставит `start <ID> --owner <agent>`. Выбор модели и причина —
  строкой в «Журнал» (`note <ID> "модель claude-sonnet-5-5, medium: решения приняты"`). Отчёт исполнитель
  пишет в «Итог» (`done <ID> --summary "…"`), находки вне задачи заводит `tasks new`.
- **Проекта с `tasks/` нет** — md в `.claude/artifacts/tasks/<тема>-NN-*.md` с шапкой ниже, находки в
  `.claude/artifacts/tasks/BACKLOG.md`.

## Шаги

1. **Шапка задания.** Для файла задачи — поле `owner` (= имя в Agent Mail) и запись про модель в
   журнале; для отдельного md — YAML в начале файла:
   ```yaml
   ---
   model: claude-sonnet-5-5
   effort: medium
   why: решения приняты, код и тесты по спецификации
   agent: repo-dev-scout-e0   # имя в Agent Mail: <app>-dev-<задача>
   ---
   ```
2. **Чип** — `spawn_task`. `title` — глагол + предмет. `prompt` строго такой (подставь путь и имя):
   ```
   Первый ход: ничего не читай и не запускай. Ответь одной строкой «Жду сигнала сеньора» и заверши ход —
   сеньор выставит модель, она действует со следующего хода.

   Когда придёт «Начинай» (или пользователь напишет «начинай»): выполни задание
   <путь к файлу задачи или к md-заданию> целиком. В Agent Mail регистрируйся под именем
   <agent> (правило .claude/rules/agent-mail.md, раздел про временное имя). Отчёт — в «Итог» файла
   задачи (`bun scripts/tasks.mjs done <ID> --summary`) либо в файл, указанный в md-задании. Таймер studio: <вести по проекту X | не вести — инфраструктура>.
   ```
3. **Уведомление о старте** («The user started your suggested background task …»):
   - `list_sessions` → сессия с тем же `title`, `isRunning` → её `sessionId` (`local_…`);
   - `set_session_model` и `set_session_effort` из шапки задания;
   - `get_session` — сверь, что `model` и `effort` применились;
   - `SendMessage` с `to: "<sessionId>"`: «Начинай. Модель <model>, усилие <effort>.»
4. Владельцу — одна строка: какая сессия, модель и усилие.
5. **Отчёт пришёл** (уведомление о завершении чипа) — аудит: diff каждого коммита, перепроверка
   цифр командой из отчёта; находки — задачи через `tasks new` (или `BACKLOG.md`, если `tasks/` нет).

## Ловушки

- ⚠️ Смена модели не трогает ход, который уже идёт. Поэтому первый ход пустой. Без него всё
  задание пройдёт одним длинным ходом на модели по умолчанию.
- Чип могут запустить, когда этой сессии уже нет. Тогда сигнала не будет: владелец выставит модель
  в меню и напишет «начинай» — промпт это предусматривает.
- Модель дороже текущей сессии или чужая сессия — приложение спросит владельца. Это норма, не ошибка.
- Опус не выставляй «на всякий случай»: дорогая модель тратится на решения, а решения уже в задании.
