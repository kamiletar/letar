# VK Audio Downloader 1.2.0

Python 3.10+ скрипт для скачивания аудио VK через браузерную сессию Brave или API-токен.
Принимает ID, `audios<ID>`, `id<ID>` и ссылки на профили с короткими именами. Несколько профилей
обрабатываются последовательно, аудиофайлы внутри профиля — параллельно, по умолчанию в 6 потоков.

## Быстрый запуск в PowerShell

```powershell
cd C:\web\letar\scripts\vk-audio
python -m pip install -r requirements.txt
python downloader.py https://vk.ru/audios20157923 --browser brave --limit 3 --check
```

Для HLS-аудио нужен установленный `ffmpeg` в PATH. На текущем компьютере он уже доступен.
Если тест доступа прошёл, пробная загрузка и полная библиотека:

```powershell
python downloader.py https://vk.ru/audios20157923 --browser brave --limit 3
python downloader.py https://vk.ru/audios20157923 --browser brave
```

## Cookies из Brave

Скрипт читает только cookies VK из Brave через `browser-cookie3`. Другой профиль можно выбрать
через `--brave-profile "Profile 1"`. Файл cookies может быть заблокирован открытым Brave;
в этом случае полностью закройте браузер на время импорта или используйте локальный экспорт.
Поддержка шифрования зависит от версии Brave/Windows; скрипт не отключает защиту браузера.

Для экспорта без расширений:

1. В Brave откройте `https://vk.ru/audios20157923` в своём аккаунте.
2. DevTools → Network → обновите страницу → выберите запрос страницы VK.
3. В Headers → Request Headers скопируйте полное значение `Cookie`.
4. Сохраните его одной строкой в `cookies-header.txt` рядом со скриптом:

   ```text
   remixsid=значение; remixnsid=значение; другие_параметры=значения
   ```

5. Проверьте доступ и скачайте первые три записи:

```powershell
python downloader.py https://vk.ru/audios20157923 --cookies cookies-header.txt --limit 3 --check
python downloader.py https://vk.ru/audios20157923 --cookies cookies-header.txt --limit 3
```

Ключевая cookie авторизации — `remixsid` (или `remixsid6`). Полная строка Cookie сохраняет
дополнительные параметры сессии. Файлы `cookies*.txt/json` исключены из Git.
Также поддерживаются Netscape TXT с HttpOnly-cookie и JSON-экспорт массива cookies.
Cookies не печатаются в логи и не добавляются к запросам на CDN музыки.
Веб-режим не требует создания приложения VK или отдельного API-токена.
Поскольку веб-протокол VK может измениться, доступ проверяется на реальной сессии режимом `--check`.
Для веб-режима надёжнее использовать числовые ID; неоднозначное короткое имя вызывает ошибку.

Если аргументы не указаны, целевой ID по умолчанию — `20157923`.
При запуске из этой папки файлы и логи сохраняются в `vk_downloaded_music/`.
При запуске из другой папки `--output` считается относительно текущего рабочего каталога,
а `.env` по умолчанию читается рядом с `downloader.py`.
Переменные окружения имеют приоритет над `.env`; другой файл можно указать через `--env`.

Изолированная установка для нового окружения:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe downloader.py https://vk.ru/audios20157923
```

## Токен и доступ к audio.get

Альтернативный API-режим выбирается через `--api`. Запишите токен в `.env`:

```dotenv
VK_ACCESS_TOKEN=ваш_пользовательский_токен
VK_API_VERSION=5.199
```

```powershell
python downloader.py https://vk.ru/audios20157923 --api --check
```

Без явно выбранного источника скрипт использует токен из окружения, если он задан, иначе Brave.

Право `audio` само по себе **не даёт доступ к чтению музыки**. Документация библиотеки
[VkUserPermissions.AUDIO](https://vk-api.readthedocs.io/en/latest/enums.html)
указывает: без доступа приложения к закрытому аудио API разрешена только загрузка аудио в VK.
Открытый профиль пользователя также не снимает ограничение приложения.

Нужен пользовательский Access Token приложения, которому VK разрешил `audio.get`.
Токен сообщества, сервисный ключ и токен только для авторизации VK ID для этой задачи не подходят.
Создание обычного нового Standalone-приложения не гарантирует доступ к аудио.

Если у вас уже есть такое Standalone-приложение и для него доступен Implicit Flow:

1. Возьмите его `client_id` в кабинете разработчика VK.
2. Подставьте ID вместо `YOUR_CLIENT_ID` и откройте в браузере запрос авторизации:

   ```text
   https://oauth.vk.ru/authorize?client_id=YOUR_CLIENT_ID&display=page&redirect_uri=https%3A%2F%2Foauth.vk.ru%2Fblank.html&scope=audio&response_type=token&v=5.199
   ```

3. Войдите в свой аккаунт на странице VK и подтвердите запрошенный доступ.
4. При успешном перенаправлении возьмите значение `access_token` из фрагмента адреса
   `#access_token=...&expires_in=...`. Сохраните только значение токена в локальном `.env`.
5. Запустите `--check`. Код VK 5 означает проблему авторизации; 7/15 может означать
   запрет метода или недоступный список. Проверка выдаёт сообщение и ненулевой код завершения.

Это условный путь для приложения с нужным доступом. Если VK отклоняет этот OAuth flow
или у приложения нет доступа к аудио API, добавление `scope=audio` проблему не решит.
Универсального гарантированного способа получить такой токен через новое Standalone-приложение нет.
Текущий код библиотеки использует этот OAuth endpoint и `response_type=token`:
[vk_api.py](https://github.com/python273/vk_api/blob/master/vk_api/vk_api.py).

Токен храните локально; `.env`, виртуальное окружение, MP3 и логи исключены из Git.
Скрипт не выводит токен или прямые URL в терминал и логи.

## Несколько профилей

```powershell
python downloader.py https://vk.ru/id12345 https://vk.ru/example_profile --workers 6
```

При нескольких аргументах создаются подпапки `vk_downloaded_music/<owner_id>/`,
а `download.log` и `skipped.log` остаются в общей папке. При одном аргументе MP3 лежат
непосредственно в `--output`. Для повторного запуска используйте ту же команду и папку.
Если продолжаете один профиль из предыдущего пакетного запуска, задайте его подпапку явно:

```powershell
python downloader.py 12345 --output .\vk_downloaded_music\12345
```

Повторные аргументы одного профиля обрабатываются один раз.
Одна ошибка получения списка не мешает обработке следующих профилей.
Ссылки на отдельные `audio_playlist...` не поддерживаются: эта версия скачивает библиотеки профилей.

Если часть HLS-треков завершилась ошибками, получите свежие ссылки только для них:

```powershell
python downloader.py https://vk.ru/audios20157923 --cookies cookies-header.txt --retry-errors
```

Режим использует последнее состояние записей из `download.log`: успешно скачанные повторно
не обрабатываются. В веб-режиме хэши/URL обновляются только для неудачных audio ID; полный список
названий сохраняется, чтобы суффиксы при совпадающих именах оставались теми же.
`--retry-errors` и `--limit` используются отдельно. Текст ошибки ffmpeg не содержит URL потока.

## Поведение при скачивании

- В API-режиме первый `audio.get` запрашивает `count=2000` **без offset**. Если ответ содержит все 1500 записей,
  дополнительного запроса списка нет. Если `count` в ответе больше числа полученных записей,
  скрипт получает оставшиеся страницы со смещением. Неполный/повторяющийся ответ считается ошибкой.
- Счётчик использует число реально полученных уникальных записей, а не фиксированное 1500.
- Пустые URL записываются в `skipped.log`. Ошибки загрузки и повторы — в `download.log`.
- Имена: `Исполнитель - Название.mp3`. Запрещённые символы и управляющие знаки заменяются `_`;
  служебные имена Windows и чрезмерно длинные названия также обрабатываются.
- При совпадающих именах добавляется суффикс из хеша audio ID, чтобы разные записи не перезаписали друг друга.
- Ненулевые готовые MP3 пропускаются. Загрузка идёт в `.mp3.part`, итоговый MP3 появляется
  только после успешного ответа и проверки размера/признаков MP3. Существующие ненулевые файлы
  считаются готовыми; целостность файлов, ранее скачанных другими программами, не проверяется.
- Таймауты, разрыв соединения, 429 и 5xx: исходная попытка + **до 3 повторов**.
  Задержки 1/2/4 секунды; `Retry-After` может увеличить ожидание до 300 секунд.
  403/404 и другие постоянные ошибки повторно не запрашиваются.
- Прямые ссылки `.m3u8` скачиваются и преобразуются в MP3 через `ffmpeg` (`libmp3lame`, качество `-q:a 2`).
  Для HLS с AAC это дополнительное кодирование с потерями. Конвертация пишет `.part`, готовый MP3
  появляется после проверки; при остановке дочерний процесс завершает работу.
- HTML, JSON и другие ответы без признаков MP3 считаются ошибкой. Проверка сигнатуры не заменяет
  полное декодирование аудио. HLS-ссылки должны иметь `.m3u8` в пути URL.
- `Ctrl+C` прекращает очередь и текущие загрузки после выхода из сетевого ожидания.
  Готовые MP3 сохраняются; незавершённый трек при повторном запуске скачивается заново целиком.
- Отчёт: скачано, уже на диске, без URL, ошибки загрузки и ошибки получения списков.
  Код завершения: `0` — успешно, `1` — ошибки, `2` — отсутствующий токен/ошибка аргументов, `130` — остановка.

Лимит потоков можно уменьшить до 1 или увеличить до 8. Число потоков не гарантирует отсутствие
ограничений со стороны VK; если часто появляются 429, уменьшите `--workers`.

## Проверки

```powershell
python -m unittest -v
```

Тесты используют локальный HTTP-сервер: MP3, 429/503, обрыв ответа, пустой файл, HTML,
повторный запуск и параллельные загрузки с одинаковыми именами. Также проверяются запрос
1500 записей за один вызов, страницы, разрешение профилей и отсутствие токена в ошибках.
Также проверяются Cookie-header/Netscape/JSON, фильтрация доменов, веб-списки и реальное
преобразование тестового HLS через ffmpeg. Настоящий ответ VK и число доступных треков
подтверждаются только запуском с рабочей браузерной сессией или подходящим API-токеном.
