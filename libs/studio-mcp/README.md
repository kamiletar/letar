# @letar/studio-mcp

MCP-сервер: Claude Code агент полностью управляет студией напрямую — клиенты, проекты, счета,
абонентки — вместо ручной работы через `/owner/*` в браузере.

Тонкий HTTP-слой над `/api/mcp/admin/*` в studio — вся бизнес-логика (валидация схем, нумерация
счетов, пересчёт аванса, email-уведомления) остаётся там, см. `apps/studio/src/app/api/mcp/admin/**`.
Роуты переиспользуют те же Zod-схемы, что и Server Actions владельческой панели
(`ClientUpsertSchema`, `ProjectUpsertSchema`, `RecurringUpsertSchema`, `InvoiceUpsertSchema`) —
одна валидация, два способа её вызвать (браузер владельца vs агент).

## Инструменты

Суммы денег во всех инструментах — **в рублях** (агент считает как человек), конвертация в
копейки — внутри (`money.ts`). API studio ожидает копейки — это деталь эндпоинта, не тула.

### Клиенты

| Инструмент                          | Действие                                                     |
| ----------------------------------- | ------------------------------------------------------------ |
| `studio_client_list({ search? })`   | Список клиентов, с числом проектов/счетов                    |
| `studio_client_get({ id })`         | Карточка клиента: реквизиты, проекты, счётчики               |
| `studio_client_create({ ... })`     | Новый клиент                                                 |
| `studio_client_update({ id, ... })` | Полная замена реквизитов (как форма редактирования, не патч) |

Удаление клиента (анонимизация 152-ФЗ) сюда намеренно не вынесено — необратимая операция над
персональными данными, доступна только в `/owner/clients`.

### Проекты

| Инструмент                                    | Действие                  |
| --------------------------------------------- | ------------------------- |
| `studio_project_list({ clientId?, status? })` | Список проектов           |
| `studio_project_get({ id })`                  | Карточка: этапы, счётчики |
| `studio_project_create({ ... })`              | Новый проект у клиента    |
| `studio_project_update({ id, ... })`          | Полная замена полей       |
| `studio_project_set_status({ id, status })`   | Смена только статуса      |

### Абонентки (`RecurringInvoice`)

| Инструмент                                | Действие                                                                  |
| ----------------------------------------- | ------------------------------------------------------------------------- |
| `studio_recurring_list({ clientId? })`    | Список абонентских правил                                                 |
| `studio_recurring_get({ id })`            | Карточка правила                                                          |
| `studio_recurring_create({ ... })`        | Новая абонентка — крон САМ выставит и отправит первый счёт на `nextRunAt` |
| `studio_recurring_update({ id, ... })`    | Полная замена полей                                                       |
| `studio_recurring_toggle({ id, active })` | Включить/выключить без изменения остальных полей                          |
| `studio_recurring_delete({ id })`         | Удалить правило (уже выставленные счета не трогает)                       |

⚠️ **`nextRunAt` в прошлом или сегодня → счёт уходит клиенту письмом при ближайшем прогоне крона**,
не после подтверждения — абонентка это не черновик, а расписание. Ставь будущую дату, если нужно
сначала проверить механизм.

### Счета

| Инструмент                                    | Действие                                                              |
| --------------------------------------------- | --------------------------------------------------------------------- |
| `studio_invoice_list({ clientId?, status? })` | Список счетов                                                         |
| `studio_invoice_get({ id })`                  | Карточка: позиции, платежи                                            |
| `studio_invoice_create({ ... })`              | Черновик (`DRAFT`) — клиент его ещё не видит                          |
| `studio_invoice_send({ id })`                 | `DRAFT → SENT` + письмо клиенту — необратимо видимое клиенту действие |
| `studio_invoice_cancel({ id })`               | Отмена неоплаченного счёта (`PAID` отменить нельзя)                   |

`markPaid` (ручная регистрация оплаты) сюда намеренно не вынесен — финансовая сверка остаётся
только в `/owner/invoices` или через вебхук Точки, чтобы состояние оплаты не могло разойтись
из-за агента.

## Соединение и безопасность

- **Обычный HTTP fetch**, без SSH-туннеля — `STUDIO_URL` целится либо в локальный dev-сервер
  (`http://localhost:3024`), либо в публичный прод-домен.
- **Заголовок `X-Admin-Mcp-Secret`** — `ADMIN_MCP_SECRET` (и `STUDIO_URL`) читаются из
  `process.env`, а если не заданы — из `apps/studio/.env.local` (тот же файловый fallback, что и
  у `studio-time-mcp`, но отдельная переменная и отдельный заголовок — этот периметр даёт запись
  в бизнес-данные, а не только тайм-трекинг).
- **По умолчанию `apps/studio/.env.local` целится в прод** (`https://studio.letar.best`).
- Для другого таргета — переопредели `STUDIO_URL`/`ADMIN_MCP_SECRET` через `env` в `.mcp.json`.

## Запуск

Регистрируется в корневом `.mcp.json` как `studio-mcp` (`bunx tsx libs/studio-mcp/src/cli.ts`),
запускается из корня репозитория. Env-override `STUDIO_MCP_REPO_ROOT` — если cwd не корень репо.

## Команды

```bash
nx test studio-mcp
nx lint studio-mcp
nx typecheck:tsgo studio-mcp
nx serve studio-mcp   # ручной запуск сервера по stdio
```

## Ограничения / backlog

- **Модель доверия процедурная**, как у `deploy-mcp`/`studio-time-mcp`: `.mcp.json` общий для
  всех сессий, тулы вызываемы из любой сессии, работающей в этом репозитории.
- **v1 покрывает 4 сущности** (клиенты, проекты, абонентки, счета). Не покрыто пока: этапы
  проекта (`ProjectStage`), расходы (`ProjectExpense`), ручная регистрация оплаты (`markPaid`),
  документы, заявки (`InquiryRequest`), задачи. Расширять по мере реальной потребности — см.
  `apps/studio/PLAN.md`.
